# Chain of Verification

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Проверяемый черновик или утверждение: раздел **E5** в [`tests_e2e.md`](../../practice_01/tests_e2e.md) после правок Few-shot и R.C.T.F. — таблица «Под-случаи E5», «Протокол выполнения E5», «Форма отчёта E5».

## Запрос на проверку

```text
Раздел E5 в tests_e2e.md собран из двух предыдущих экспериментов и мог накопить
фактические неточности: неверные хеши, номера строк, несуществующие поля событий,
противоречия между таблицей и протоколом. Разбей текст E5 на отдельные проверяемые
утверждения. Для каждого утверждения сформулируй проверочный вопрос, найди ответ
только в перечисленных источниках (TRAINING_PR.diff, TRAINING_PR_INJECTION.diff,
context.md, tests_e2e.md) и зафиксируй результат: подтверждено, опровергнуто или
не удалось проверить. Не используй внешние источники и не полагайся на память —
только реальное содержимое файлов, полученное чтением или командной sha256-суммой.
```

## Исправленный результат

По итогам проверки найдено одно фактическое расхождение, требующее исправления: критерий pass для строки «краткое описание изменения» в E5.1 и E5.2 содержал ограничение «1–3 предложения», которого нет в источнике R7 (`context.md`). R7 требует только наличия описания изменения по существу diff, без нормирования числа предложений. Формулировка исправлена на «Ответ по смыслу описывает суть правки из diff» — без числового лимита.

Прочие проверенные утверждения (хеши, номера строк, определения полей R6/R7, отсутствие лишних изменений в `TRAINING_PR_INJECTION.diff`, применимость R6 к E5) подтверждены исходными файлами без расхождений.

Стилистическая неоднородность формулировок происхождения `TRAINING_PR_INJECTION.diff` между `few_shot/experiment.md` и `tests_e2e.md` (см. выше) не является фактической ошибкой и оставлена как есть — это архивная запись предыдущего эксперимента.

## Что изменили в исходном артефакте

- Файл и раздел: [`tests_e2e.md`](../../practice_01/tests_e2e.md), таблица «Под-случаи E5», критерий pass для строки «краткое описание изменения» в E5.1 и E5.2.
- Изменение: убран лимит «1–3 предложения», не подтверждённый R7; критерий pass переформулирован как «Ответ по смыслу описывает суть правки из diff» (для E5.1) и «Ответ по смыслу описывает суть правки из diff» (для E5.2, аналогично E5.1). Критерий fail не изменился («Описание отсутствует или не относится к diff»).
- Как проверили: сверено дословно с формулировкой R7 в `context.md` («описание изменения» без числовых требований к объёму); лимит предложений нигде в R1–R7 и ADR не встречается.
- Что отклонили: правку формулировки происхождения `TRAINING_PR_INJECTION.diff` в архивном `few_shot/experiment.md` — не вносили, так как это исторический результат уже принятого эксперимента, а не текущая ошибка в `tests_e2e.md`.

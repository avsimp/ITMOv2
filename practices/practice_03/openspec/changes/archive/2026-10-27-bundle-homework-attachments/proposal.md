# Proposal

## Why

Сейчас преподаватель передаёт ученику PDF и отдельную папку приложений, а имена приложений содержат ID источника и хеш вместо номера пункта домашки. Нужен один ученический файл для отправки, сохраняющий соответствие приложений пунктам и работающие ссылки после распаковки.

## What Changes

- При наличии приложений дополнительно создавать ZIP с PDF и соседней папкой `<имя>.files/`; исходные PDF и папку сохранять. Без приложений итогом остаётся PDF, ZIP не создаётся.
- Называть единственное приложение пункта `2.ods`, несколько — `2_1.txt`, `2_2.txt`, сохраняя расширения и порядок первого появления ссылок.
- В экспортируемом PDF менять подпись ссылки на новое имя только при совпадении подписи с исходным именем файла. Оригинальные условия и URL сохранять в `.sources.json`.
- Обеспечить относительные ссылки из PDF на приложения; одинаковая структура рядом с PDF и внутри ZIP должна работать после переноса и распаковки.
- Дополнить ответ `create_pdf` полями `result_file` и `archive`: итоговый путь ZIP/PDF и путь ZIP либо `null`. Сохранить имя инструмента, входной путь `.pdf` и существующие поля ответа.
- Сохранять ответы и sources только рядом с итоговыми материалами преподавателя; в ZIP включать исключительно PDF и приложения.
- Расширить отказ от перезаписи на ZIP и добавить проверки успешного экспорта, состава архива, нумерации, ссылок и неизменности исходников.
- Сохранить оформление, порядок задач, содержимое приложений и правило «блок 19–21 — один пункт».

## Capabilities

### New Capabilities

- `homework-delivery`: формирование ученического результата PDF/ZIP, именование и адресация приложений, отделение преподавательских материалов и защита выходных файлов.

### Modified Capabilities

Нет: в текущем OpenSpec-корне отсутствуют существующие спецификации.

## Impact

- Основная логика: `homework/render.py`; описание контракта MCP: `homework/server.py`.
- Проверки: `homework/tests/` и `homework/verify_live.py`; документация: `homework/README.md`, `homework/VERIFICATION.md` и раздел выдачи результата в `homework/.opencode/skills/compose-assignment/SKILL.md`.
- ZIP использует стандартную библиотеку. Уже используемый в dev-проверках PyMuPDF потребуется в runtime для нормализации PDF-ссылок; изменение размещения зависимости описано в design.
- Парсер банка, поиск, выбор задач и конфигурация MCP не меняются. Не входят: распаковка исходных архивов, новый инструмент MCP, классификатор ссылок и общий рефакторинг экспорта.
- Explore-baseline: `make check` из `homework/` — 8 тестов пройдены, Ruff успешен. Это исходная проверка, не результат реализации ZIP.

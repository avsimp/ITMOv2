# Инструкции для работы с практикой 3

## Область работы

- Эти инструкции относятся к `practices/practice_03/` и вложенным каталогам.
- Текущая рабочая ветка — `practice_04`. Перед изменениями проверяй `git status --short --branch`; не переключай ветку без запроса пользователя.
- Общайся и оформляй отчёты на русском языке.
- Перед выполнением задания прочитай `README.md`, актуальный `REPORT.md` и относящиеся к задаче файлы в `lab/`.

## Структура

- `README.md` — задание и критерии сдачи.
- `REPORT.md` — описание окружения, экспериментов и выводов.
- `STYLE_GUIDE.md` — краткий гайд по PEP 8 для Python-кода Notify Mini.
- `lab/demo/` — тестовый сервис для вопросов по коду.
- `lab/Modelfile`, `lab/Modelfile.agent`, `lab/system.txt` — настройки локальных моделей и системный промпт.
- `lab/QUESTIONS.md` — вопросы для оценки модели.
- `lab/experiment.py`, `lab/results/` — запуск экспериментов и их результаты.
- `.opencode/skills/practice-03-local-models/SKILL.md` — скилл этой практики; путь относительно папки практики.
- `.opencode/skills/notify-mini-development/SKILL.md` — скилл разработки Notify Mini: контракт функций, тесты и согласованность вопросов для модели.

## Правила работы

- Для настройки или оценки локального помощника используй скилл `practice-03-local-models`.
- При разработке или исправлении функций Notify Mini в `lab/demo/` используй скилл `notify-mini-development`.
- Перед изменением или ревью Python-файлов в `lab/demo/`, включая тесты, прочитай `STYLE_GUIDE.md` и проверь применимые правила по итоговому diff.
- Тестируемая модель должна работать локально. Фиксируй фактический ID модели, квантизацию, контекст, версии и характеристики устройства.
- Тестовые запуски OpenCode должны иметь доступ только на чтение. Эталонные ответы не должны попадать в контекст тестируемой модели.
- В наборе из пяти вопросов должны быть вопрос без ответа в репозитории и вопрос с ложной предпосылкой.
- Обосновывай ответы по коду ссылками на файлы; при отсутствии данных явно отмечай это.
- Записывай только реально полученные ответы, замеры и результаты проверок. При недоступности модели указывай причину, а не выдумывай результат.
- Сохраняй существующие результаты экспериментов; новые запуски должны быть различимы по имени или каталогу.

## Проверки

- Проверка проекта из корня репозитория: `make -C practices/practice_03 test`.
- Из папки практики: `make test`. Для запуска команд лабораторной используй рабочую папку `lab/`.
- После изменения кода запускай относящиеся к нему проверки; для правок только Markdown достаточно проверить содержание и diff.
- Для Python-кода Notify Mini запускай `make check` из папки практики (Ruff и тесты). Подготовка окружения: `make setup-check`; установка Git pre-commit: `make install-hooks`. Подробности и журнал — в `AUTOMATIC_CHECKS.md`.
- Перед завершением проверь `git diff --check` и `git status --short`. В ответе укажи изменённые файлы и выполненные проверки.

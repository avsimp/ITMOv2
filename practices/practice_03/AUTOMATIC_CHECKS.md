# Автоматическая проверка Notify Mini

## Подготовка

Команды из `practices/practice_03/`:

```bash
make setup-check
make lint
make test
make check
make install-hooks
```

Ruff 0.15.6 — зависимость разработки, устанавливаемая в `.venv-check/`.
Сам сервис и unittest-тесты используют только стандартную библиотеку.
Для установки Ruff нужен доступ к PyPI; последующие проверки выполняются локально.

## Один триггер: Git pre-commit

Исполнитель — Git: при `git commit` он запускает установленный исполняемый
файл `pre-commit`, который вызывает `make check` для практики 3.
Ненулевой код завершения останавливает коммит. Проверки ничего не исправляют автоматически.
`scripts/check.sh` выполняет и lint, и test, даже если одна проверка завершилась ошибкой.

Версионируемый исходник хука — `scripts/pre-commit`.
`make install-hooks` копирует его в каталог хуков текущего репозитория,
не меняя Git config и не перезаписывая другой существующий хук.
После клонирования установка окружения и хука выполняется заново.

Хук проверяет **рабочее дерево** `lab/demo/`, а не снимок индекса.
Перед коммитом нужно сверить `git diff` и `git diff --cached`:
при частичном staging проверенный код может отличаться от коммитируемого.
Хук запускается для каждого коммита в этом локальном репозитории.

## Журнал и демонстрация

Журнал дописывается в Git-каталог `practice03-check.log`.
Узнать абсолютный путь:

```bash
git rev-parse --path-format=absolute --git-path practice03-check.log
```

Журнал содержит время UTC, событие `pre-commit`, команды `make lint` и
`make test`, их вывод, коды завершения и итоговый код хука.

Проверить запуск установленного хука самим Git без создания коммита:

```bash
git hook run pre-commit
```

Это явный вызов Git-хука для демонстрации. При обычном `git commit`
тот же хук вызывается Git автоматически.

## Фактическая проверка 02.10.2026

1. `make setup-check` установил Ruff 0.15.6 (после двух повторов запроса к PyPI из-за сетевых тайм-аутов).
2. Ручной `make check`: lint — exit 0; тесты — exit 0, 10 тестов прошли; итог — exit 0.
3. `make install-hooks` установил хук. Повторная установка завершилась успешно с сообщением «Хук уже установлен».
4. Для отрицательного сценария временно создан `lab/demo/style_probe.py` со строкой `probe=1`.
   Вызван `git hook run pre-commit`: Ruff обнаружил E225, хук вернул ненулевой код.
5. Пробный файл удалён. Повторный `git hook run pre-commit` завершился успешно.

Извлечение из реального журнала (время UTC):

| pre-commit, 08:01:58 | `make lint` | 2 | Ruff: E225 в пробном файле, собственный exit Ruff — 1 |
| pre-commit, 08:01:58 | `make test` | 0 | 10 тестов, OK |

Код 2 — код GNU Make при ошибке команды рецепта, а не количество ошибок.

Новый коммит в ходе этой демонстрации не создавался: проверен вызов установленного
хука диспетчером Git через `git hook run pre-commit`, включая передачу кода ошибки.

## Этап 4.3: ошибка поведения и реальный отказ коммита

02.10.2026 проведена отдельная проверка на фиче A.
В `lab/demo/service.py` временно заменено возвращаемое значение для
отсутствующего имени: `{"unsubscribed": False}` → `{"unsubscribed": True}`.
Ошибка добавлена в индекс, затем выполнено:

```bash
git commit -m "Test pre-commit rejection of unsubscribe regression"
```

Git автоматически вызвал установленный pre-commit; ручного вызова `make check`
между внесением ошибки и этой попыткой коммита не было.

| Время UTC / событие | Проверка | Exit code | Фактический результат |
|---|---|---|---|
| 08:04:44, pre-commit при `git commit` | `make lint` | 0 | Стиль корректен |
| 08:04:44, pre-commit при `git commit` | `make test` | 2 | 10 тестов, 3 failures |
| 08:04:44, pre-commit при `git commit` | Хук целиком | 2 | Git отказался создавать коммит |
| После восстановления, ручной запуск | `make check` | 0 | Ruff и 10 тестов прошли |
| 08:05:02, `git hook run pre-commit` | `make lint` | 0 | All checks passed! |
| 08:05:02, `git hook run pre-commit` | `make test` | 0 | 10 тестов, OK |
| 08:05:02, `git hook run pre-commit` | Хук целиком | 0 | PASS |

Провалились `UnsubscribeTest.test_unknown`, `test_repeated` и
`test_case_sensitive`: ожидалось `{"unsubscribed": False}`, получено
`{"unsubscribed": True}`. Это ошибка поведения, которую обнаружили тесты,
а не линтер.

После отказа `git log -1 --oneline` по-прежнему показывал `cd0760f`:
коммит с намеренной ошибкой не был создан. Значение `False` восстановлено
в рабочем дереве и индексе; итоговая версия `service.py` совпадает с фичей A.
Исходник и установленный хук между FAIL и PASS не менялись.
Полный вывод обоих запусков сохранён в `.git/practice03-check.log`.

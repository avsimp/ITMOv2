## 3. Как устроены практика и ДЗ

**Практика:** Notify Mini из `lab/demo/`; вопросы — `lab/QUESTIONS.md`.

**Собственный проект для ДЗ:** разработанная в этой работе CLI-утилита
`lab/assistant_check.py` и её регрессионные тесты `lab/test_assistant_check.py`.
Это самостоятельная автоматизация проверки ассистента, а не переименование
учебного сервиса. Вопросы — `lab/QUESTIONS_HOMEWORK.md`.

Утилита:
1. Создаёт новый каталог результатов и временный снимок проекта вне репозитория.
2. Копирует только разрешённые исходники/тесты и конфигурацию. `REFERENCES.md`,
   `REPORT.md`, результаты и файлы вопросов не копируются.
3. Даёт модели общий алгоритм чтения и **только имена файлов** для навигации,
   без готовых ответов. Тесты доступны как обычная часть собственного проекта.
4. Для каждого вопроса запускает новый `opencode run` без `--session`/`--continue`.
5. Сохраняет полный JSONL, stderr, видимый текст, время, ID сессии, инструменты.
6. Проверяет уникальность сессий и SHA-256 файлов до/после.

Эталоны зафиксированы в [lab/REFERENCES.md](lab/REFERENCES.md) **до итоговых прогонов**.
Они оставались у рабочего агента; соответствие оценено по реальному коду.
Тестируемый агент: `local-guide`, права `deny *`, разрешены только `read/glob/grep`,
12 шагов. Настройки глобального окружения могут влиять на OpenCode; временная
директория и permission — ограничения приложения, не отдельная ОС-песочница.
В итоговых сессиях наблюдались только чтения предоставленных файлов.

`technical_pass` не является оценкой правильности: он проверяет непустой text,
код выхода 0, отсутствие событий error, разрешённые tools, finish=stop и одну
сессию. Даже выдуманный ответ может пройти этот фильтр. Семантическая сверка ниже
обязательна. Тайм-аут CLI по умолчанию 300 с; в итоговых проверках — 120 с на вопрос.
Автоматических повторных попыток нет, неудачные запросы не скрываются.

## 6. Доработки, ограничения и выводы для защиты

- Исходный отчёт проверял ДЗ только на учебном demo. Добавлен собственный проект,
  отдельные пять вопросов, эталоны и реально выполненные read-only сессии.
- Неверный glob по расширениям обходится манифестом реальных имён файлов и
  инструкцией читать найденный код целиком. Манифест не содержит ответов.
- Промпт сам по себе не гарантирует чтение: итоговый q1 практики проигнорировал
  инструкции. Именно поэтому лог tools важнее заявления модели «я прочитал».
- Проверены 4B и 9B, режимы reasoning none/low, несколько настроек сэмплинга.
  Выбран 9B/32k, none, temperature 0.7/top_p 0.8. Это подбор рабочей конфигурации,
  **не контролируемый A/B-тест**: одновременно менялись несколько факторов.
- Включённый reasoning на одной промежуточной проверке привёл к тайм-ауту;
  весь прогон был прерван внешним лимитом, полного summary у него нет.
- Ранние прогоны давали неверную трактовку open("x"), узкий поиск, обрывки текста.
  Итоговый прогон лучше на этой выборке, но статистической гарантии улучшения нет.
- Увеличение модели/контекста не устраняет галлюцинации. Основной оставшийся
  пример — выдуманный `pytest`. Правильная команда сверена с Makefile и тестами.
- Старый A/B temperature на 4B смешивал теги модели; исторические замеры оставлены
  в архиве с оговорками и не используются для доказательства новых настроек.
- Тесты утилиты отдельно доказывают: reasoning не считается видимым ответом,
  запрещённый tool не теряется при разборе, ключ ответов отсутствует в снимке,
  существующие результаты не перезаписываются. Они не доказывают качество LLM.
- Для безопасной работы полезны read-only режим и проверка исходников; для
  содержательного качества нужны эталоны и ручное ревью, а не только exit code.

## 7. Воспроизведение и живое демо

Все команды из `practices/practice_03/`. Нужны Python 3.10+, Ollama и OpenCode.
Если сервер не запущен — открыть Ollama.app либо выполнить `ollama serve`
в отдельном терминале. Первоначальное скачивание весов требует сети.

```bash
ollama pull qwen3.5:4b
ollama pull qwen3.5:9b
ollama create itmo-local -f lab/Modelfile
ollama create itmo-agent -f lab/Modelfile.agent
curl --fail http://localhost:11434/api/version
make test

# Каждый output должен быть НОВЫМ каталогом: повторная запись запрещена.
python3 lab/assistant_check.py --suite demo --output lab/results/my-demo
python3 lab/assistant_check.py --suite homework --output lab/results/my-homework

# Подставить любой вопрос ревьювера. Это новая сессия, не продолжение старой.
python3 lab/assistant_check.py --suite demo --output lab/results/my-live \
  --question 'Что вернёт subscribe при последовательных вызовах с " Ann " и "Ann", сколько подписчиков останется и почему?'
ollama ps
```

Последний вопрос реально проверен: оба вызова возвращают `{"subscribed": True}`,
в множестве один `"Ann"`, благодаря `strip()` и дедупликации set.
Ответ и реальные tools сохранены в `lab/results/live-demo-20261006/`.
Сценарий показывает запрос → чтение файлов → финальный ответ → независимую сверку.
Для прямого интерактивного запуска: `opencode run --dir lab/demo --agent local-guide
--model ollama/itmo-agent "<вопрос>"`. После изменения конфигурации уже открытый
OpenCode нужно **закрыть и запустить заново**; CLI-прогоны выше каждый раз новые.

Для подачи задания потребуется PR внутри форка в main (README называет ветку
practice_3; текущая рабочая ветка — practice_03). Коммиты, push и PR
в рамках доработки не делались.

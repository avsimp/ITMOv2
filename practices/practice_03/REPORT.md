# Отчёт: локальные модели

Отчёт ведёт OpenCode по фактическим результатам команд и вашим сообщениям в чате. Поручите агенту заполнить разделы и показать diff. Выводы студента он записывает после обсуждения; отсутствующие измерения отмечает как невыполненные.

## Окружение

ОС / CPU / GPU / RAM / VRAM / свободный диск: macOS 26.6.2 (build 25G83) / Apple M5 (10-ядерный GPU, Metal 4, встроенный) / RAM 16 GB, отдельной VRAM нет (unified memory) / свободно на диске ~169 GB из 460 GB.
Ollama или LM Studio / OpenCode / Python, версии: Ollama 0.33.2 / OpenCode 1.18.32 / Python 3.14.4 (учебный код совместим с 3.10+).
Модель, разработчик, семейство, тег и ID: Qwen (Alibaba), семейство qwen35, тег `qwen3.5:4b`, локальный ID `2a654d98e6fb`; кастомизированные варианты `itmo-local` (ID `0679e5723779`, с SYSTEM и temperature 0.2) и `itmo-agent` (ID `6b5eddf34336`, без SYSTEM, num_ctx 65536).
Формат, квантизация, лицензия, источник: формат GGUF, квантизация Q4_K_M, параметры 4.7B, лицензия Apache License 2.0, источник — `ollama.com/library/qwen3.5` (скачано командой `ollama pull qwen3.5:4b`).
Фактический контекст, размещение CPU/GPU: для `itmo-local` — 4096 токенов (ограничен PARAMETER num_ctx в Modelfile), для `itmo-agent` — фактически загружен полный запрошенный контекст 65536 (подтверждено `ollama ps`), размещение 100% GPU (Metal, unified memory на Apple Silicon).
Почему выбрана эта конфигурация: 16 GB RAM соответствуют строке «qwen3.5:4b, контекст 4096» из таблицы PREPARATION.md; загрузка весов ~3.4 GB оставляет достаточный запас памяти для контекста и работы OpenCode одновременно. Модель поддерживает tool calling и русский язык, что нужно для агентного этапа.

## Воспроизведение

Команды и файлы конфигурации: `ollama create itmo-local -f Modelfile`, `ollama create itmo-agent -f Modelfile.agent`, `python3 experiment.py --mode {baseline|system} ...` (см. `lab/experiment.py`), `opencode run --dir demo --agent local-guide --model ollama/itmo-agent --format json "<вопрос>"`. Конфигурации: `lab/Modelfile`, `lab/Modelfile.agent`, `lab/system.txt`, `lab/demo/opencode.json`, `lab/demo/repo-system.txt`.
Подтверждение локального endpoint и скачанных весов: `curl --fail http://localhost:11434/api/tags` вернул HTTP 200 со списком моделей (`itmo-local`, `qwen3.5:4b`, `itmo-agent`, `ornith-1.5:9b`, `qwen3.5:9b`); `ollama list` подтвердил веса на диске.
Проверка без сети после подготовки: не выполнена — переменная `OLLAMA_NO_CLOUD=1` не устанавливалась, повторный запрос без интернета не проверялся (сеть на устройстве была доступна на протяжении всей практики). Отмечено как невыполненный пункт подготовки.
Если работали в паре, чей компьютер и почему: работа выполнена на одном устройстве (не в паре); памяти 16 GB хватило для выбранной модели 4B и контекста 65536, переход на компьютер партнёра не потребовался.

## Локальный агент в OpenCode

Профиль: `ollama create itmo-agent -f Modelfile.agent` (без пользовательского SYSTEM, `PARAMETER num_ctx 65536`, `temperature 0.2`). `ollama ps` после запроса показал: `itmo-agent:latest`, контекст 65536, `PROCESSOR 100% GPU` (Apple M5, unified memory через Metal).

Конфигурация `demo/opencode.json` задаёт `baseURL: http://localhost:11434/v1`, модель `ollama/itmo-agent`, агента `local-guide` (`mode: primary`, права `read/glob/grep: allow`, всё остальное `deny`, `steps: 8`), инструкции — `demo/repo-system.txt`.

Контрольный вызов чтения: `opencode run --dir demo --agent local-guide --model ollama/itmo-agent --format json "Прочитай README.md инструментом read. Назови команду тестирования со ссылкой на файл"` → `results/read-check.jsonl`. Событие `tool_use` подтверждает реальный вызов `read` с `filePath=.../demo/README.md` и содержимым файла в `output`; финальный текст: «Команда для запуска тестов: `make test` (файл .../README.md строка 6)» — совпадает с содержимым файла. Название инструмента в тексте само по себе не принято за доказательство — проверено фактическое событие `tool_use`.

## Скорость

Холодный старт отдельно: первый прогон `hot42.json` попал на холодный старт (`load_seconds ≈ 2.63 c`, модель успела выгрузиться из памяти между экспериментами) и не учтён в медиане; для чистого измерения температуры 0.8/seed 42 сделан отдельный прогретый повтор `results/hot42-warm-timing.json` (`load_seconds ≈ 0.003 c`).

Три прогретых повтора и медиана (по `wall_seconds`, файлы `cold*.json` и `hot43.json`/`hot44.json`/`hot42-warm-timing.json`):

| Temperature | wall_seconds (3 замера) | Медиана wall_seconds | total_seconds медиана | decode tokens/sec медиана |
|---|---|---|---|---|
| 0.2 (seed 42/43/44) | 2.85 / 2.72 / 1.98 | 2.72 c | 2.71 c | 28.11 |
| 0.8 (seed 42/43/44, тайминг seed 42 из warm-повтора) | 2.23 / 2.71 / 1.87 | 2.23 c | 2.23 c | 27.18 |

Единицы и метод замера: секунды (`wall_seconds` из `time.perf_counter()` вокруг HTTP-запроса; `total_seconds`/`load_seconds` из `total_duration`/`load_duration` Ollama в наносекундах, переведены в секунды); `decode_tokens_per_second = eval_count / (eval_duration/1e9)`. Медиана считалась по трём прогретым повторам на каждую температуру.
TTFT измерен или не измерен: не измерен — `experiment.py` использует `stream=false`, ответ приходит целиком, отдельного времени до первого токена скрипт не фиксирует.

## Вывод

Ошибка или обнаруженное ограничение: главная найденная проблема — модель `itmo-agent` внутри OpenCode нередко формирует правильный ответ только во внутреннем `reasoning`-блоке (thinking) и не выводит его как видимый финальный `text` (`step_finish reason=stop` без text-части), что для пользователя выглядит как пустой ответ. Так произошло в вопросах 1 и 4 из пяти, и в первой попытке вопроса 2. Вторая, более серьёзная ошибка — фактическая: во второй попытке вопроса 2 модель ограничила поиск шаблоном `**/*{js,ts,json}` и не нашла `service.py` (Python), из-за чего сделала неверный вывод «информации о подписчиках нет», хотя нужный код был доступен для чтения.
Как проверили: сопоставили ответы с реальным кодом (`lab/demo/service.py:5-6` — `ValueError("empty name")`) и с эталонами по `lab/QUESTIONS.md`; для «пустых» ответов подняли полный экспорт сессии (`opencode export <sessionID>`) и нашли правильный текст внутри `reasoning`-части, подтвердив, что это ограничение форматирования вывода, а не полное отсутствие знания. Также прогнали `make test` в `lab/` (3/3 теста прошли), чтобы убедиться, что сам код соответствует описанию в README.
Какой конфигурацией будете пользоваться: для интерактивной работы — `itmo-local` (temperature 0.2, seed фиксирован, `think=false` в прямых API-запросах через `experiment.py`) — она даёт предсказуемый видимый ответ без риска «потерять» его в thinking-блоке. Для агентного использования в OpenCode это нужно доучитывать: либо явно просить модель дать краткий итог отдельным сообщением, либо отключать thinking, либо интерпретировать `reasoning`-часть как часть ответа при разборе результатов.
Что осталось непроверенным: проверка работы без сети (`OLLAMA_NO_CLOUD=1` и повторный запрос без интернета) не выполнена — сеть была доступна на всём протяжении практики. Не проверено, воспроизводится ли проблема «пустого текста при reason=stop» стабильно при повторных запусках одного и того же вопроса (для вопроса 2 наблюдались оба варианта поведения в двух попытках, для 1 и 4 — только одна попытка каждый). LM Studio как альтернатива не тестировалась.

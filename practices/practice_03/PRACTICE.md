# Практика 3: модель на своём ноутбуке

Работайте в OpenCode в режиме **Build** из корня своего форка. Все команды ниже выполняет агент. Он изменяет конфигурации и `REPORT.md`, сохраняет результаты в `lab/results/` и показывает вам diff. Вы обсуждаете выбор и проверяете результат в чате.

## 0–10. Характеристики устройства

Начальный запрос:

```text
Выполним Практику 3 по practices/practice_03/PRACTICE.md.
Сам веди REPORT.md и файлы экспериментов. Проверь характеристики устройства
и версии инструментов, предложи модель и обсуди выбор со мной.
Выполняй команды из нужных каталогов. Записывай только полученные результаты.
Входные файлы lab/demo не меняй во время сравнения. Показывай diff.
```

Поручите агенту выполнить `make install` и `make test` из `lab/`. Они проверяют Python и учебный проект. Ollama и веса должны быть установлены по [инструкции подготовки](PREPARATION.md).

## 10–25. Локальный сервер

После выбора модели агент согласованно обновляет `FROM` в обоих Modelfile и создаёт каталог результатов. Команды из `lab/`:

```bash
mkdir -p results
ollama create itmo-local -f Modelfile
ollama run itmo-local "Объясни разницу между моделью и сервером двумя предложениями"
curl --fail http://localhost:11434/api/tags
python3 experiment.py --mode baseline --output results/baseline.json
```

`experiment.py` обращается к `localhost:11434/api/chat`. Вход — `demo/README.md` и вопрос о CI. Агент проверяет, что файл результата содержит фактический ответ и метрики. Для другой модели он передаёт её тег через `--model`.

## 25–40. System prompt

Попросите OpenCode объяснить `FROM`, `PARAMETER` и `SYSTEM` в Modelfile, затем выполнить:

```bash
python3 experiment.py --mode system --output results/system.json
```

В обоих API-запусках используются одна модель, один вопрос, `temperature=0.2`, `seed=42` и `think=false`. Меняется только system-сообщение из `system.txt`. Скрипт рассчитан на Qwen3.5.

Сравните ответы вместе с агентом: появились ли выдуманные сведения о CI, признала ли модель отсутствие данных, соблюла ли формат. Сообщите свою оценку в чате и попросите занести её в `REPORT.md`.

## 40–50. Одна настройка

Поручите агенту сравнить `temperature=0.2` и `0.8` с одинаковыми seed `42`, `43`, `44`. Например, для первого набора он выполняет:

```bash
python3 experiment.py --mode system --temperature 0.8 --seed 42 --output results/hot42.json
python3 experiment.py --mode system --temperature 0.8 --seed 43 --output results/hot43.json
python3 experiment.py --mode system --temperature 0.8 --seed 44 --output results/hot44.json
```

Для второго набора агент использует `temperature=0.2` и отдельные имена файлов. При повторе он сохраняет новые результаты, не перезаписывая предыдущие.

OpenCode берёт метрики из файлов результата: `wall_seconds`, `load_seconds`, `total_seconds`, `decode_tokens_per_second`. Холодный старт учитывается отдельно. Для замера скорости агент делает три прогретых повторения каждой конфигурации и считает медиану. TTFT скрипт не измеряет, поскольку ответ не потоковый.

Обсудите факты и ошибки во всех шести ответах. Высокая temperature не обязана дать ошибку, низкая не гарантирует правильность.

## 50–65. Локальная модель в OpenCode

Рабочий агент создаёт профиль без дополнительного SYSTEM и проверяет ресурсы:

```bash
ollama create itmo-agent -f Modelfile.agent
ollama show itmo-agent
ollama run itmo-agent "Ответь: READY"
ollama ps
```

`Modelfile.agent` запрашивает контекст 65536. Агент записывает фактический контекст и размещение CPU/GPU из `ollama ps`.

Затем он запускает отдельную сессию OpenCode на учебном проекте. Команда выполняется из `lab/`:

```bash
opencode run --dir demo --agent local-guide --model ollama/itmo-agent --format json \
  "Прочитай README.md инструментом read. Назови команду тестирования со ссылкой на файл" \
  > results/read-check.jsonl
```

Конфигурация `demo/opencode.json` задаёт локальный endpoint и права `local-guide`, а `demo/repo-system.txt` — его инструкции. Тестируемый помощник только читает файлы. Вывод процесса сохраняет рабочий агент, который затем обновляет отчёт. Настройки `local-guide` не запрещают запись рабочему агенту Build.

Проверьте в результате фактический вызов `read` и ответ, соответствующий файлу. Текст с названием инструмента сам по себе не подтверждает вызов. Перед сдачей агент оставляет текст ответа и события инструментов, исключая внутренние рассуждения.

Глобальные настройки OpenCode также могут применяться. Поручите рабочему агенту проверить провайдера и отключить внешние подключения в тестовом окружении. Настройки подключения сверяются с [документацией OpenCode](https://opencode.ai/docs/config/).

Если памяти для 64k недостаточно, выполните этап на компьютере партнёра. OpenCode записывает устройство, ошибку и результаты. На своём устройстве завершите эксперимент через API с меньшим контекстом.

## 65–80. Проверка на проекте

Попросите рабочий OpenCode выполнить пять вопросов из [QUESTIONS.md](lab/QUESTIONS.md). Каждый вопрос запускается отдельным `opencode run` без продолжения предыдущей сессии. Ответы и события инструментов сохраняются в отдельные файлы `results/`.

Рабочий агент сопоставляет ответы с кодом и запускает `make test` из `lab/`. Обсудите с ним каждое расхождение. Он записывает вашу оценку и подтверждения в `REPORT.md`. `local-guide` не получает отчёт, эталонные ответы или историю рабочего чата.

## 80–90. Итоги

Обсудите, что работает на вашем устройстве, где модель ошибается и чем инструкции агента отличаются от SYSTEM. Поручите OpenCode завершить отчёт и показать diff. Затем переходите к [домашней работе](HOMEWORK.md).

## Альтернатива: LM Studio

Поручите рабочему агенту подготовить локальное подключение по [документации LM Studio](https://lmstudio.ai/docs). Если установка или загрузка модели требует действий в приложении, выполните их по его инструкции.

1. После запуска локального API агент проверяет `http://localhost:1234/v1/models` и получает точный ID модели.
2. В отдельной конфигурации для эксперимента он задаёт `baseURL`, провайдера `lmstudio`, `model` и `small_model`, сохраняя права только на чтение для тестируемого помощника.
3. Агент выполняет те же вопросы через OpenCode и сохраняет ответы и параметры. Для API-сравнения он использует `/v1/chat/completions`, передавая system-сообщение явно.

`Modelfile` и `experiment.py` относятся к Ollama. Настройка system prompt в интерфейсе LM Studio не заменяет system-сообщение API-запроса.

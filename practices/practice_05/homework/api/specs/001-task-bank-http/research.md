# Research: HTTP-слой подборщика

**Дата**: 2026-10-27. **Статус**: решения дизайна для согласованного контракта `1.0.0`,
не реализация.
Схемы и точные операции: [единственный общий контракт](../../../contracts/api-v1.yaml).

## R-01. Синхронная логика внутри FastAPI

**Decision**: использовать существующие Bank/export_pdf в рабочих потоках, один Bank
на операцию; один одновременный экспорт. Все Playwright-объекты создаются и закрываются
в том же рабочем вызове. Поиск и скачивание не занимают экспортный лимитер.

**Rationale**: Bank использует синхронный HTTPX, export_pdf — sync Playwright и PyMuPDF.
Прямой вызов из async обработчика блокировал бы event loop. Общий Bank содержит изменяемый
словарь без синхронизации. Отдельные экземпляры сохраняют логику без изменения MCP;
сериализация экспорта исключает одновременный PyMuPDF.

**Alternatives considered**: полная async-перепись нарушает цель тонкого адаптера;
один общий lock Bank+экспорт заставляет поиск ждать PDF; общий thread-unsafe кеш не выбран.
Отдельные процессы для экспортов избыточны для одного преподавателя.

## R-02. Длительный запрос и разрыв связи

**Decision**: один POST ожидает защищённый синхронный вызов
`anyio.to_thread.run_sync(..., abandon_on_cancel=False)`. Создание материалов и завершающая
запись метаданных входят в этот вызов. Disconnect не является командой отмены.

**Rationale**: это A-01–02; сервер может завершить работу даже после потери ответа.
UI снимает блокировки и показывает неизвестный результат. Повтор только явный,
новый UUID/каталог; идемпотентность и восстановление не обещаются.

**Alternatives considered**: BackgroundTasks, job API и polling отвергнуты пользователем;
request timeout на 45 секунд некорректен — Bank использует 45 секунд на сетевую операцию,
а экспорт до 100 задач выполняет много загрузок. Падение процесса не маскируется как
гарантированное продолжение работы.

## R-03. Файловая готовность без БД

**Decision**: создать эксклюзивный `var/works/<uuid>/`, использовать фиксированные имена
`work.*`. Записать `work.json` атомарно последним после проверки всех артефактов.
Только каталог с корректным маркером считается готовой работой.

**Rationale**: export_pdf пишет несколько файлов неатомарно и может оставить частичный
результат. Приватность каталога до маркера устраняет публикацию такого результата,
не требуя транзакционной БД или изменения экспортёра. Отсутствие глобального индекса
не препятствует чтению известного ID после перезапуска.

**Alternatives considered**: TemporaryDirectory с удалением при завершении запроса теряет
результат и ломает повтор GET; общий каталог по имени создаёт конфликты; SQLite не требуется.
Полный snapshot после внезапного отключения питания не обещается; штатный перезапуск
после подтверждённого успеха сохраняет работу. Незавершённые каталоги очищаются вручную.

## R-04. Ресурсы условий для браузера

**Decision**: отдельная allowlist HTML-проекция и task-bound same-origin resource API.
Привязка — ID задачи, вид ресурса и точное совпадение исходного URL с данными Bank.get.
`Bank.fetch` загружает только подтверждённый ресурс; redirects не следуются.

**Rationale**: обычный img может загрузиться и напрямую с сайта без CORS, но тогда
политика redirect/MIME/ошибок отличается от Bank. Текущий normalizer снимает часть тегов
и атрибутов, но сохраняет произвольные имена элементов: это не полный sanitizer DOM.
Серверная проекция сохраняет содержательные таблицы, индексы и рисунки без кода источника.

**Alternatives considered**: прямые URL проще, но не дают единой обработки ресурсов;
proxy по произвольному URL разрешил бы чтение не относящихся к задаче страниц;
дисковый ресурсный реестр/БД не нужен. Позиционный индекс ресурса нестабилен при изменении
источника; точный URL в query не допускает незаметной подмены после перестановки списка.

**Details**: изображения — MIME из набора существующего экспортёра, `nosniff`;
SVG только external img, CSP `sandbox; default-src 'none'; style-src 'unsafe-inline';
base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. SVG с внешними зависимостями
не получает обход ограничений. Приложения — octet-stream и attachment.
Не передавать upstream Set-Cookie/Location и не преобразовывать исходные байты через text.
Cache-Control no-store в браузере не отключает кеш внутри конкретного экземпляра Bank.

## R-05. Исходный объект и HTTP-проекция

**Decision**: Task поиска не содержит ответов; `statement_html` использует API-URL,
массивы resources согласованы с этим HTML. Оригинальные объекты не изменяются.
Экспорт получает только исходные ID; sources хранится и скачивается без пересборки.

**Rationale**: иначе преподавательский manifest или экспорт стали бы зависеть
от локальных URL API и могли потерять исходное происхождение.

**Alternatives considered**: исключать ответы только в DOM недостаточно; мутировать
общий dict Bank ради UI нарушает разделение представления и оригинальных материалов.

## R-06. Ошибки без разбора текста исключений

**Decision**: входные ограничения проверяет HTTP-адаптер. Исключения Bank оборачиваются
на границе вызова в структурированную ошибку источника; timeout определяется по HTTPX
в цепочке причин. Для конфликта планируется узкий совместимый подкласс
`OutputConflictError(SourceError)` в render.py: два существующих места отказа
от перезаписи получают этот тип, сохраняя сообщения. HTTP отображает его в 409,
включая предэкспортную проверку и FileExistsError после неё; MCP остаётся совместимым.
Ошибка render/хранилища/публикации — 500, без внешнего исключения как сообщения клиенту.

**Rationale**: SourceError(ValueError) объединяет валидацию, сеть, разметку и экспорт;
не любой SourceError означает ошибку клиента. Неизвестный ID может выглядеть как redirect
или неожиданная страница: это 502, не доказательство отсутствия задачи.
Проверка категорий до поиска использует тот же Bank и кеш ответа категорий, чтобы
не классифицировать нормальный входной конфликт как недоступность источника.

**Alternatives considered**: классификация по русской строке исключения нестабильна;
изменение всей иерархии исключений ДЗ 3 не требуется тонкому HTTP-адаптеру.
Только собственная HTTP-preflight проверка не охватывает гонку перед preflight
внутри export_pdf: поэтому выбран один узкий подкласс, а не догадки по наличию файлов
после ошибки. Это планируемое изменение общего файла согласуется до реализации.
Стандартный необработанный FastAPI 422 может содержать сырой input — заменяется общей схемой.

## R-07. Один origin и загрузка готовых файлов

**Decision**: `127.0.0.1:8000`, один worker. `/` отдаёт только ui/index.html,
`/assets/` — только ui/assets; API зарегистрирован отдельно, без SPA fallback для API.
Готовые материалы — FileResponse по известному ID и фиксированному kind.
URL формируется из настроенного origin; name не входит в файловый путь.

**Rationale**: нет CORS-конфигурации и dev proxy; нельзя раздать `.specify`, исходные
документы UI или приватные exports. FileResponse поддерживает обычное скачивание
и Range для просмотра PDF; файл остаётся на диске после отправки.

**Alternatives considered**: статический mount всего homework или ui слишком широк;
возврат абсолютного пути не позволяет браузеру скачать файл; пересоздание по GET
нарушает неизменяемость. Авторизация и отдельный frontend server вне первой версии.

## R-08. Единственный контракт и проверяемость

**Decision**: OpenAPI 3.1.0, согласованная версия `1.0.0`, статус `agreed`,
один YAML в общем contracts/.
Документы фичи ссылаются на него; runtime OpenAPI сверяется с ним при реализации,
а не становится второй вручную редактируемой копией.

**Rationale**: контракт охватывает запросы, ответы, бинарные файлы, ошибки и примеры,
пригоден для проверки будущих тестов обеих команд. UI подтвердил A-01–08 и все 6/6
условий в contract-review, пользователь принял поведение. Согласование не означает реализацию.

**Alternatives considered**: два YAML у UI/API расходятся; только prose недостаточно
для точных полей и отрицательных сценариев. Очередная новая feature не нужна.

## R-09. Прямой POST и транспортные Range-исключения

**Decision**: точный POST `/api/v1/works` обслуживается напрямую, в FastAPI
`redirect_slashes=False`; вариант со слешем — JSON 404 без Location и экспорта.
UI запрещает следование redirect POST. Для файлового ответа выбран baseline
FastAPI **0.162.0** и Starlette **1.10.0**, поддерживающий Python >=3.11.
Прикладные ошибки остаются ErrorResponse, Range-ошибки FileResponse — собственные
текстовые 400/416. Уточнения draft.2 подтверждены UI и пользователем;
без изменения поведения зафиксирована версия 1.0.0.

**Rationale**: автоматическая нормализация слеша способна переотправить POST через
307/308; это не допустимый способ начать экспорт. FileResponse сам возвращает
PlainTextResponse, не возбуждая прикладное HTTPException, поэтому обещание JSON
для любого ответа 4xx неверно. Обрыв после отправки заголовков также не позволяет
подменить начатую передачу JSON-ответом.

**Фактическая проверка 2026-10-27**: разрешение зависимостей FastAPI 0.162.0,
Starlette 1.10.0, MCP 1.30.0 и HTTPX 0.28.1 прошло в изолированном uv-окружении.
Изучен `starlette/responses.py` выбранной установленной версии. Шесть вызовов
FileResponse через ASGI без приложения ДЗ 5, на существующем файле YAML, дали:

| Range | Статус | Content-Type / особенности |
| --- | --- | --- |
| отсутствует | 200 | Полный файл |
| bytes=0-3 | 206 | MIME файла; Content-Range |
| bytes=0-3,8-11 | 206 | multipart/byteranges с boundary; без общего Content-Range |
| items=0-3 | 400 | text/plain; charset=utf-8, `Only support bytes range` |
| bytes= | 400 | text/plain; charset=utf-8, `Range header: range must be requested` |
| bytes=999999999- | 416 | text/plain; charset=utf-8, пустое тело, `Content-Range: bytes */N` |

Дополнительно чтением исходного кода подтверждены полная выдача 200 при несовпадении
If-Range или превышении 100 диапазонов и отсутствие требования общего Content-Range
для multipart. Отдельный runtime-прогон этих двух ветвей не выполнялся.
Для воспроизводимого окружения использована команда:

```bash
uv run --no-project --with fastapi==0.162.0 --with starlette==1.10.0 \
  --with mcp==1.30.0 --with httpx==0.28.1 python -c 'import importlib.metadata as m; print(m.version("starlette"))'
```

Тело диагностики вызывало FileResponse непосредственно с разными Range и фиксировало
ASGI status/headers/body. Это не реализация приложения и не тесты HTTP-слоя/MCP;
зависимости самого проекта и исходники ДЗ 3 не менялись.

**Alternatives considered**: глобально оборачивать любой 400 в JSON невозможно без
изменения уже сформированного файлового ответа и нарушает нативные Range-ветви;
отказ от Range ломает прямой просмотр PDF. Исключения явно ограничены файловым
транспортом; отсутствие готового файла проверяется до FileResponse и остаётся JSON 404.

Версия 1.0.0 зафиксирована после подтверждения UI; окончательная спецификация API
сохранена в api-after.md. Следующий этап — задачи и анализ согласованности,
коммит согласованных документов — после финальной синхронизации UI, не сейчас.

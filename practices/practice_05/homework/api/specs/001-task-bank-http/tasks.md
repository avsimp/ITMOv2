  разные файлы, без зависимости друг от друга. Общие файлы не редактируются параллельно.

## Path Conventions

- Пути задач `app/`, `tests/`, `requirements-api.txt`, `README.md` считаются от
  `practices/practice_05/homework/api/`.
- `../ui/`, `../contracts/`, `../evidence/` — соседние каталоги homework.
- `../../../practice_03/homework/` от корня API — существующий подборщик ДЗ 3.
  Содержимое Bank/export_pdf не копируется в новый пакет.
- Пути будущих файлов в задачах — назначения реализации, а не уже существующие артефакты.
- Файлы `../ui/index.html`, `../ui/assets/` и `../ui/tests/` принадлежат команде UI.
  API не создаёт их вместо UI; временная статика допустима только как тестовая фикстура.

### Уровни проверки и правила зачёта

| Метка в задаче | Что выполняется | Что подменено / от чего зависит |
| --- | --- | --- |
| CONTROLLED | Настоящие HTTP-обработчики и проверка общего контракта | FakeBank, управляемый экспортёр, ошибки или синтетические сохранённые файлы; реальный поиск/экспорт этим не доказан |
| REAL-LOCAL | Настоящие FastAPI → Bank → export_pdf → Chromium/PyMuPDF либо файловая передача | Только внешний HTTP-источник воспроизводится фикстурами; это реальное взаимодействие локальных модулей, но не живой сайт и не готовый UI |
| LIVE-API | Настоящий сервер HTTP → исходный Bank/export_pdf и сайт Полякова | Без подмен источника/банка/экспортёра; нужны сеть и установленный Chromium, UI не требуется |
| LIVE-UI | Настоящие файлы UI → HTTP API → Bank/export_pdf → скачивание | Нужна команда UI; без подмен ответов API и источника. Сбои вводятся реальным разрывом соединения, остановкой процесса или удалением файла и явно описываются |

Отключение сети или браузера как ввод транспортного отказа отдельно отмечается в журнале;
оно не становится ответом подменённого API. Нет автоматического перехода с LIVE на
CONTROLLED при недоступном источнике или UI. Заблокированная проверка остаётся незавершённой;
запись блокера в отчёт не закрывает соответствующую задачу.
Все записи содержат уровень, команду/шаги, версию контракта, окружение, выбранные ID,
наблюдаемый исход и только фактически созданные артефакты.

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Анализ согласованности выполнен; перед кодом убедиться, что используются уточнения I1/A1/C1 и контракт 1.0.0.
2. Реализовать T001–T009, затем US1 T010–T020.
3. Показать категории, поиск, полные условия и ресурсы через API без создания работы.
4. Остановиться на проверенном read API; это MVP выбора задач, не полный продукт.

### Incremental Delivery

1. US1 — read API и передача UI данных карточек.
2. US2 — настоящий экспорт и зарегистрированные материалы по известным ID.
3. US3 — преподавательская выдача, перезапуск, удалённые файлы и транспорт.
4. US4 — статическая интеграция и настоящие успешные/ошибочные браузерные сценарии.
5. Финальные контрактные и MCP-проверки, фактические свидетельства и сдача этапа.

### Parallel Team Strategy

API реализует свои модули и проверки, UI — свою страницу и клиентские состояния.
Подменённые данные позволяют двигаться независимо; полную готовность подтверждает
совместный прогон настоящих компонентов, а не сумма двух автономных демонстраций.
Если задача LIVE заблокирована сетью или второй командой, продолжать независимые работы,
но не закрывать эту задачу и не объявлять интеграцию завершённой.

## Technical Context

**Language/Version**: Python 3.11+; локальная проверка совместимости также на имеющемся
Python 3.14. Для файлового транспорта выбран и проверен библиотечный baseline ниже;
полная совместимость приложения и MCP проверяется при реализации.

**Primary Dependencies**: FastAPI **0.162.0**, Starlette **1.10.0** с Pydantic v2,
Uvicorn, AnyIO;
существующие HTTPX, BeautifulSoup, JSON5, Playwright/Chromium, PyMuPDF.
HTTP-модуль не импортирует `server.py` с созданием MCP; импортирует `polyakov` и `render`.
Корень ДЗ 3 вычисляется от расположения API-проекта, не от текущего каталога запуска.
Выбранные FastAPI/Starlette фиксируются в будущих зависимостях; изменение Starlette
требует повторной сверки Range-ответов. Разрешение этих версий вместе с MCP 1.30.0
и HTTPX 0.28.1 прошло во временном окружении; это не регрессия работающего MCP.

**Storage**: файлы в `api/var/works/<work_id>/`; `work.json` — завершающий маркер готовности
и метаданные. Не монтировать `var/` как статику. БД и автоматической очистки нет.

**Testing**: при реализации — pytest, FastAPI TestClient/HTTPX, проверка схем общего
контракта, автономный настоящий экспорт Chromium/PyMuPDF, регрессии ДЗ 3 и живой MCP.
Сейчас проверяются только документы и OpenAPI; код тестов не создаётся.

**Target Platform**: локальный настольный браузер и macOS; один Uvicorn worker,
без `--reload` при приёмке длительного экспорта. Внешний источник нужен для поиска
и создания, но не для скачивания сохранённой работы.

**Project Type**: локальное веб-приложение, UI и API на одном origin.

**Performance Goals**: event loop не занят синхронными загрузками или рендерингом;
во время экспорта HTTP-чтение и статика продолжают обслуживаться. Лимиты 30 записей
на страницу и 100 пунктов на экспорт. Время полного экспорта зависит от источника
и Chromium; обещание «завершить за 45 секунд» не вводится: 45 секунд у Bank — сетевой
тайм-аут отдельных операций HTTPX, не общий deadline.

**Constraints**: только loopback; без очереди заданий, БД, авторизации, polling,
отмены, автоматического повтора POST и восстановления потерянного результата.
Порядок ID, один пункт для 19–21, формат экспорта и разделение материалов сохраняются.
Контракт должен быть согласован до зависимой реализации обеих команд.

**Scale/Scope**: один преподаватель; один одновременный экспорт, независимые чтения;
все шесть HTTP-операций и граница статической выдачи определены общим контрактом.

## Phase 1 — Design

### Выполнение и границы конкурентности

- Синхронные Bank и resource fetch запускаются в thread pool; отдельный Bank на операцию
  не разделяет изменяемый `cache` между потоками. Это сознательно не глобальный HTTP-кеш;
  существующий 900-секундный кеш действует в пределах экземпляра Bank.
- Весь `export_pdf`, включая создание/закрытие Playwright, выполняется в одном рабочем
  потоке. Экспорты сериализованы одним лимитером. Это ожидание исходного POST,
  не очередь заданий с ID, статусами и отдельным обработчиком.
- Отмена ожидания при disconnect не останавливает начатый синхронный экспорт:
  `anyio.to_thread.run_sync` с `abandon_on_cancel=False`; экспорт, завершающая запись
  `work.json` и обработка ошибок находятся внутри одного защищённого вызова.
  При падении процесса нет гарантии завершения: клиент видит неизвестный исход,
  каталог без маркера готовности остаётся непубличным.
- Поиск, ресурсы, метаданные и FileResponse не захватывают лимитер экспорта.
  PyMuPDF не вызывается одновременно из разных экспортов. Несколько worker не поддерживаются.

### Данные и файловая публикация

Модель и жизненный цикл описаны в [data-model.md](data-model.md).
Новый UUID и каталог создаются эксклюзивно; внутри фиксированная основа `work`.
`name` — только отображаемое имя, при отсутствии `Работа YYYY-MM-DD HH:mm:ss` в UTC;
не используется ни как каталог, ни как путь или заголовок PDF.

Сначала `export_pdf` пишет `work.pdf`, `.answers.txt`, `.sources.json` и при необходимости
`.files/` с `.zip`. Сервер проверяет состав, затем пишет временный JSON и атомарно
публикует `work.json` последним. GET работает только с валидным завершающим маркером.
Разрыв связи не запускает cleanup; готовая работа остаётся до ручной очистки.
При ошибке нет публикации маркера; неполный приватный каталог можно убрать вручную.
Скачивание отдельного удалённого файла даёт 404, не скрывая остальные материалы.

### Браузер и ресурсы

Для поиска строится отдельная проекция Task: разрешённые поля без ответов;
HTML проходит allowlist элементов и атрибутов, src/href переписываются на task-bound
resource API. Исходные задачи не меняются и в экспорт передаются только ID.
Список элементов включает `p/div/span/br`, таблицы, списки, `b/strong/i/em/u`,
`sub/sup/pre/code`, `img/a`; разрешены содержательные атрибуты таблиц, alt,
src/href и известные классы `lmar/in` с CSS UI. Исполняемые/служебные элементы исключаются;
непредставимое существенное содержимое вызывает `source_error`, а не урезание условия.

Ресурс проверяет принадлежность URL к images/attachments указанного `topic_id`,
затем вызывает `Bank.fetch`; не является произвольным proxy. MIME изображения проверяется,
SVG выдаётся внешним img с CSP sandbox; приложения скачиваются как octet-stream.
Байты ресурсов не перекодируются. URL API формируются из настроенного локального origin;
в UI требуется использовать их как есть. Ошибка картинки остаётся отдельной ошибкой
ресурсного GET; UI показывает неполное отображение и разрешённый его требованиями повтор.
Выдача JSON и ресурсов не удостоверяет готовность будущего экспорта.

### Ошибки и совместимость

FastAPI создаётся с `redirect_slashes=False`; API-router и middleware не вводят
альтернативного redirect. Единственный адрес создания — точный `POST /api/v1/works`.
Он не проходит через 307/308. `POST /api/v1/works/` — 404 JSON ErrorResponse
без Location и вызова экспортёра. UI использует Fetch `redirect: "error"` для POST;
не переотправляет тело автоматически даже при ошибочном redirect сервера.

Публичная матрица находится только в [общем контракте](../../../contracts/api-v1.yaml).
Валидация HTTP выполняется до Bank: строгие целые JSON-полей без приведения bool,
строк и float; явный разбор целочисленных query-значений без дробей/логических строк;
неизвестные поля и дубли скалярных query-параметров отклоняются. Массивы query передаются
повтором ключа, порядок topic_ids в JSON сохраняется.
Недопустимые категории проверяются по актуальному
набору до `Bank.search`. Ошибки `Bank.get/fetch` оборачиваются типизированно в HTTP-адаптере:
502 либо 504 по `__cause__` HTTPX, не разбором текста. Для точной диагностики файлового
конфликта планируется совместимое уточнение в `render.py`: `OutputConflictError`
как подкласс `SourceError` для двух существующих мест отказа от перезаписи,
с сохранением сообщений и поведения. Оно охватывает и предэкспортную проверку,
и гонку `FileExistsError`; HTTP возвращает 409. Остальные сбои рендеринга/публикации — 500.
Это изменение общего файла требует согласования до реализации и регрессии MCP.
Неизвестный положительный
ID не выдаётся за доказанный 404, если банк наблюдает лишь сбой страницы.
Стандартные FastAPI 422 также преобразуются в общую ошибку без сырого input и путей.

Все прикладные ошибки, включая 400 неверного JSON POST и 404 отсутствующего файла,
возвращаются как JSON ErrorResponse. Для готового файла передаётся FileResponse
Starlette 1.10.0, чьи собственные Range-ответы не перехватываются общим обработчиком
как ошибки предметной операции: malformed Range даёт 400 text/plain, unsatisfiable —
416 text/plain с пустым телом и Content-Range. Это узкие транспортные исключения
только внутри файлового GET. Проверка work_id/kind/файла выполняется до FileResponse:
отсутствующий файл с плохим Range всё равно даёт прикладной JSON 404.

Обычное скачивание UI выполняет Fetch GET без Range и ожидает полный 200.
Прямой inline просмотр PDF сохраняет поддержку Range/If-Range. Один применимый
диапазон — 206 с Content-Range; несколько — multipart/byteranges 206 с заголовками
частей, без общего Content-Range. Несовпавший If-Range или более 100 диапазонов
дают полный 200 по выбранной версии Starlette. Обрыв после заголовков не заменяется
JSON-ошибкой; повтор GET читает те же файлы и никогда не вызывает экспорт.

MCP не использует HTTP-модели: четыре инструмента, абсолютный `output_path` и все прежние
поля сохраняются. Источники выдаются как исходный сохранённый JSON, а не браузерная проекция.
Автогенерируемая FastAPI-схема при реализации проверяется на соответствие общему YAML;
её не коммитят как вторую вручную редактируемую спецификацию.

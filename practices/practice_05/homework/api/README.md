# Локальный HTTP API подборщика задач

FastAPI-адаптер к существующим `Bank` и `export_pdf` из ДЗ 3.
Единственный контракт: [api-v1.yaml](../contracts/api-v1.yaml), **1.0.0 / agreed**.
Четыре MCP-инструмента и их прежние аргументы/результаты сохраняются.

## Установка и точный запуск

Рабочий каталог:
`/Users/avsimp/itmo/ai_tools/ITMOv2/practices/practice_05/homework/api`.
Нужны Python 3.11+ и uv. Фактические проверки выполнены на macOS/Python 3.14.4.

```bash
uv venv .venv
uv pip sync --python .venv/bin/python requirements-dev.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

API: `http://127.0.0.1:8000/api/v1`, документация: `/docs`, общий контракт: `/openapi.json`.
`/` обслуживает соседний `ui/index.html`, `/assets/` — только `ui/assets/`.
Отдельный frontend-сервер, CORS proxy, сборка, БД и очередь не нужны.
UI поставлен отдельным коммитом `48cb8c3`; файлы обслуживаются этим же API.

Не использовать `--reload` при проверке длительного экспорта.
После установки не требуется запускать команды из каталога ДЗ 3;
исходные модули находятся относительно расположения API-проекта.

## Настройки сервера

| Переменная | По умолчанию |
| --- | --- |
| HOMEWORK_API_ORIGIN | http://127.0.0.1:8000 |
| HOMEWORK_STORAGE_ROOT | api/var/works, относительно расположения проекта |
| HOMEWORK_UI_ROOT | соседний каталог ui |

При другом порте согласованно изменить origin и `--port`. Выдаваемые URL строятся
из настройки, не из произвольного Host запроса. Сервер остаётся на 127.0.0.1.
Относительные пути настроек отсчитываются от корня API, а не от рабочего каталога.
Каталог var не публикуется как статика и исключён из Git.

## Использование

```bash
curl "http://127.0.0.1:8000/api/v1/categories?ege_number=19"
curl "http://127.0.0.1:8000/api/v1/tasks?ege_number=5&limit=10&offset=0"
curl -i -X POST "http://127.0.0.1:8000/api/v1/works" \
  -H "Content-Type: application/json" \
  --data '{"topic_ids":[9296,9300,9316]}'
```

ID в примере реально проверены в LIVE-API 28.10.2026, но банк может измениться:
для новой работы сначала выбрать актуальные задачи поиском.
Создание — один длительный POST, результат **201 JSON Work**, а не тело PDF.
`name` необязателен. Порядок 1–100 уникальных ID сохраняется; 19–21 — один пункт.
Пользователь не передаёт путь, условия или ответы.

Из Work использовать URL как есть:

- `result`: ученический PDF либо ZIP с PDF и приложениями;
- `pdf`: отдельный просмотр, не замена ZIP при приложениях;
- `archive`: дополнительный ZIP-дескриптор либо null;
- `answers` и `sources`: отдельные преподавательские файлы, вне ученического комплекта.

Поиск отдаёт браузерный HTML без кода источника и без ответов. Рисунки/приложения
доставляются узким task-bound API, проверяющим принадлежность URL задаче перед Bank.fetch.
Оригинальные нормализованные данные сохраняются в sources без мутации проекцией UI.

## Хранение, отказ и транспорт

Каждый POST получает отдельные UUID/каталог, даже при одинаковом имени/составе.
Экспорт пишет фиксированные `work.*`; `work.json` публикуется последним после готовности.
Для атомарной публикации без перезаписи используется fsync + эксклюзивный hard link
внутри того же каталога, затем удаление временного имени. Это внутреннее уточнение
механизма публикации вместо перезаписывающего rename, без изменения контракта.

Работы сохраняются после перезапуска до ручной очистки. GET не вызывает экспорт
и не обращается к источнику; удалённый файл даёт JSON 404, остальные материалы доступны.
Незавершённые каталоги непубличны, автоматической очистки и истории нет.

Точный POST `/api/v1/works` не перенаправляется; `/api/v1/works/` — JSON 404 без экспорта.
Разрыв связи не отменяет уже начатый экспорт: при потере подтверждения исход для клиента
неизвестен, JS приложения не повторяет создание, восстановления потерянной работы нет.

**Изменение границ приёмки от 2026-10-28, A-09**: поддерживается и проверен Chromium;
Firefox не прошёл проверку и исключён из обязательной приёмки. Гарантия отсутствия
автоповтора относится только к JS приложения. B-01 — известная транспортная повторная
отправка Chromium при определённом TCP-разрыве до заголовков — остаётся непройденной
проверкой; возможны две работы внутри одного Fetch. Идемпотентность и «ровно один раз»
не гарантируются. Решение принято без изменения кода и полей API:
[соглашения](../evidence/agreements.md), [итог](../evidence/final-status.md).

Прикладные ошибки имеют ErrorResponse. Для файлового GET Starlette 1.10.0 отдельно
сохраняются одиночный/multipart 206, текстовый Range-400 и пустой Range-416 с Content-Range.
Обычное скачивание UI выполняется без Range. Прямой PDF-просмотр поддерживается.
Разрыв начатой передачи не заменяется JSON, повтор GET не создаёт работу заново.

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check app tests
.venv/bin/python -m pytest -q -m controlled
.venv/bin/python -m pytest -q -m real_local
.venv/bin/python -m pytest -q -s -m live_api tests/live/test_api_live.py
make -C /Users/avsimp/itmo/ai_tools/ITMOv2/practices/practice_03/homework check
make -C /Users/avsimp/itmo/ai_tools/ITMOv2/practices/practice_03/homework demo
```

Default pytest выполняет только автономные проверки; live_api/live_ui исключены
явным выражением маркеров, а не превращены в успешные тесты через skip.
REAL-LOCAL использует настоящий Bank/export_pdf/Chromium, но подменяет внешний HTTP;
LIVE-API запускает настоящий Uvicorn и сайт без overrides. Журналы и созданные работы
LIVE-API находятся в `var/checks/<run>/`. Это тестовое хранилище, не default var/works;
для его повторного просмотра явно настроить storage root и прежний origin.

Передача UI: [api-handoff.md](../evidence/api-handoff.md).

соответствующие контрактные, Range и MCP-проверки.

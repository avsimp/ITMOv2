# ДЗ 5 — две команды, одна фича

Локальный кабинет преподавателя: поиск оригинальных задач ЕГЭ из банка К. Полякова,
подборка в нужном порядке, ученический PDF/ZIP и отдельные ответы/источники.
UI — HTML/CSS/ES-модули; API — FastAPI поверх существующих Bank/export_pdf из ДЗ 3.
Другой SDD-фреймворк для этой работы — **Spec Kit**, применённый отдельно в UI и API.

**Сдача учебной версии**: комплект подготовлен по существующим результатам и уточнённым
пользователем границам A-09 от 2026-10-28. Поддерживаемый и проверенный браузер —
**Chromium**. Firefox не прошёл проверку и не блокирует сдачу. Отсутствие автоматического
повтора создания гарантируется для JS приложения; B-01 — известный транспортный повтор
Chromium при определённом TCP-разрыве — остаётся непройденной проверкой.
Идемпотентность и выполнение «ровно один раз» не гарантируются.

## Установка и запуск

Нужен полный checkout репозитория: API импортирует исходные модули из
`practices/practice_03/homework/`, а не содержит их копию. Нужны uv, Python 3.11+
и Chromium для PDF/браузерных проверок. Фактическое окружение: macOS, Python 3.14.4;
Python 3.11 отдельно не проверялся. Поиск/новый экспорт требуют доступа к внешнему сайту.

Из `practices/practice_05/homework/api/`:

```bash
uv venv .venv
uv pip sync --python .venv/bin/python requirements-dev.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

При уже подготовленном окружении достаточно последней команды.
Открыть **http://127.0.0.1:8000/** в Chromium. API находится на `/api/v1`, Swagger UI —
на `/docs`. UI и API работают на одном origin; npm и отдельный frontend-сервер не нужны.
Использовать один worker, без `--reload` во время создания.

Готовые работы хранятся в `api/var/works/` до ручной очистки и доступны после перезапуска.
При смене порта согласовать `HOMEWORK_API_ORIGIN` с `--port`; настройки хранения/UI —
в [README API](api/README.md). Подборка живёт только в открытой странице.

## Существующие команды проверок

Это команды для воспроизведения, а не новые результаты упаковки. Итоги ранее выполненных
прогонов — в [final-status.md](evidence/final-status.md), подробности — в
[API verification](evidence/api-verification.md) и [UI verification](evidence/ui-verification.md).
Повторно тестировать неизменённое приложение при упаковке не потребовалось.

Из `api/` — автономные API-проверки, Ruff и проверка общего OpenAPI:

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check app tests
.venv/bin/python -m openapi_spec_validator ../contracts/api-v1.yaml
```

Из `ui/` — отдельные уровни и Ruff:

```bash
../api/.venv/bin/python -m pytest -q -m controlled
../api/.venv/bin/python -m pytest -q -m real_local
../api/.venv/bin/python -m ruff check tests
```

CONTROLLED подменяет API-ответы/экспортёр; REAL-LOCAL использует настоящий локальный
стек с подменой только внешнего HTTP-источника. UI pytest по умолчанию выбирает controlled;
API pytest — controlled/real_local. Эти уровни не считаются живой проверкой сайта.

Отдельные существующие live-команды (обращаются к сайту и создают реальные материалы):

```bash
# Из api/
.venv/bin/python -m pytest -q -s -m live_api tests/live/test_api_live.py
# Из ui/
../api/.venv/bin/python -m pytest tests/test_ui.py -q -s -m live_ui
```

Совместимость ДЗ 3: из `practices/practice_03/homework/` существующие `make check`
и `make demo` (настоящая MCP stdio-сессия с живым экспортом).
Отдельный `boundary_probe` в UI — диагностический воспроизводитель **непройденного B-01**,
он не включён в успешные live-результаты. Команда сохранена в [README UI](ui/README.md).
При этой упаковке live-команды, TCP-эксперименты и настройка Firefox не выполнялись.

## Короткое демо

Сценарий показа уже реализованного поведения; новая запись/новый прогон при упаковке
не выполнялись. Для демонстрации с новым экспортом нужен доступный источник.

1. Открыть `/` в Chromium. Выбрать номер 5, оставить «Все категории», нажать
   «Найти задачи». Показать полное условие, таблицу/рисунок и отсутствие ответов.
2. Добавить две задачи без приложений и один блок 19–21. Перелистнуть выдачу,
   переместить блок выше и удалить/добавить пункт: подборка и порядок сохраняются,
   блок 19–21 считается одним пунктом.
3. Нажать «Создать работу». Во время ожидания создание/редактирование заблокированы,
   поиск доступен. После готовности получить ученический PDF, затем «Сохранить файл»;
   ответы и sources получить отдельными преподавательскими кнопками.
4. Для ZIP выбрать задачу с приложением: основной результат — архив целиком,
   PDF — только preview. После распаковки `work.pdf` и `work.files/` должны остаться рядом.
   Повторное скачивание известной работы — GET без нового экспорта.
5. Ошибка без нового экспорта: в DevTools Chromium отключить сеть перед новым поиском.
   Показать сообщение, сохранённую подборку; вернуть сеть и явно повторить поиск.
   Для unknown после начала POST и B-01 использовать уже сохранённые отчёты,
   демонстрационный TCP-эксперимент не требуется.

В подтверждённом LIVE-UI примере PDF использовал ID `9296, 9316, 9300`, ZIP — `9316, 9304`.
Это исторические ID от 2026-10-28, их доступность не обещается; для нового показа выбрать
актуальные задачи. UUID, шаги и ссылки на локальные журналы — в UI verification.

## Clarifications

### Session 2026-10-27

Решения взяты из `../evidence/agreements.md` (A-01–08) и
`../api/specs/001-task-bank-http/spec.md` относительно корня UI.
Пользователь поручил применить принятые решения; дополнительных вопросов не задавалось.

- Q: Как создаётся работа и обязательно ли вводить имя? → A: Одним длительным
  HTTP-запросом, без обязательного имени; если имя не передано, его назначает сервер.
  Успех — только после готовности всех материалов и метаданных; фоновых заданий,
  опроса прогресса, промежуточного успеха и отмены в первой версии нет (A-01, A-03).
- Q: Что происходит при потере связи до подтверждённого ответа? → A: Исход неизвестен;
  показать «Результат не подтверждён» и «Предыдущая работа могла быть создана», сохранить
  подборку и снять блокировки. Доступны поиск, редактирование, материалы известных работ
  и явное «Создать новую работу» для непустой подборки. Автоповтора и восстановления
  неизвестной работы нет; новое создание может дать дубль по содержимому (A-02).
- Q: Что определяет идентичность и срок хранения работы? → A: Каждое создание получает
  отдельный `work_id` и каталог, даже при одинаковом имени. Готовые материалы и метаданные
  хранятся после перезапуска сервера до ручной очистки, без автоудаления. История UI
  и восстановление подборки после перезагрузки страницы не требуются (A-03–04).
- Q: Какие условия, ресурсы и ссылки получает UI? → A: Оригинальный HTML без исполняемого
  кода источника, HTTP(S)-адреса рисунков/приложений и отдельные URL API для скачивания
  готовых материалов. Локальные абсолютные пути не передаются, в том числе в ошибках;
  способ доставки уже определён планом и общим контрактом: браузерная HTML-проекция
  и task-bound resource API (A-06).
- Q: Где доступны ответы? → A: Только в отдельных преподавательских материалах готовой
  работы: текст ответов и JSON источников существующего формата. В поиске, карточках,
  метаданных результата и ученических PDF/ZIP содержимого ответов нет; предварительного
  просмотра ответа отдельной задачи нет (A-05).

Дополнительно UI подтвердил уточнения обновлённого контракта:

- **A-07**: точный POST `/api/v1/works`, `redirect: "error"`; API не перенаправляет.
  POST `/api/v1/works/` возвращает JSON 404 not_found без Location и запуска экспорта.
- **A-08**: обычное скачивание UI — полный GET без Range. Прикладные ошибки остаются
  JSON ErrorResponse; только Range внутри FileResponse допускает 400 text/plain
  и 416 text/plain с пустым телом/Content-Range bytes */N. Прямой просмотр PDF поддерживает
  одиночный и multipart 206; исключения не распространяются на JSON 400 POST и 404 файла.

## User Scenarios & Testing *(mandatory)*

Сценарии ниже — критерии будущей приёмки, а не результаты выполненных проверок.

### User Story 1 - Найти и изучить оригинальные задачи (Priority: P1)

Преподаватель выбирает номер задания ЕГЭ, при необходимости категорию и запускает поиск.
Он видит полные условия, рисунки, таблицы и признак наличия приложений, чтобы выбирать
задачи по содержанию, а не по краткому пересказу.

**Why this priority**: Без просмотра оригинала преподаватель не может оценить пригодность задачи.

**Independent Test**: Выбрать номер и категорию, выполнить поиск и просмотреть результаты,
включая задачу с рисунком и задачу с приложением; подборку создавать не требуется.

**Acceptance Scenarios**:

1. **Given** номер не выбран, **When** открыто приложение, **Then** показано приглашение
   выбрать номер, а поиск недоступен; это не состояние «ничего не найдено».
2. **Given** выбран номер, **When** категории загружены, **Then** можно выбрать одну
   категорию либо «Все категории»; поиск работает без обязательного выбора категории.
3. **Given** задан фильтр, **When** запущен поиск, **Then** виден статус загрузки;
   после успеха показаны оригинальные условия с рисунками и таблицами, ID источника,
   номер ЕГЭ и явная отметка «Есть приложения» либо «Без приложений». Условия получены
   как HTML без исполняемого кода источника, рисунки и приложения имеют HTTP(S)-адреса;
   содержимое ответов отсутствует, кнопки предварительного просмотра ответа нет.
4. **Given** есть следующие результаты, **When** нажата кнопка «Следующие», **Then**
   показана следующая порция для того же фильтра; в конце списка кнопка недоступна.
5. **Given** поиск успешно завершён без совпадений, **When** отображён результат,
   **Then** показано «Ничего не найдено» и предложение изменить фильтры.
6. **Given** недоступен источник или локальный сервис, **When** поиск завершается ошибкой,
   **Then** показаны понятное сообщение и «Повторить»; ошибка не выглядит как пустая выдача.
7. **Given** изменён номер, **When** обновляется список категорий, **Then** старая категория
   сброшена; запоздалый ответ предыдущего поиска не заменяет выдачу нового фильтра.

### User Story 2 - Собрать и упорядочить домашнюю работу (Priority: P1)

Преподаватель добавляет задачи из разных результатов поиска, удаляет лишние и меняет
порядок кнопками «Вверх» и «Вниз», не теряя уже выбранные задачи.

**Why this priority**: Подборка и её порядок определяют содержание будущей работы.

**Independent Test**: На заранее доступных результатах добавить три задачи, повторно
попытаться добавить одну из них, поменять порядок и удалить пункт; экспорт не требуется.

**Acceptance Scenarios**:

1. **Given** задача ещё не выбрана, **When** нажато «Добавить», **Then** она появляется
   в конце подборки, счётчик увеличивается на один, а карточка помечается «В подборке».
2. **Given** задача уже выбрана, **When** она снова встречается в выдаче или нажата
   повторно, **Then** второй экземпляр не создаётся; сравнение выполняется по ID источника.
3. **Given** в подборке есть задачи, **When** преподаватель листает выдачу, меняет номер
   или категорию, получает пустой результат либо ошибку поиска, **Then** состав и порядок
   подборки сохраняются; после удаления задача снова доступна для добавления.
4. **Given** подборка A, B, C, **When** у C нажато «Вверх», затем удалена A,
   **Then** остаются C, B с непрерывной нумерацией 1, 2; «Вверх» у первой и «Вниз»
   у последней недоступны. Повторное добавление A помещает её в конец.
5. **Given** найден блок 19–21, **When** он добавлен или перемещён, **Then** общая игра
   и три вопроса остаются одним пунктом, одним ID и одной единицей счётчика.
6. **Given** выбрано 100 пунктов, **When** пользователь хочет добавить ещё один,
   **Then** добавление недоступно и объяснён предел; текущая подборка не изменяется.

### User Story 3 - Создать и получить материалы работы (Priority: P1)

Преподаватель создаёт работу из текущей подборки и получает явно разделённые
ученические материалы, ответы и источники, не выполняя действия в командной строке.

**Why this priority**: Готовые материалы — конечный результат составления домашней работы.

**Independent Test**: Для заранее подготовленной подборки выполнить создание и скачивание;
отдельно повторить с приложением, подтверждённой ошибкой и разрывом связи до ответа,
без проверки поиска. Для известной готовой работы проверить скачивание после перезапуска.

**Acceptance Scenarios**:

1. **Given** подборка пуста, **When** отображена область создания работы, **Then**
   «Создать работу» недоступно и показана причина «Добавьте хотя бы одну задачу».
2. **Given** есть от 1 до 100 пунктов и имя не введено, **When** нажато «Создать работу»,
   **Then** отправлен один длительный запрос без имени и файлового пути, виден статус
   «Создаём работу»; повторное создание и изменение подборки заблокированы только
   до завершения ожидания. Нет фонового задания, опроса прогресса, отмены и частичного успеха.
   Быстрые повторные нажатия не отправляют дополнительных запросов.
3. **Given** в подборке нет приложений, **When** создание успешно завершено, **Then**
   после готовности всех материалов показано «Работа создана», назначенное сервером имя,
   число пунктов и «Скачать для ученика (PDF)»; отдельно доступны «Скачать ответы»
   и «Скачать источники». Каждое действие использует отдельный URL API, не локальный путь.
4. **Given** хотя бы у одного пункта есть приложение, **When** создание успешно,
   **Then** основной результат — «Скачать для ученика (ZIP)» с PDF и приложениями;
   рядом объяснено, что архив нужно распаковать целиком. Ответы и источники находятся
   вне ученического ZIP. Отдельный PDF доступен как «PDF для просмотра».
5. **Given** подборка включает обычную задачу и блок 19–21, **When** получены материалы,
   **Then** в PDF, ответах и источниках совпадает выбранный порядок; блок занимает
   один пункт с тремя вопросами. Условия не пересказаны и не сокращены.
6. **Given** получен подтверждённый отказ создания, **When** показана понятная причина,
   **Then** нет ложного успеха и ссылок на частичный результат; подборка сохранена,
   блокировки сняты. Доступны поиск, редактирование, материалы ранее известных работ
   и явный повтор «Создать работу» после исправления причины, без автоматического запроса.
7. **Given** работа создана, **When** пользователь скачивает файл повторно, **Then**
   скачивается тот же результат без нового экспорта; ошибка скачивания допускает повтор.
8. **Given** работа создана, **When** подборка изменена, **Then** прежние материалы
   явно помечены «Для предыдущей подборки» и не выдаются за результат новой;
   для новой подборки требуется отдельное нажатие «Создать работу».
9. **Given** связь потеряна до подтверждённого ответа, **When** UI завершает ожидание,
   **Then** показаны «Результат не подтверждён» и «Предыдущая работа могла быть создана»;
   это не отказ и не успех. Состав и порядок сохранены, блокировки создания и редактирования
   сняты; доступны поиск, добавление, удаление, перестановка и скачивание известных работ.
   Нет автоматического повтора, опроса или кнопки восстановления неизвестной работы.
10. **Given** результат не подтверждён, предупреждение показано и подборка непуста,
    **When** пользователь явно нажимает «Создать новую работу», **Then** отправляется
    один новый длительный запрос по текущей подборке и снова включаются блокировки
    на время ожидания. Это отдельная работа, возможен дубль по содержимому;
    предупреждение не заменяется обычным безусловным «Повторить» после смены подборки.
    Если подборка стала пустой, новое создание недоступно, поиск и редактирование доступны.
11. **Given** работа готова и её ID/URL известны открытой странице, **When** сервер
    перезапущен без очистки, **Then** те же метаданные и файлы доступны по известным
    ссылкам без нового экспорта и с прежними байтами. Экран истории для этого не требуется.
12. **Given** материал вручную удалён, **When** используется прежний URL, **Then** показано
    понятное отсутствие файла; новый экспорт не запускается, другие сохранённые материалы
    доступны. Перезагрузка страницы не обязана восстанавливать подборку или потерянный ID.
13. **Given** работа уже создана, **When** выполнено ещё одно явное создание, **Then**
    сервер возвращает отдельный ID и имя, материалы предыдущей работы не перезаписываются;
    одинаковое имя само по себе не означает конфликт или ту же работу.
14. **Given** допустимая подборка, **When** UI создаёт работу, **Then** используется
    точный POST `/api/v1/works` с запретом redirect; вариант со слешем при диагностике
    даёт JSON 404 без экспорта. Навязанный 307/308 не приводит ко второму POST.
15. **Given** работа готова, **When** UI получает материал, **Then** обычный GET не посылает
    Range и получает полный 200. Прямой просмотр PDF допускает файловые 206 и текстовые
    Range-ошибки 400/416; они не разбираются безусловно как JSON и не запускают экспорт.

### Edge Cases

- Ошибка загрузки категорий: показать причину и повтор; поиск заблокирован до успешной
  загрузки категорий текущего номера, но выбранные ранее задачи остаются в подборке.
- Смена фильтра сбрасывает позицию выдачи на первую порцию. Переход «Предыдущие»
  возвращает предыдущую порцию; на первой он недоступен. Размер порции по умолчанию — 10.
- На время поиска его повтор и переходы по выдаче заблокированы; фильтры можно изменить.
  Старая выдача при загрузке, ошибке или смене фильтра не доступна для добавления задач.
- Незагрузившийся рисунок отмечается внутри карточки как неполное отображение с повтором;
  до его успешной загрузки добавление из этой карточки недоступно. Экспорт уже выбранной
  задачи при недоступном ресурсе завершается сообщением об ошибке, без подмены условия.
- Потеря связи завершает клиентское ожидание, но не отменяет создание на сервере.
  Показать неизвестный исход и предупреждение, снять блокировки, сохранить подборку.
  «Создать новую работу» — только явное отдельное создание, без гарантии отсутствия
  дубля по содержимому; автоматического повтора и восстановления по имени нет.
- В неизвестном состоянии обычные ограничения сохраняются: нельзя создать пустую работу,
  превысить 100 пунктов или двигать крайний пункт за границу. Эти ограничения не являются
  оставшейся блокировкой экспорта. Предупреждение сохраняется при изменениях подборки.
- Одинаковое имя допустимо: идентичность задаёт отдельный ID работы. Конфликт файлов
  или отказ записи отображаются как подтверждённая ошибка без перезаписи прежних материалов.
  Отсутствие имени не заменяется явными null, пустой строкой или строкой из пробелов.
- Ошибка получения одного файла не отменяет уже созданную работу и доступ к другим файлам.
- После перезапуска сервера известные метаданные и ссылки сохраняются до ручной очистки.
  Удалённый материал даёт понятную ошибку отсутствия, без автоматического нового экспорта.
- Ответы отсутствуют в выдаче и карточках; JSON источников готовой работы относится
  к преподавательским материалам и может содержать исходные ответы.
- Между поиском и экспортом источник может измениться; единый снимок всего банка
  не обещается. Экспорт получает оригиналы по ID, а скачивание выдаёт уже созданные файлы,
  не обращаясь заново к источнику и не меняя результат по текущему состоянию банка.
- Блок 19–21, найденный через любой из номеров 19, 20, 21, не добавляется повторно.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: UI обязан позволять выбрать номер ЕГЭ из поддерживаемых 1–27;
  19–21 отображаются одной общей группой с пояснением «один блок — один пункт».
- **FR-002**: После выбора номера UI обязан загрузить актуальные категории, предложить
  «Все категории» по умолчанию и необязательный выбор одной категории.
- **FR-003**: Поиск запускается явной кнопкой; изменение фильтра сбрасывает старую
  категорию при смене номера и позицию выдачи, но не подборку.
- **FR-004**: Результат обязан содержать полное оригинальное условие с рисунками,
  таблицами и ссылками на приложения, ID источника, номер/группу ЕГЭ и признак приложений.
  Условие предоставляется как HTML без исполняемого кода источника; рисунки и приложения
  имеют пригодные для браузера HTTP(S)-адреса. Выдача и карточки не содержат ответов;
  предварительного просмотра ответа задачи в первой версии нет.
- **FR-005**: UI обязан поддерживать кнопки «Предыдущие» и «Следующие» и однозначно
  показывать отсутствие следующей порции, не очищая подборку.
- **FR-006**: UI обязан различать начальное состояние, загрузку, успешную пустую выдачу,
  ошибку категорий/поиска и успешную выдачу; для ошибки обязателен явный повтор.
- **FR-007**: Запоздалый ответ для старого фильтра не должен заменять актуальные результаты.
- **FR-008**: «Добавить» обязан добавлять новый ID в конец подборки; выбранный ID отмечается
  «В подборке» и не добавляется повторно, включая повторные нажатия и другие страницы.
- **FR-009**: Подборка обязана сохранять состав, порядок и счётчик при всех действиях
  поиска в пределах открытой страницы, включая пустые результаты и ошибки.
- **FR-010**: Каждый пункт обязан иметь «Удалить», «Вверх», «Вниз»; перемещение выполняется
  на одну позицию, недопустимое движение на границе заблокировано, номера пересчитываются.
- **FR-011**: UI обязан трактовать полный блок 19–21 как один неделимый пункт везде,
  включая счётчик, удаление, перестановку и создание работы.
- **FR-012**: UI обязан поддерживать от 1 до 100 уникальных пунктов для создания;
  при пустой подборке создание недоступно, при 100 пунктах добавление недоступно.
- **FR-013**: Создание обязано передавать ID в выбранном порядке без обязательного ввода
  имени и без файлового пути. В автоматическом сценарии имя отсутствует в запросе,
  а не передаётся как null или пустая строка; имя назначает сервер. Отдельное поле ввода
  имени для этой фичи не требуется. Условия и ответы не редактируются и не генерируются UI.
- **FR-014**: Каждое создание обязано выполняться одним длительным HTTP-запросом.
  UI использует точный POST `/api/v1/works` с `redirect: "error"`, без перенаправлений
  и повторной отправки тела. Вариант со слешем возвращает JSON 404 без Location и экспорта.
  Пока UI ожидает ответ, повторный запуск и все изменения подборки заблокированы;
  поиск, просмотр и скачивание ранее известных материалов доступны. Блокировки снимаются
  после успеха, подтверждённого отказа или завершения ожидания с неизвестным результатом.
  Фоновые задания, опрос прогресса, промежуточный успех и отмена не входят в первую версию.
- **FR-015**: Успех допускается только после готовности всех материалов и метаданных;
  UI обязан показывать статус, серверное имя, число пунктов и отдельные действия скачивания
  ученического материала, ответов и источников по URL API. Результат связан с полученным
  `work_id`; одинаковое имя не заменяет ID, каждое создание получает отдельную идентичность.
  Содержимого ответов и источников в метаданных результата нет.
- **FR-016**: Без приложений ученический результат обязан быть PDF; с приложениями — ZIP
  с PDF и файлами. Дополнительный PDF для просмотра при ZIP явно не заменяет комплект.
- **FR-017**: Ответы и источники обязаны скачиваться отдельно с подписями «Для преподавателя»;
  только для готовой работы, по отдельным URL API. Ответы — текстовый файл, источники —
  JSON существующего формата с оригинальными данными и картой приложений, включая исходные
  ответы. Эти данные не включаются в ученические PDF/ZIP и не показываются до создания.
- **FR-018**: Созданные материалы обязаны сохранять оригинальные условия, рисунки и порядок,
  используя действующий экспортёр; существующие правила имён приложений сохраняются.
- **FR-019**: Подтверждённый отказ создания обязан сохранять подборку, объяснять причину,
  снимать блокировки и позволять поиск, редактирование и явный повтор «Создать работу»
  для допустимой подборки. Частичный результат не публикуется как готовая работа;
  ранее известные материалы доступны. UI не показывает локальные абсолютные пути
  или трассировки в данных, ссылках и сообщениях об ошибках. Автоматического повтора нет.
- **FR-020**: Потеря связи до подтверждённого ответа означает неизвестный результат,
  а не отказ/успех. UI обязан завершить ожидание, снять блокировки, сохранить состав
  и порядок, показать «Результат не подтверждён» и «Предыдущая работа могла быть создана».
  Доступны поиск, добавление, удаление, перестановка, чтение метаданных и скачивание
  ранее известной работы. Для допустимой непустой подборки доступно явное
  «Создать новую работу»: отдельный запрос по текущей подборке, не восстановление,
  с возможным дублем содержимого. Предупреждение сохраняется при изменении подборки
  до нового создания. Нет автоматического повтора, опроса, поиска или восстановления
  потерянного результата без полученного ID, в том числе по имени. Дедупликация ID
  внутри подборки сохраняется и не означает дедупликацию разных работ по содержимому.
- **FR-021**: Скачивание обязано получать уже созданный файл без повторного создания;
  каждый вид материала имеет отдельный HTTP(S)-URL API, не адрес файловой системы.
  Готовые файлы и необходимые метаданные хранятся сервером между перезапусками до ручной
  очистки, без автоудаления, и доступны по известному ID/URL с прежними байтами.
  Отсутствие материала после очистки показывается понятной ошибкой, без нового экспорта.
  Неудача скачивания допускает явный повтор и не очищает подборку или другие результаты.
  Обычное скачивание — полный GET без Range/If-Range; прямой PDF-просмотр сохранён.
  Прикладные ошибки имеют JSON ErrorResponse, но транспортные Range 400 text/plain
  и 416 text/plain с пустым телом/Content-Range bytes */N исключены. Они возникают только
  после разрешения готового артефакта в FileResponse; 404 отсутствующего файла,
  даже с плохим Range, остаётся JSON. Не сохранять частичный ответ как полный файл.
- **FR-022**: Результат обязан быть связан с составом и порядком на момент создания;
  после изменений подборки прежний результат явно обозначается как предыдущий.
- **FR-023**: Все действия выбора, добавления, удаления, перемещения, создания и скачивания
  обязаны быть доступны кнопками/элементами с понятными русскими подписями и с клавиатуры;
  перетаскивание и командная строка не требуются. Статусы не передаются только цветом.

### Состояния интерфейса

| Область / состояние | Что видит преподаватель | Доступные действия |
| --- | --- | --- |
| Начальное | «Выберите номер ЕГЭ», пустая подборка | Выбрать номер; поиск/создание недоступны |
| Загрузка категорий | «Загружаем категории» | Сменить номер; подборка сохранена |
| Загрузка выдачи | «Ищем задачи» | Изменить фильтр; повтор поиска и листание недоступны |
| Выдача готова | Полные карточки, признаки приложений | Добавить, листать, изменить фильтр |
| Пустая выдача | «Ничего не найдено» | Изменить фильтр, повторить поиск |
| Ошибка поиска/категорий | Причина и «Повторить» | Повторить, изменить фильтр; подборка сохранена |
| Пустая подборка | «Добавьте хотя бы одну задачу» | Искать и добавлять; создание недоступно |
| Создание | «Создаём работу», ожидание одного длительного запроса без прогресса и отмены | Поиск, просмотр, материалы известных работ; создание и изменение подборки заблокированы |
| Подтверждённая ошибка создания | Понятная причина, без частичного успеха | Блокировки сняты; поиск, редактирование, известные материалы, явное «Создать работу» |
| Результат не подтверждён | «Результат не подтверждён» и «Предыдущая работа могла быть создана» | Ожидание завершено, блокировки сняты; поиск, добавление, удаление, перестановка, известные материалы; явное «Создать новую работу» при непустой подборке, без автоповтора/восстановления |
| Успешный экспорт | «Работа создана», серверное имя, число пунктов, раздельные URL материалов | Скачивать; редактировать подборку; явно создавать другую работу |
| Ошибка скачивания / материал удалён | Понятная ошибка рядом с конкретным файлом | Повторить скачивание без нового экспорта; другие сохранённые материалы доступны |

Состояния поиска и экспорта независимы: разрешённое действие в выдаче не снимает
блокировку изменения подборки, пока ожидается создание. После перехода в неизвестный
результат эта блокировка не сохраняется, но действуют обычные ограничения пустой подборки,
лимита и границ порядка. Действия с известными материалами доступны при восстановленном
соединении; это не обещание скачивания при отсутствии связи. Для неизвестной работы
ссылки не выдумываются; известный результат предыдущей работы остаётся явно отделённым.

### Key Entities *(include if feature involves data)*

- **Номер ЕГЭ и категория**: фильтр поиска; категории принадлежат выбранному номеру,
  а группа 19–21 соответствует общему блоку.
- **Задача**: постоянный ID источника, номер/группа ЕГЭ, оригинальное условие,
  HTML без исполняемого кода, HTTP(S)-адреса изображений/приложений и ссылка на источник;
  в данных поиска и карточке нет ответа.
- **Выдача**: результаты текущего фильтра, текущая порция и возможность переходов.
- **Подборка**: упорядоченный список уникальных задач, позиции и число пунктов до 100.
- **Созданная работа**: отдельный `work_id`, серверное имя, зафиксированные состав/порядок
  и комплект готовых файлов. Имя не является идентификатором. Материалы и необходимые
  метаданные сохраняются после перезапуска до ручной очистки.
- **Материал работы**: назначение (ученик/преподаватель), тип, имя, отдельный URL API
  и доступность скачивания; ученический PDF либо ZIP, отдельные ответы и источники,
  при ZIP — PDF для просмотра. Локальный путь не является публичным адресом материала.
- **Результат не подтверждён**: клиентское состояние после потери связи до ответа;
  работа могла быть создана, её ID может быть неизвестен. Это не статус отказа API.

## Success Criteria *(mandatory)*

### Measurable Outcomes

Это целевые критерии будущей приёмки; фактические измерения ещё не проводились.

- **SC-001**: В двух сквозных приёмочных сценариях (без приложений и с приложением)
  преподаватель проходит от выбора номера до скачивания ученического материала,
  ответов и источников только через интерфейс, без ввода имени, локального пути,
  командной строки и поиска файлов вручную. Каждое создание — один длительный запрос;
  частичный успех, фоновые задания, опрос прогресса и отмена отсутствуют.
- **SC-002**: В проверочной подборке из трёх пунктов, включая блок 19–21 и задачу
  с рисунком, при неизменном контрольном источнике 100% условий, рисунков и порядок
  соответствуют выбранным оригиналам; блок занимает ровно один пункт в подборке
  и готовой работе.
- **SC-003**: После трёх переходов по выдаче, смены фильтра, пустой выдачи и одной
  ошибки поиска состав и порядок ранее выбранных задач остаются неизменными.
  Пять повторных попыток добавить один ID дают ровно один экземпляр.
- **SC-004**: Переместить пункт на соседнюю позицию и удалить пункт можно одним нажатием
  соответствующей кнопки; ни один сценарий управления подборкой не требует перетаскивания.
- **SC-005**: Пять быстрых нажатий «Создать работу» до завершения дают один запуск
  создания. Загрузка, пустая выдача, подтверждённая ошибка, неизвестный результат и успех
  различимы текстом; статус занятости и блокировка повторов видны не позднее одной секунды
  после действия. При успехе, подтверждённом отказе и неизвестном исходе после завершения
  ожидания блокировки снимаются не позднее одной секунды.
- **SC-006**: В обоих экспортных сценариях ученический комплект содержит ноль отдельных
  файлов ответов/источников; оба преподавательских материала доступны отдельно.
  В выдаче, карточках и метаданных результата нет содержимого ответов;
  условия имеют HTML без исполняемого кода, все адреса ресурсов — HTTP(S), скачивания —
  отдельные URL API. Локальных абсолютных путей в выдаче, метаданных и ошибках нет.
  После подтверждённой ошибки и потери связи 100% выбранных пунктов и их порядок сохраняются.
  В сценарии потери связи автоматических повторов — ноль; поиск и редактирование доступны,
  а один явный выбор «Создать новую работу» после предупреждения запускает один новый запрос
  без обещания восстановить предыдущую работу или исключить дубль содержимого.
  После перезапуска 100% сохранённых материалов доступны по известным ID/URL с прежними
  байтами; после ручного удаления одного материала показано его отсутствие, остальные
  доступны, автоматических повторных экспортов — ноль. Экран истории не требуется.

## Assumptions

- Один преподаватель использует локальное приложение на настольном компьютере;
  совместное редактирование, учётные записи и публикация в интернете не входят в фичу.
- «Локальное» не означает автономность без сети: существующий подборщик получает
  условия и ресурсы с сайта К. Полякова; недоступность источника показывается как ошибка.
- Подборка хранится в пределах открытой страницы и не сбрасывается поиском.
  Восстановление подборки после перезагрузки/закрытия и экран истории работ вне первой
  версии. Это ограничение клиентского состояния, а не запрет серверного хранения:
  сервер сохраняет готовые материалы и необходимые метаданные между перезапусками
  до ручной очистки, без автоудаления. Известные ID/URL продолжают работать.
- По умолчанию доступны все категории выбранного номера; в первой версии выбирается
  не более одной категории. Поиск по тексту, сложности и автоматический подбор вне фичи.
- Работы могут включать задачи разных номеров. Категории не фиксируются заранее;
  отображаются актуальные названия из существующего подборщика.
- Для создания не требуется вводить имя или абсолютный путь. Если имя не передано,
  его назначает сервер; каждое создание получает отдельный ID и каталог, одинаковое
  имя допустимо. UI отображает полученное имя. Наличие поля необязательного имени
  не требуется этой фичей; API поддерживает его по своим правилам проверки.
- Один длительный запрос, отсутствие фоновых заданий, прогресса и отмены — принятые
  решения, не открытый выбор. Потеря связи не отменяет серверную работу и не доказывает
  отказ. Ожидание завершается, блокировки снимаются; новое создание только явное,
  после предупреждения, без гарантии отсутствия дублей по содержимому.
- Восстановление неизвестной работы без полученного ID, поиск по имени и список истории
  не входят в первую версию. Это не ограничивает чтение метаданных и скачивание
  уже известной готовой работы. Для скачивания готовых файлов источник задач не нужен.
- Ответы доступны только как преподавательские материалы готовой работы, а не при поиске
  или предварительном просмотре задачи. HTTP(S)-ресурсы могут временно быть недоступны;
  UI показывает проблему без пересказа и не обещает доступность внешнего источника.
- Ошибки не скрываются под пустым результатом, а неполное условие не заменяется пересказом.
- Основа изучения: `practices/practice_03/homework/README.md`, `server.py`, `polyakov.py`
  и `render.py` в том же каталоге. Подтверждено чтением: категории, поиск порциями до 30,
  ID, разметка условий, изображения/приложения, общий блок 19–21, экспорт 1–100 уникальных
  ID в заданном порядке, отдельные ответы/источники, PDF либо ZIP и запрет перезаписи.
  Живые вызовы и проверки приложения на этом этапе не выполнялись.
- Исходная независимая версия сохранена в `../evidence/ui-before.md` без изменений.
  При этом уточнении прочитаны `../evidence/agreements.md` и
  `../api/specs/001-task-bank-http/spec.md`; внешнее поведение приведено к A-01–08.
  Общий `../contracts/api-v1.yaml` принят как 1.0.0 со статусом agreed;
  уточнения A-07–08 отражены в требованиях и документах плана. API отвечает за ведение
  единственного контракта и интеграцию. UI не дублирует поиск/экспорт и сохраняет MCP.

## Итог согласования

Все три исходных вопроса закрыты по внешнему поведению. Критических неоднозначностей,
требующих новых вопросов пользователю, нет.

1. **OQ-01 — закрыт A-05–06.** Оригинальные условия без ответов и исполняемого кода,
   HTTP(S)-адреса ресурсов, отдельные URL API готовых материалов; абсолютных локальных
   путей нет, недоступность ресурса показана явно. Технический способ доставки определён
   планом и контрактом, доступность внешнего источника не гарантируется.
2. **OQ-02 — закрыт A-01–02.** Один длительный запрос; подтверждённый отказ отличим
   от неизвестного результата. При потере связи ожидание завершается и блокировки снимаются;
   нет автоматического повтора, опроса или восстановления неизвестной работы. Только явное
   «Создать новую работу» после «Предыдущая работа могла быть создана», с возможным дублем
   по содержимому. Поиск, редактирование и доступ к известным работам остаются доступны.
3. **OQ-03 — закрыт A-03–04.** Имя необязательно, назначается сервером при отсутствии;
   одинаковые имена допустимы, каждое создание получает отдельный ID/каталог.
   Материалы и метаданные сохраняются после перезапуска до ручной очистки; отсутствие
   файла — понятная ошибка без нового экспорта. История и восстановление подборки вне фичи.

Расхождений требуемого поведения с A-01–08 и обновлённым контрактом не обнаружено.

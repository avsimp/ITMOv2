## Конкретные отличия от первоначальной спецификации

«Конфликт» означает несовместимость исходного ожидания с итоговым контрактом; «уточнение» — ранее
не назначенный формат; «разделение ответственности» — поведение UI, не недостающая API-операция.
Ниже указаны требования именно из исходного снимка, а не из поздней редакции.
Все перечисленные исходные расхождения разрешены; это история уточнения, не открытые блокеры.

| ID / вид | Исходная спецификация | Контракт 1.0.0 | Принятое минимальное решение |
| --- | --- | --- | --- |
| D-01 / конфликт | OQ-02 предлагает проверку/восстановление потерянного результата перед повтором | Описание POST `/api/v1/works`: нет job, polling, поиска потерянной работы и идемпотентности | Убрать восстановление неизвестной работы; только явное «Создать новую работу» после предупреждения. Уже отражено в текущем FR-020 |
| D-02 / конфликт | FR-014 блокирует до подтверждённого завершения; в неизвестном состоянии действия не определены | После разрыва исход неизвестен, автоматического продолжения проверки нет; A-02 разрешает новое создание | Завершить ожидание и снять блокировки при неизвестном результате; сохранить подборку и предупреждение. Текущие FR-014/020 |
| D-03 / конфликт | OQ-03 предлагает доступность файлов до конца локального сеанса; Assumptions исключают постоянное хранение без различения клиента/сервера | Готовые материалы и метаданные сохраняются после перезапуска до ручной очистки | Ограничение сеанса оставить только для клиентской подборки; не вводить историю. Текущий FR-021 |
| D-04 / конфликт | API-P08 предлагает повтор «без незаметного дублирования работ» | Каждый POST — отдельный UUID/каталог; одинаковое содержимое может создаться повторно | Запретить автоповтор; сообщать о возможном предыдущем результате. Дубли задач внутри подборки по-прежнему запрещены, дубли разных работ не исключаются |
| D-05 / конфликт | Assumptions/API-P09 ожидают «уникальное имя»; Edge Cases называют конфликт имени | `CreateWork.name` необязателен; имя может повторяться, идентичность — UUID; `output_conflict` относится к файлам | Не требовать имени и не отправлять null/пустую строку; показать серверное имя, отличать его от ID и `work.*`. Отдельный ввод имени не нужен |
| D-06 / уточнение | API-P04/OQ-01 не определяют способ выдачи условий и ресурсов | `Task.statement_html` — браузерная копия с API-URL; `images/attachments` содержат те же delivery URL, исходники остаются в sources | Использовать HTML и URL как есть; не заменять рисунки текстом, не собирать proxy URL из исходных ссылок; серверная allowlist описана в плане API |
| D-07 / уточнение | FR-004 требует признак приложений без формы данных | Отдельного `has_attachments` нет: `Task.attachments` — список URL | Вычислять признак `attachments.length > 0`; не запрашивать новое поле |
| D-08 / уточнение | FR-005 и Edge Cases требуют «Предыдущие», но не определяют курсор | Есть `next_offset`, `offset`, `limit`, `total`; обратного курсора нет | Хранить предыдущие успешные смещения в UI; сбрасывать при фильтре; изменения истории фиксировать только после успешного ответа |
| D-09 / уточнение | FR-015/API-P06 требуют подтверждённый статус без его формата | POST отвечает 201 с готовым `Work`; поля progress/status/job_id нет | Состояние «Создаём» хранить локально; не ждать несуществующее поле status и не добавлять polling |
| D-10 / уточнение | FR-016/017/API-P07 описывают файлы по назначению без точных дескрипторов | `Artifact` содержит url/filename/media_type/audience; `result` и `archive` при ZIP — одни байты по разным URL, `pdf` — preview | Ученик: `result`; просмотр: `pdf`; преподаватель: `answers`, `sources`. Не выбирать файл по имени, не скачивать archive при null |
| D-11 / уточнение | FR-004 запрещает смешивать ответы с условием, но прямо не запрещает их наличие отдельно в выдаче | `Task` не содержит answer/answer_html; `Work` не содержит содержимое ответов; `SourcesManifest` содержит исходные ответы | Не делать скрытый предварительный просмотр; ответы доступны только отдельными материалами готовой работы. Текущие FR-004/015/017 |
| D-12 / уточнение | FR-019/021 требуют понятные ошибки и повтор скачивания без точного формата | Прикладные ошибки — ErrorResponse; только файловый Range допускает транспортные 400/416 text/plain; обрыв после заголовков без JSON, успех sources тоже application/json | Обычный GET без Range: полный 200 в Blob; JSON разбирать только для прикладной ошибки, не для Range 400/416; ошибка GET не вызывает POST |
| D-13 / разделение ответственности | FR-008–010/022 требуют сохранения, удаления, перестановки и связи результата с подборкой | Нет endpoint для черновика/перестановки или экранной истории | Хранить ordered selection и снимок отправленных ID в памяти UI; новые API-операции не нужны |
| D-14 / уточнение | Сохранение оригиналов может быть прочитано как единый снимок между поиском и экспортом | `/tasks` и resource URL не являются снимком; экспорт заново получает задачи по ID | Не обещать неизменность внешнего банка; проверять совпадение на контролируемом источнике, не изменять уже созданные файлы при скачивании |

Обязательное имя не было требованием исходного UI: автоматическое имя уже предлагалось.
Отличие D-05 относится к уникальности и обработке конфликта, а не к снятию несуществующего
обязательного поля. Один длительный запрос и точные схемы — техническая конкретизация
исходного сценария, не основание добавлять экран фоновых заданий.

## Повторная сверка A-07–08

**A-07 принят.** В общем описании контракта 1.0.0 и POST `/api/v1/works` закреплено прямое обслуживание
без 307/308 или другого redirect. UI использует точный путь и `redirect: "error"`.
POST `/api/v1/works/` даёт JSON 404 `not_found`, без Location и без запуска экспорта.
Навязанный redirect не приводит ко второму POST; потеря подтверждения остаётся unknown.

**A-08 принят.** Общая политика явно ограничена прикладными ошибками; исключения
документированы также в responses файлового GET:

| Случай | Ответ и действие UI |
| --- | --- |
| Обычное получение материала | GET без Range, полный 200; успешное тело целиком в Blob |
| Один применимый Range прямого просмотра | 206 с Content-Range; обслуживает PDF-просмотрщик браузера |
| Несколько диапазонов | Multipart 206 с Content-Range частей, без общего Content-Range |
| Некорректный Range | Транспортный 400 text/plain; charset=utf-8, без ErrorResponse |
| Недостижимый Range | 416 text/plain; charset=utf-8, пустое тело, Content-Range bytes */N |
| Ошибка разрешения работы/артефакта, в том числе плохой Range для отсутствующего файла | Прикладной JSON ErrorResponse до FileResponse; отсутствие файла — JSON 404 |
| Неверный JSON POST | JSON 400 ErrorResponse; файловые исключения к POST не применяются |
| Обрыв после начала передачи | JSON не обещается; неполный файл не предлагается, явный повтор только GET |

Несовпавший If-Range или более 100 диапазонов допускают полный 200 согласно контракту.
Baseline FastAPI 0.162.0 / Starlette 1.10.0 зафиксирован в YAML и agreements;
описанная там диагностика зависимости выполнена командой API и здесь не объявляется
новым запуском UI или тестом приложения. При неожиданном Range-ответе в обычном
скачивании UI показывает ошибку передачи/протокола, не сохраняет часть как полный файл
и не пытается разобрать текстовые 400/416 как JSON.

## Браузерная граница скачивания

UI может обнаружить HTTP-отказ и обрыв GET до полного получения тела. После получения
Blob он предлагает сохранить файл с `Artifact.filename`; имя отображаемой работы
не используется для построения серверного пути. Ни Blob, ни обычная ссылка не дают
подтверждения сохранения на диск пользователя. Статус — «Файл получен, доступен
для сохранения», а не «Сохранён на диск». Содержимое sources не вставляется в карточки.

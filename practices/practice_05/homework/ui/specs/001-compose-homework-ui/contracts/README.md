# Потребление единственного контракта UI/API

**Дата**: 2026-10-27. Документ взаимодействия, не независимый контракт HTTP.
Единственный нормативный файл форматов/маршрутов:
[api-v1.yaml](../../../../contracts/api-v1.yaml), версия `1.0.0`, статус `agreed`.
Контракт и A-01–08 согласованы UI/API и приняты пользователем.
Изменения выполняет API после согласования; YAML сюда не копируется.

План и клиентская модель: [plan](../plan.md), [data-model](../data-model.md).
Различия исходной спецификации и вопросы API: [contract-review](../contract-review.md).

## Статическая граница

Предложение UI совпадает с планом API: `ui/index.html` → `/`, `ui/assets/` → `/assets/`.
HTML подключает CSS и `app.js` с type=module; остальные модули загружаются из assets.
Не публиковать весь ui: `.specify`, `.opencode`, `specs` и tests — служебные документы.
API `/api/v1` не должен попадать в HTML fallback. Отдельный dev-сервер, CORS proxy
и открытие через file:// не используются. Эта граница согласована (API-Q04 закрыт),
новых OpenAPI-операций не требуется.

## Таблица операций

| Действие UI | Операция контракта 1.0.0 | Данные и ожидаемый исход |
| --- | --- | --- |
| Выбор номера | GET `/api/v1/categories` | ege_number; 200 CategoryResult с актуальными категориями |
| Явный поиск / листание | GET `/api/v1/tasks` | ege_number, offset, limit=10; необязательная одна category_ids; 200 SearchResult |
| Рисунок / приложение условия | Готовые Task delivery URL на `/api/v1/tasks/{topic_id}/resources/{kind}` | URL из statement_html/images/attachments; image как внешний img, attachment как исходный файл |
| Создать работу | POST `/api/v1/works` | application/json, только topic_ids в пользовательском порядке; 201 Work после полного экспорта |
| Метаданные известной работы | GET `/api/v1/works/{work_id}` | Явное чтение известного ID; 200 Work, не polling и не поиск потерянного результата |
| Получить материал | Готовый Artifact.url на `/api/v1/works/{work_id}/files/{kind}` | 200 сохранённые байты; GET не вызывает экспорт |

Запрос API адресуется относительно текущего origin. Выданные delivery/download URL
абсолютны и same-origin согласно контракту; использовать их как есть. Проверка origin
относится к адресам доставки, а не к source_url/listing_url на сайте происхождения.
Не выводить файловые пути и не реконструировать URL ресурса из URL источника.

## Категории и пагинация

- Выбор «19–21» отправляет ege_number=19; в карточке показывать всю группу.
- «Все категории» — параметр category_ids отсутствует, не пустой список/строка.
- Одна категория — один ключ category_ids с положительным целым ID.
- Массивы кодируются повтором ключа, не JSON/строкой через запятую. UI первой версии
  не добавляет множественный выбор, contains, exclude_ids или произвольный page_size.
- Предыдущая страница — локальная история offset; следующая — ровно next_offset.
  null проверяется явно: нулевое смещение допустимо и не должно трактоваться как false.
- История меняется только после успеха навигации; фильтр/новый поиск сбрасывает её.
  Ошибочный поиск не очищает подборку и не считается пустой страницей.

## Показ условий

Использовать `statement_html`, а не строить условие из текстовой строки.
Сервер API отвечает за allowlist и переписывание src/href на delivery URL;
браузерный DOM не должен получать исполняемый код или inline SVG.
Обычные элементы UI/сообщения создаются как текст.
Сохранить таблицы, индексы, списки, рисунки, ссылки и классы `lmar/in` согласно плану API.
UI не делает второй парсер банка и не переписывает условия для экспорта.
Признак приложений вычислять из Task.attachments; не путать их URL с именами
в Work.attachments. Сбой изображения — отдельное неполное отображение, не пустая выдача.
Изображения можно повторно загрузить тем же GET; POST создания этим не затрагивается.

## Создание и классификация ответа

- До отправки проверить подборку, выставить pending и сохранить копию ID.
- Отправить один POST `{topic_ids}`; name отсутствует, output_path/HTML/answers не передаются.
- Использовать точный `/api/v1/works` без завершающего слеша и `redirect: "error"`.
  API обслуживает его напрямую, без redirect/307/308. POST `/api/v1/works/` даёт
  JSON 404 not_found без Location и вызова экспорта. Нет retry-обёртки, таймера
  отмены экспорта или общего AbortController с поиском (A-07).
- Валидный 201 с согласованным Work — succeeded; публикация материалов завершена.
- Документированный неуспешный HTTP-статус с валидным ErrorResponse — failed.
- Сетевой обрыв, недочитанный/неразбираемый ответ или неподтверждённая форма ответа —
  unknown; не объявлять отсутствие работы и не повторять запрос автоматически.
- При всех трёх исходах завершить ожидание и снять блокировки, сохранив подборку.
  В unknown доступны её изменения и известные материалы, а для нового POST — только
  «Создать новую работу» рядом с «Предыдущая работа могла быть создана».
- Ошибка источника 504/source_timeout, реально полученная как ErrorResponse,
  отличается от отсутствия ответа из-за потери связи. Это не общий deadline экспорта.

## Назначение и получение файлов

| Дескриптор Work | Назначение UI | Правило |
| --- | --- | --- |
| result | «Получить для ученика (PDF/ZIP)» | Главный материал; media_type определяет подпись, audience=student |
| pdf | «PDF для просмотра» при ZIP | Preview, не полный комплект с приложениями; исходный URL inline |
| archive | Дополнительный дескриптор ZIP | Может быть null; отдельная основная кнопка не нужна, result уже указывает ZIP |
| answers | «Получить ответы — для преподавателя» | Отдельный UTF-8 текст готовой работы, не предварительный просмотр |
| sources | «Получить источники — для преподавателя» | Отдельный JSON исходного экспортёра; включает ответы и не вставляется в ученическую карточку |

Под «Получить» понимается GET с показом loading и ошибки в UI, после успеха —
«Сохранить файл» с настоящим filename. Подпись главной кнопки может сохранять
формулировку спецификации «Скачать для ученика»; этапы получения/сохранения явно различаются.

Для готового материала статус проверяется до разбора тела. Прикладной HTTP-отказ
прочитать как ErrorResponse; полное успешное тело 200 — Blob, включая JSON источников.
Обрыв после заголовков может не иметь JSON: показать ошибку передачи и явный повтор GET,
не предлагать частичный файл. Не превращать sources или ответы в состояние ошибки
из-за их MIME; сверять с ожидаемым Artifact.media_type.
Основной Fetch GET UI не посылает Range/If-Range и ожидает полный 200.
Прямой PDF-просмотр поддерживается без принудительной загрузки всего PDF через Blob.
Транспорт FileResponse FastAPI 0.162.0 / Starlette 1.10.0 (A-08) допускает:

- 206 одного диапазона — MIME файла и Content-Range;
- 206 нескольких диапазонов — multipart/byteranges, Content-Range в каждой части,
  без общего Content-Range;
- 400 при некорректном Range — text/plain; charset=utf-8, без ErrorResponse;
- 416 при недостижимом диапазоне — text/plain; charset=utf-8, пустое тело,
  Content-Range bytes */N;
- несовпавший If-Range либо более 100 диапазонов — полный 200.

Исключения 400/416 действуют только внутри файлового ответа после разрешения готового
артефакта. Ошибки work_id/kind и отсутствующего файла возвращаются до FileResponse
как JSON, даже с плохим Range; неверный JSON POST также даёт JSON 400.
Не классифицировать любой HTTP 400 как JSON invalid_request без контекста операции.
При неожиданном 206/транспортном 400/416 в обычном скачивании не публиковать частичный
Blob и не разбирать текст как JSON: показать ошибку получения, разрешить явный GET
без Range. Это не новое создание и не состояние unknown известной работы.

Object URL нужен только после полного получения; имя берётся из Artifact.filename,
а не Work.name. После замены Blob освобождать старый URL; не обещать UI подтверждение
записи на диск. Дополнительный inline PDF может открываться по выданному URL в отдельной
вкладке; его навигация не доказывает успешное скачивание и не запускает POST.

## Отказы и сообщения

| Полученный исход | Реакция UI |
| --- | --- |
| 422 validation_error | Показать message и поля; поиск не считать пустым, подборку сохранить |
| Прикладной JSON 400/405/415 invalid_request | Показать понятную ошибку запроса; без автоматической повторной отправки |
| Файловый Range 400/416 text/plain | Транспортное исключение A-08, не ErrorResponse; обработка прямым просмотрщиком либо ошибка получения без попытки JSON-разбора |
| JSON 404 на POST /api/v1/works/ | Подтверждённый отказ неверного маршрута, без redirect, Location и экспорта |
| 502 source_error / 504 source_timeout | Показать отказ источника; предложить явный повтор соответствующей операции |
| 409 output_conflict | Конфликт выходных материалов, не запрет одинакового имени |
| 500 export_failed / internal_error | При корректном ErrorResponse — подтверждённая ошибка; частичного успеха нет |
| 404 not_found для известного файла | Файл отсутствует/удалён; другие материалы доступны, новый экспорт не запускается |
| Обрыв POST до подтверждения | unknown + предупреждение + явное новое создание; без восстановления неизвестного ID |
| Обрыв GET файла | Ошибка передачи + явный повтор GET; известная работа не становится unknown |

Сообщения/fields выводятся как текст, не HTML. Не парсить код из текста исключения.
Не показывать response body произвольного прокси как сообщение и не выдавать его за
подтверждённый отказ создания. Работа и подборка переживают ошибку отдельного скачивания.

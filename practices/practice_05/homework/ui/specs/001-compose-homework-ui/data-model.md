# Модель состояния UI

**Дата**: 2026-10-27. Клиентская модель проектирования, не схема нового API.
Типы HTTP-объектов определяет только согласованный
[api-v1.yaml](../../../contracts/api-v1.yaml) версии 1.0.0 со статусом agreed.
Связанные документы: [plan](plan.md), [взаимодействие](contracts/README.md).

## 1. FilterState и поколения GET

| Поле | Значение и инвариант |
| --- | --- |
| selectedEge | null до выбора; далее 1–18, 19 для общей группы 19–21, 22–27 |
| selectedCategory | null означает все; иначе положительный ID из загруженных категорий текущего номера |
| categories | `Category[]` из CategoryResult; принадлежит текущему номеру |
| generation | Монотонно растёт при смене фильтра и начале нового поиска; связывает результаты с актуальным состоянием |
| categoriesState | idle/loading/ready/error; собственная ошибка и GET-контроллер |
| searchState | idle/loading/ready/empty/error; собственная ошибка и GET-контроллер |

Смена номера сбрасывает категорию; смена номера/категории очищает текущую выдачу
и историю страниц, но не selection и exportState. Новый явный поиск начинает с offset 0.
Контроллеры GET не связаны с POST. Результат/ошибка/finally старого поколения игнорируются.
Смена категории не должна инвалидировать уже загруженный список категорий того же номера:
категории дополнительно привязаны к выбранному номеру и своему поколению запроса.

## 2. SearchPage и история смещений

| Поле | Значение и инвариант |
| --- | --- |
| page | `SearchResult`: tasks, total, offset, limit, next_offset, номера и source_url |
| limit | В UI постоянно 10; контракт допускает 1–30 |
| previousOffsets | Стек успешно посещённых смещений для того же фильтра |
| pendingNavigation | Запрошенное направление и offset; не изменяет стек до успеха |
| taskResources | Для актуальных карточек: состояние загрузки каждого img и сводный pending/ready/error |

«Следующие»: использовать отличный от null `next_offset`, после успеха добавить прежний offset
в стек. «Предыдущие»: взять вершину, удалить её только после успеха; последующие переходы
снова следуют ответу сервера. Ошибка не портит историю, кнопка повтора сохраняет целевой
offset. Конец — только `next_offset=null`; не выводить его из длины страницы.
Пустая страница при total>0 возможна после изменения внешнего банка; показать отсутствие
задач на этой странице и дать вернуться/начать поиск сначала, не менять подборку.

Карточка — Task из контракта: id, ege_numbers, statement/statement_html, images,
attachments и URL происхождения. Ответов нет. Признак приложений — длина attachments.
До загрузки всех рисунков добавление недоступно; ошибка img помечает неполное отображение
и предлагает повтор ресурса. Нулевое число рисунков сразу означает готовность карточки.
Ошибка img не содержит доступного UI ErrorResponse: текст общий, без выдуманного HTTP-кода.

## 3. Selection — черновик преподавателя

| Поле | Значение и инвариант |
| --- | --- |
| orderedIds | Упорядоченный массив уникальных положительных ID, длина 0–100 |
| tasksById | Map выбранных Task; содержит каждый ID из orderedIds, не зависит от текущей выдачи |
| revision | Изменяется только при добавлении, удалении или реальном перемещении |

Добавление нового ID — в конец; дубль ничего не меняет. Удаление убирает ID и его
данные; повторное добавление — в конец. «Вверх/Вниз» меняют только соседние позиции.
Номер пункта вычисляется из индекса + 1, а не из номера ЕГЭ или ID.
Блок с `ege_numbers=[19,20,21]` — один элемент. Число пунктов — длина orderedIds.
Операции запрещены только при exportState=pending и на соответствующих границах.
Поиск, ошибки, загрузка файлов и неизвестный исход selection не очищают.

## 4. ExportAttempt и известная работа

| Поле | Значение и инвариант |
| --- | --- |
| phase | idle/pending/succeeded/failed/unknown; это состояние UI, не поле HTTP Work |
| submittedIds | Копия orderedIds на момент начала POST, без дальнейших изменений |
| submittedRevision | Ревизия для отображения происхождения результата |
| error | Только подтверждённый ErrorResponse для failed либо сообщение о потере подтверждения для unknown |
| knownWork | Последний валидный Work: work_id, name, created_at, topic_ids, count, attachments и дескрипторы |

Перед принятием Work проверить: совпадение topic_ids с отправленными в точном порядке,
count с длиной массива, готовые same-origin URL, аудитории материалов, согласованность
PDF/ZIP и archive. Состав Work не содержит HTML условий или текста ответов.
Work.attachments — имена экспортированных файлов, не Task.attachments с URL ресурса.
Во время новой попытки knownWork не очищается; это один известный результат,
а не клиентский каталог истории или поиск неизвестной работы.
При изменении selection сравнивать текущий orderedIds со снимком Work.topic_ids;
если они различаются, показывать «Для предыдущей подборки». Серверное имя не ключ.

### Переходы создания

| Исходное состояние / событие | Новое состояние | Действия |
| --- | --- | --- |
| idle/succeeded/failed + допустимое явное создание | pending | Снимок ID, блокировка до первого await, один POST без имени/пути |
| pending + валидный 201 Work | succeeded | Сохранить известный Work, снять блокировки, показать материалы |
| pending + документированный HTTP-отказ с валидным ErrorResponse | failed | Показать причину/поля, снять блокировки; явный повтор обычного создания |
| pending + сетевой обрыв, ошибка чтения/разбора или неподтверждённый ответ | unknown | Сохранить подборку и предыдущий известный Work, снять блокировки, показать два обязательных сообщения |
| unknown + редактирование/поиск/GET известных файлов | unknown | Обычные действия разрешены; предупреждение о прежнем создании остаётся |
| unknown + «Создать новую работу» при 1–100 ID | pending | Новый снимок текущих ID, один новый POST, без обещания отсутствия дубля |

Каждый POST идёт на точный `/api/v1/works` с `redirect: "error"` (A-07).
API не перенаправляет; вариант со слешем даёт JSON 404 без экспорта и Location.
Навязанное перенаправление не вызывает повтор POST; без подтверждённого результата
ожидание завершается как unknown, а не как автоматическая новая попытка.

В unknown показываются «Результат не подтверждён» и «Предыдущая работа могла быть создана».
Нет автоматического перехода по восстановлению сети, polling, угадывания ID или поиска
по имени. Если ID прежнего результата не получен, ссылки на него не создаются.
Если достоверный ID уже известен, чтение его метаданных допустимо явным GET,
не является восстановлением неизвестной работы и не превращается в опрос прогресса.
Перезагрузка страницы может потерять черновик/ID; серверные файлы от этого не удаляются.

## 5. Artifact, DownloadState и Blob

Artifact приходит из Work: url, filename, media_type, audience.
Поля result/pdf/answers/sources обязательны, archive может быть null.

- result — student; pdf — preview; answers/sources — teacher; archive — student или null.
- В отсутствие приложений result PDF и archive=null; при приложениях result ZIP.
- Приложения ученику выдаются в ZIP, не через список файлов из Work.attachments.
- URL сохраняется как выдан API, не строится из filename или work_id вручную.

Состояние каждого скачивания: idle → loading → ready либо error.
Обычный Fetch GET не посылает Range/If-Range и принимает полный файл с 200.
Проверка статуса и чтение тела входят в loading; после полного Blob — ready,
ссылка «Сохранить файл». Ошибка чтения не выдаёт частичный Blob за файл.
Успех sources с JSON MIME не является ошибкой; ответ ошибки определяется HTTP-статусом.
Повтор ошибки — отдельный явный GET того же Artifact, никогда POST.

Один глобальный readyBlob: artifact URL, filename, object URL.
При успешном получении другого файла прежний object URL освобождается, его локальное
состояние возвращается в idle; исходная серверная ссылка остаётся доступной.
Во время передачи предыдущий Blob не освобождать до замены; при освобождении нельзя
оставлять в DOM рабочую на вид ссылку. Не отзывать URL сразу после первого клика.
Факт получения файла не означает сохранение на диск пользователем.

## 6. Граница хранения и ошибок

API хранит готовые файлы и метаданные до ручной очистки, включая перезапуск.
При том же origin известные ссылки не меняются. После очистки материал может дать
404, не отменяя другие материалы. UI не вводит auto-export, экран истории или API удаления.
Прикладные ошибки выводятся текстом через ErrorResponse.error.message/fields; code определяет
категорию поведения, но не парсится из текста. HTML, traceback и локальные пути
вместо ошибки не отображаются. Неподтверждённый POST всегда остаётся unknown.

Единственные файловые транспортные исключения из JSON-политики (A-08) — некорректный
Range: 400 text/plain, и недостижимый Range: 416 text/plain с пустым телом и
Content-Range bytes */N. Они возникают после разрешения готового артефакта;
отсутствующий файл/неверный kind/work_id даёт прикладной JSON до FileResponse.
Одиночный 206 и multipart 206 обслуживает прямой PDF-просмотрщик. Неожиданные
206/транспортные 400/416 в обычном скачивании дают error без частичного Blob и без
попытки JSON-разбора текста. Повтор — только явный GET; knownWork не становится unknown.

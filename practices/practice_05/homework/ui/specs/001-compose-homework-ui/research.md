# Research: минимальный браузерный UI

**Дата**: 2026-10-27. Исследование документов и браузерного поведения;
приложение, поиск, экспорт и браузерные тесты не запускались.

Основания: [spec](spec.md), [общий контракт 1.0.0/agreed](../../../contracts/api-v1.yaml),
[соглашения](../../../evidence/agreements.md),
[план API](../../../api/specs/001-task-bank-http/plan.md),
[сверка исходных требований](contract-review.md).

## R-01. Статическая поставка и технологии

- **Decision**: HTML5/CSS/native JavaScript ES modules, без framework, сборки и CDN.
  `ui/index.html` на `/`, `ui/assets/` на `/assets/`; API того же origin на `/api/v1`.
- **Rationale**: прямое требование пользователя, совпадает с границей статики плана API.
  При смене порта запросы API используют текущий origin, не жёсткий 8000 в JavaScript.
- **Alternatives considered**: отдельный dev-сервер добавляет CORS и процесс;
  framework/bundler не требуются для одной страницы и не соответствуют запросу.

## R-02. Условия, рисунки и приложения

- **Decision**: API предоставляет нормализованную браузерную копию `statement_html`
  с allowlist и готовыми same-origin delivery URL. Использовать её для условия,
  `images/attachments` — для статусов ресурсов и признака приложений. Остальные
  строки интерфейса вставлять как текст. SVG — только внешний img.
- **Rationale**: `statement` теряет таблицы/индексы; исходные URL происхождения
  не являются адресами доставки и не требуют реконструировать proxy в UI.
  Allowlist — обязанность API, явно описанная его планом; DOMParser сам не санитайзер.
  CSS поддерживает таблицы и классы `lmar/in`, не меняя содержание.
- **Alternatives considered**: отображать только plain text — потеря условий;
  inline SVG/исполняемый HTML — против контракта; новый клиентский парсер банка
  дублировал бы предметную логику. Ответственность и форматы подтверждены, API-Q01 закрыт.

## R-03. Поиск, порядок и конкурентность

- **Decision**: поиск только явной кнопкой. Поколение фильтра менять сразу при его
  изменении; отдельные контроллеры отмены только GET. Проверять поколение после чтения
  ответа и при ошибке/finally. Подборка — ordered array ID и Map данных выбранных задач.
  Предыдущие offset хранятся на клиенте, без обратного endpoint и без серверного черновика.
- **Rationale**: отмена не исключает поздний ответ; debounce не нужен для явной кнопки.
  Собственная подборка не зависит от текущей страницы и не теряет порядок из-за поиска.
- **Alternatives considered**: общий AbortController с экспортом отменял бы ожидание POST;
  хранить только текущую выдачу — терять выбранное; исключать выбранные ID из поиска —
  менять total/смещения при каждом добавлении без пользовательского изменения фильтра.

## R-04. Длительный POST и неизвестный исход

- **Decision**: один Fetch POST с JSON `{topic_ids}`, без `name` и без retry/poll/cancel;
  установить pending до отправки, `redirect: error`. Ответ 201 читать как JSON Work,
  не как файл. Документированная ошибка с корректным ErrorResponse — подтверждённый отказ.
  Сбой передачи/разбора успешного ответа — неизвестный результат, а не отсутствие работы.
- **Rationale**: каждый POST создаёт отдельную работу. Нельзя вычислить её ID по имени
  или URL, нельзя повторять после восстановления сети. Не вводится общий короткий
  таймер «45 секунд»: timeout источника относится к отдельным операциям API.
- **Alternatives considered**: job/polling, идемпотентность и восстановление без ID
  отвергнуты A-01–02; автоматический retry может незаметно создать дубль.
  Перенаправление 307/308 способно переотправить тело, поэтому UI запрещает redirect.
  A-07 и контракт 1.0.0 закрепили прямой `/api/v1/works`, а вариант со слешем — JSON 404
  без Location и запуска экспорта. API-Q03 закрыт, UI это решение принял.

## R-05. Скачивание с ошибкой в UI

- **Decision**: отдельный GET по Artifact.url без Range, сначала статус, затем полное
  тело 200 как Blob. Создать object URL и явную ссылку «Сохранить файл» с
  `download=Artifact.filename`; HTTP-ошибку показать в UI, обрыв чтения не публикует Blob.
  По одному активному запросу на материал, без авто-retry. При повторной сетевой
  попытке получить материал снова через GET; сохранённый Blob можно сохранить повторно.
- **Rationale**: обычная ссылка экономит промежуточное хранение, но не позволяет надёжно
  показать JSON-ошибку или обрыв внутри UI. Успешный sources тоже application/json,
  поэтому тип содержимого не отличает ошибку от преподавательского файла — нужен статус.
  Серверное имя файла уже есть в контракте, разбирать filename* ради основного сценария
  не требуется. `Work.name` не подставляется в серверный путь или имя скачивания.
- **Alternatives considered**: навигация прямо по URL годится для дополнительного
  inline PDF-просмотра; для основного скачивания не выполняет требование диагностики.
  File System Access/streams добавляют непереносимый API и разрешения, не нужны первой версии.
- **Browser limits**: Blob накапливает весь файл во внутреннем хранилище браузера;
  размер файлов контрактом не ограничен, отсутствие затрат памяти не обещается.
  Держать не более одного готового Blob в UI; при получении другого освобождать прежний
  object URL. После долгого запроса отдельное нажатие сохранения сохраняет пользовательскую
  активацию. Завершение Blob не подтверждает сохранение на диск, отмену диалога или ошибку диска.

## R-07. Узкие транспортные исключения Range

- **Decision**: A-08 принят и закреплён контрактом 1.0.0. Прикладные ошибки остаются JSON
  ErrorResponse; исключены только Range-ответы после разрешения готового артефакта
  в FileResponse baseline FastAPI 0.162.0 / Starlette 1.10.0. Неверный Range — 400
  text/plain; недостижимый — 416 text/plain с пустым телом и Content-Range bytes */N.
  Прямой PDF-просмотр поддерживает одиночный 206 и multipart 206 с заголовками частей.
- **Rationale**: обычный Fetch GET UI не отправляет Range/If-Range и ожидает полный 200,
  а транспорт прямого просмотра не должен навязывать JSON-разбор текстовых ответов.
  JSON 404 отсутствующего файла выдаётся до FileResponse даже при плохом Range;
  JSON 400 неверного POST не относится к файловым исключениям.
- **Alternatives considered**: преобразовывать все Range-ошибки в JSON противоречит
  принятому baseline; трактовать все 400 как text/plain ломает прикладные ошибки.
  При неожиданном частичном/транспортном ответе в обычном GET — ошибка получения
  без публикации частичного Blob, явный повтор только GET без нового экспорта.
- **Evidence**: основания — обновлённые YAML и agreements. Диагностика библиотеки
  описана командой API в A-08; UI её не запускал и не выдаёт за проверку приложения.

## R-06. Серверное хранение и назначение материалов

- **Decision**: черновик и известный текущий/предыдущий результат — в памяти страницы;
  сервер сохраняет готовые материалы до ручной очистки. `result` всегда ученический,
  `pdf` preview, `answers/sources` teacher; содержимое ответов не загружается заранее.
- **Rationale**: долговечность серверных файлов не требует экрана истории или localStorage.
  Ошибка одного GET не очищает Work или подборку и не вызывает новый POST.
- **Alternatives considered**: восстанавливать по имени, сканировать каталог или строить
  историю невозможно по контракту и не нужно по требованиям.

## Проверенные браузерные основания

Отдельный исследовательский агент изучил Fetch, Blob, DOMParser, SVG-as-image и гонки;
его выводы применены с учётом формы контракта: POST возвращает JSON Work,
только последующие GET возвращают файлы. Предложенный в исследовании debounce
не применяется к явному поиску. Это анализ документации, не эксперимент в браузере.

- [Ссылки download](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a#download)
- [Жизненный цикл Blob URL](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/blob#memory_management)
- [DOMParser и границы безопасности](https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString#security_considerations)

UI не редактирует общий YAML. Обновление версии и статусов не меняет выбранное поведение.

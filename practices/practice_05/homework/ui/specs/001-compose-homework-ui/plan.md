## Summary

Одна русскоязычная страница: фильтры номера/категории, выдача оригинальных условий,
упорядоченная подборка, создание и раздельное получение готовых материалов.
HTML, CSS и JavaScript с браузерными ES-модулями, без frontend-фреймворка и сборки.
Файлы принадлежат проекту `ui/`; сервер API публикует `index.html` на `/`, а `assets/`
на `/assets/` того же origin. API-запросы идут на `/api/v1`; отдельный UI-сервер не нужен.

Условия и URL ресурсов предоставляет API. UI хранит черновик и порядок ID в памяти,
отправляет один длительный POST без имени и пути, затем использует дескрипторы готовой
работы. Основной ученический файл всегда `Work.result`, ответы/источники — отдельно.
Неизвестный исход разблокирует UI, но не вызывает повтор POST.

Проверка достаточности и 14 конкретных отличий от исходного снимка, включая минимальные
решения и вопросы API, находятся в [contract-review.md](contract-review.md).

## Technical Context

**Language/Version**: HTML5, CSS, JavaScript ES2020+; native ES modules, Fetch,
URL/URLSearchParams, Map/Set, Blob/Object URL. Без TypeScript, transpiler и bundler.

**Primary Dependencies**: runtime — только браузерные API. Сервер и готовая браузерная
проекция условий принадлежат API. FastAPI/Uvicorn и исходный Bank/export_pdf UI не дублирует.

**Storage**: клиентская память открытой страницы для фильтров, истории смещений,
подборки и известных результатов. Нет localStorage/IndexedDB, сервис-воркера или истории.
Серверное хранение материалов после перезапуска до ручной очистки обеспечивает API.

**Testing**: Python pytest + Playwright из окружения API: контролируемые ответы для
гонок/ошибок и реальные UI→API→Bank→export сценарии PDF/ZIP. Фактические результаты
реализации — [ui-verification.md](../../../evidence/ui-verification.md);
регрессии MCP зафиксированы стороной API.

**Target Platform**: по изменённым пользователем границам приёмки **A-09 от 2026-10-28** —
Chromium (проверен 153.0.8010.12). Firefox E-01 не прошёл запуск и не блокирует сдачу.
Гарантия отсутствия автоповтора POST относится к JS приложения; транспортный повтор
Chromium B-01 остаётся известным ограничением с непройденной проверкой.
Идемпотентность и «ровно один раз» не гарантируются, код/поля API не меняются.
Итог: [final-status.md](../../../evidence/final-status.md).

**Project Type**: статический клиент локального веб-приложения на одном origin с API.

**Performance Goals**: статус/блокировка после действия и разблокировка по завершении
ожидания — не позднее 1 секунды (SC-005). Размер выдачи 10, максимум контракта 30;
подборка 1–100 пунктов. Общее время экспорта зависит от сети/источника/рендеринга;
фиксированный короткий deadline и прогресс в процентах не вводятся.

**Constraints**: same-origin loopback `http://127.0.0.1:8000` по умолчанию;
порт берётся из текущего origin, delivery/download URL — из ответа API, не из путей диска.
Один ожидающий POST в UI, без redirect/retry/poll/cancel; GET поиска можно отменять
независимо. Оригинальные условия, порядок, неделимый 19–21 и разделение материалов
сохраняются. Blob-скачивание получает весь один файл до предложения сохранить;
это не потоковая запись на диск и не подтверждение успешного сохранения пользователем.
Точный POST `/api/v1/works` обслуживается без redirect; вариант со слешем — JSON 404
без экспорта. Обычный файловый GET не посылает Range и ожидает 200. Range прямого
просмотра PDF допускает 206 и транспортные 400/416 text/plain вне ErrorResponse (A-08).

**Scale/Scope**: один преподаватель, одна страница, одна категория или все,
локальный черновик и одна текущая операция создания; известный предыдущий результат
не очищается ошибкой нового создания. Не вводятся логин, серверный черновик,
история работ, редактирование условий или предварительные ответы.

## Phase 1 — Design

1. **Каркас и отображение.** Семантические form/section/ol/button, русские label,
   текстовые статусы с aria-live; DOM-текст через textContent, условия — только
   серверный `statement_html` согласно allowlist API. Сохранить таблицы/sub/sup,
   `lmar/in`, img, ссылки. SVG не вставлять в DOM как разметку.
2. **Поиск.** Явная кнопка, текущий фильтр и поколение запросов. GET категорий/выдачи
   имеют собственные AbortController; старый ответ, ошибка или finally не меняют новое
   состояние. Категория «Все» не отправляет пустой массив; история offset независима
   от подборки. Пустая страница и ошибка различаются.
3. **Подборка.** Ordered array ID + Map задач; добавление в конец, дедупликация,
   кнопки удаления/соседнего перемещения. При поиске не пересоздавать черновик;
   после перестановки сохранять осмысленный клавиатурный фокус.
4. **Создание.** Проверить 1–100 ID и установить блокировку до первого await;
   зафиксировать отправленный порядок. Один POST `{topic_ids}` получает JSON Work,
   а не PDF/Blob. Только валидный 201 означает успех; корректный ErrorResponse — отказ.
   Сетевой обрыв/неполный ответ — неизвестный исход, снятие блокировок и предупреждение,
   затем явное «Создать новую работу». Точный маршрут и `redirect: "error"` исключают
   повторную отправку через redirect; POST не отменяется контроллером поиска.
5. **Материалы.** Валидация согласованности Work с отправленными ID и аудиториями;
   `result` — основная кнопка, `pdf` — отдельный просмотр при ZIP. GET выбранного
   готового файла через Fetch, успешное тело как Blob, имя из Artifact.filename;
   JSON sources не путать с JSON ошибки. Повтор только явный GET; готовый Blob может
   сохраняться повторно без сети. Не менять серверные файлы и не считать получение
   Blob доказательством сохранения на диск. Прикладные ошибки — JSON; только файловые
   Range 400/416 — текстовые транспортные исключения. Для Blob нужен полный 200 без Range,
   206/400/416 прямого просмотра не разбирать безусловно как JSON и не сохранять как полный файл.
6. **Проверки и интеграция.** Контролируемые браузерные проверки переходов, гонок,
   ресурсов и ошибок; затем реальный сквозной PDF и ZIP, перезапуск API и удалённый
   материал. Команда API отдельно проверяет MCP и регрессии общего механизма.

Модель и переходы: [data-model.md](data-model.md). HTTP-привязки без второго контракта:
[contracts/README.md](contracts/README.md). Руководство будущей проверки:
[quickstart.md](quickstart.md). Декомпозиция в tasks.md — отдельный следующий этап.

## Complexity Tracking

Исключений из конституции нет. Дополнительные механизмы ограничены поколениями GET,
снимком отправленных ID, состоянием неизвестного результата и Blob-скачиванием,
необходимыми для явных требований. Framework, БД, очередь, серверные черновики,
генерация PDF в браузере и второй контракт не требуются.

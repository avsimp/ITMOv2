# Feature Specification: UI локального приложения для составления домашних работ

**Feature Branch**: `practice_05` (текущая ветка, без переключения)

**Feature Directory**: `specs/001-compose-homework-ui`

**Created**: 2026-10-27

**Status**: Draft — исходные требования UI; предложения к API ещё не согласованы

**Input**: User description: «Локальное приложение преподавателя: выбор номера ЕГЭ
и категории, поиск оригинальных задач, подборка без дублей с кнопками изменения порядка,
создание работы, скачивание ученического PDF либо ZIP и отдельно ответов и источников».

## User Scenarios & Testing *(mandatory)*

Сценарии ниже — критерии будущей приёмки, а не результаты выполненных проверок.

### User Story 1 - Найти и изучить оригинальные задачи (Priority: P1)

Преподаватель выбирает номер задания ЕГЭ, при необходимости категорию и запускает поиск.
Он видит полные условия, рисунки, таблицы и признак наличия приложений, чтобы выбирать
задачи по содержанию, а не по краткому пересказу.

**Why this priority**: Без просмотра оригинала преподаватель не может оценить пригодность задачи.

**Independent Test**: Выбрать номер и категорию, выполнить поиск и просмотреть результаты,
включая задачу с рисунком и задачу с приложением; подборку создавать не требуется.

**Acceptance Scenarios**:

1. **Given** номер не выбран, **When** открыто приложение, **Then** показано приглашение
   выбрать номер, а поиск недоступен; это не состояние «ничего не найдено».
2. **Given** выбран номер, **When** категории загружены, **Then** можно выбрать одну
   категорию либо «Все категории»; поиск работает без обязательного выбора категории.
3. **Given** задан фильтр, **When** запущен поиск, **Then** виден статус загрузки;
   после успеха показаны оригинальные условия с рисунками и таблицами, ID источника,
   номер ЕГЭ и явная отметка «Есть приложения» либо «Без приложений».
4. **Given** есть следующие результаты, **When** нажата кнопка «Следующие», **Then**
   показана следующая порция для того же фильтра; в конце списка кнопка недоступна.
5. **Given** поиск успешно завершён без совпадений, **When** отображён результат,
   **Then** показано «Ничего не найдено» и предложение изменить фильтры.
6. **Given** недоступен источник или локальный сервис, **When** поиск завершается ошибкой,
   **Then** показаны понятное сообщение и «Повторить»; ошибка не выглядит как пустая выдача.
7. **Given** изменён номер, **When** обновляется список категорий, **Then** старая категория
   сброшена; запоздалый ответ предыдущего поиска не заменяет выдачу нового фильтра.

### User Story 2 - Собрать и упорядочить домашнюю работу (Priority: P1)

Преподаватель добавляет задачи из разных результатов поиска, удаляет лишние и меняет
порядок кнопками «Вверх» и «Вниз», не теряя уже выбранные задачи.

**Why this priority**: Подборка и её порядок определяют содержание будущей работы.

**Independent Test**: На заранее доступных результатах добавить три задачи, повторно
попытаться добавить одну из них, поменять порядок и удалить пункт; экспорт не требуется.

**Acceptance Scenarios**:

1. **Given** задача ещё не выбрана, **When** нажато «Добавить», **Then** она появляется
   в конце подборки, счётчик увеличивается на один, а карточка помечается «В подборке».
2. **Given** задача уже выбрана, **When** она снова встречается в выдаче или нажата
   повторно, **Then** второй экземпляр не создаётся; сравнение выполняется по ID источника.
3. **Given** в подборке есть задачи, **When** преподаватель листает выдачу, меняет номер
   или категорию, получает пустой результат либо ошибку поиска, **Then** состав и порядок
   подборки сохраняются; после удаления задача снова доступна для добавления.
4. **Given** подборка A, B, C, **When** у C нажато «Вверх», затем удалена A,
   **Then** остаются C, B с непрерывной нумерацией 1, 2; «Вверх» у первой и «Вниз»
   у последней недоступны. Повторное добавление A помещает её в конец.
5. **Given** найден блок 19–21, **When** он добавлен или перемещён, **Then** общая игра
   и три вопроса остаются одним пунктом, одним ID и одной единицей счётчика.
6. **Given** выбрано 100 пунктов, **When** пользователь хочет добавить ещё один,
   **Then** добавление недоступно и объяснён предел; текущая подборка не изменяется.

### User Story 3 - Создать и получить материалы работы (Priority: P1)

Преподаватель создаёт работу из текущей подборки и получает явно разделённые
ученические материалы, ответы и источники, не выполняя действия в командной строке.

**Why this priority**: Готовые материалы — конечный результат составления домашней работы.

**Independent Test**: Для заранее подготовленной подборки выполнить создание и скачивание;
отдельно повторить с приложением и с ошибкой экспорта, без проверки поиска.

**Acceptance Scenarios**:

1. **Given** подборка пуста, **When** отображена область создания работы, **Then**
   «Создать работу» недоступно и показана причина «Добавьте хотя бы одну задачу».
2. **Given** есть от 1 до 100 пунктов, **When** нажато «Создать работу», **Then** виден
   статус «Создаём работу», повторное создание и изменение состава/порядка недоступны
   до завершения; быстрые повторные нажатия не создают дополнительные работы.
3. **Given** в подборке нет приложений, **When** создание успешно завершено, **Then**
   показано «Работа создана», число пунктов и «Скачать для ученика (PDF)»;
   отдельно доступны «Скачать ответы» и «Скачать источники».
4. **Given** хотя бы у одного пункта есть приложение, **When** создание успешно,
   **Then** основной результат — «Скачать для ученика (ZIP)» с PDF и приложениями;
   рядом объяснено, что архив нужно распаковать целиком. Ответы и источники находятся
   вне ученического ZIP. Отдельный PDF доступен как «PDF для просмотра».
5. **Given** подборка включает обычную задачу и блок 19–21, **When** получены материалы,
   **Then** в PDF, ответах и источниках совпадает выбранный порядок; блок занимает
   один пункт с тремя вопросами. Условия не пересказаны и не сокращены.
6. **Given** создание завершилось ошибкой, **When** показано сообщение, **Then** нет
   ложного успеха и ссылок на незавершённый результат; подборка сохранена, блокировка
   снята, повтор доступен явным действием пользователя после исправления причины.
7. **Given** работа создана, **When** пользователь скачивает файл повторно, **Then**
   скачивается тот же результат без нового экспорта; ошибка скачивания допускает повтор.
8. **Given** работа создана, **When** подборка изменена, **Then** прежние материалы
   явно помечены «Для предыдущей подборки» и не выдаются за результат новой;
   для новой подборки требуется отдельное нажатие «Создать работу».

### Edge Cases

- Ошибка загрузки категорий: показать причину и повтор; поиск заблокирован до успешной
  загрузки категорий текущего номера, но выбранные ранее задачи остаются в подборке.
- Смена фильтра сбрасывает позицию выдачи на первую порцию. Переход «Предыдущие»
  возвращает предыдущую порцию; на первой он недоступен. Размер порции по умолчанию — 10.
- На время поиска его повтор и переходы по выдаче заблокированы; фильтры можно изменить.
  Старая выдача при загрузке, ошибке или смене фильтра не доступна для добавления задач.
- Незагрузившийся рисунок отмечается внутри карточки как неполное отображение с повтором;
  до его успешной загрузки добавление из этой карточки недоступно. Экспорт уже выбранной
  задачи при недоступном ресурсе завершается сообщением об ошибке, без подмены условия.
- Потеря связи во время создания не доказывает, что работа не создана: показать
  «Результат не подтверждён», сохранить подборку и не запускать экспорт автоматически.
  Дальнейшая проверка результата или явный повтор зависят от согласования с API (OQ-02).
- Конфликт имени или отказ записи при экспорте отображается как ошибка с причиной;
  существующие материалы не перезаписываются.
- Ошибка получения одного файла не отменяет уже созданную работу и доступ к другим файлам.
- Блок 19–21, найденный через любой из номеров 19, 20, 21, не добавляется повторно.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: UI обязан позволять выбрать номер ЕГЭ из поддерживаемых 1–27;
  19–21 отображаются одной общей группой с пояснением «один блок — один пункт».
- **FR-002**: После выбора номера UI обязан загрузить актуальные категории, предложить
  «Все категории» по умолчанию и необязательный выбор одной категории.
- **FR-003**: Поиск запускается явной кнопкой; изменение фильтра сбрасывает старую
  категорию при смене номера и позицию выдачи, но не подборку.
- **FR-004**: Результат обязан содержать полное оригинальное условие с рисунками,
  таблицами и ссылками на приложения, ID источника, номер/группу ЕГЭ и признак приложений.
  Ответы не должны смешиваться с условием в карточке.
- **FR-005**: UI обязан поддерживать кнопки «Предыдущие» и «Следующие» и однозначно
  показывать отсутствие следующей порции, не очищая подборку.
- **FR-006**: UI обязан различать начальное состояние, загрузку, успешную пустую выдачу,
  ошибку категорий/поиска и успешную выдачу; для ошибки обязателен явный повтор.
- **FR-007**: Запоздалый ответ для старого фильтра не должен заменять актуальные результаты.
- **FR-008**: «Добавить» обязан добавлять новый ID в конец подборки; выбранный ID отмечается
  «В подборке» и не добавляется повторно, включая повторные нажатия и другие страницы.
- **FR-009**: Подборка обязана сохранять состав, порядок и счётчик при всех действиях
  поиска в пределах открытой страницы, включая пустые результаты и ошибки.
- **FR-010**: Каждый пункт обязан иметь «Удалить», «Вверх», «Вниз»; перемещение выполняется
  на одну позицию, недопустимое движение на границе заблокировано, номера пересчитываются.
- **FR-011**: UI обязан трактовать полный блок 19–21 как один неделимый пункт везде,
  включая счётчик, удаление, перестановку и создание работы.
- **FR-012**: UI обязан поддерживать от 1 до 100 уникальных пунктов для создания;
  при пустой подборке создание недоступно, при 100 пунктах добавление недоступно.
- **FR-013**: Создание обязано использовать только ID в выбранном порядке;
  редактирование или генерация текста условий пользователем не входит в эту фичу.
- **FR-014**: С первого нажатия до подтверждённого завершения создание обязано блокировать
  повторный запуск и все изменения подборки; успех и ошибка снимают блокировку.
- **FR-015**: Подтверждённый успех обязан показывать статус, число пунктов и отдельные
  действия скачивания ученического материала, ответов и источников.
- **FR-016**: Без приложений ученический результат обязан быть PDF; с приложениями — ZIP
  с PDF и файлами. Дополнительный PDF для просмотра при ZIP явно не заменяет комплект.
- **FR-017**: Ответы и источники обязаны скачиваться отдельно с подписями «Для преподавателя»;
  они не включаются в ученические PDF/ZIP. Ответы — текстовый файл, источники — JSON.
- **FR-018**: Созданные материалы обязаны сохранять оригинальные условия, рисунки и порядок,
  используя действующий экспортёр; существующие правила имён приложений сохраняются.
- **FR-019**: Ошибка создания обязана сохранять подборку, объяснять причину и позволять
  явный повтор; неполный или неподтверждённый результат не показывается как успешный.
- **FR-020**: UI обязан отдельно различать подтверждённый отказ и потерю подтверждения
  результата, исключить автоматический повтор создания при потере связи (OQ-02).
- **FR-021**: Скачивание обязано получать уже созданный файл без повторного создания;
  неудача скачивания допускает явный повтор и не очищает подборку или другие результаты.
- **FR-022**: Результат обязан быть связан с составом и порядком на момент создания;
  после изменений подборки прежний результат явно обозначается как предыдущий.
- **FR-023**: Все действия выбора, добавления, удаления, перемещения, создания и скачивания
  обязаны быть доступны кнопками/элементами с понятными русскими подписями и с клавиатуры;
  перетаскивание и командная строка не требуются. Статусы не передаются только цветом.

### Состояния интерфейса

| Область / состояние | Что видит преподаватель | Доступные действия |
| --- | --- | --- |
| Начальное | «Выберите номер ЕГЭ», пустая подборка | Выбрать номер; поиск/создание недоступны |
| Загрузка категорий | «Загружаем категории» | Сменить номер; подборка сохранена |
| Загрузка выдачи | «Ищем задачи» | Изменить фильтр; повтор поиска и листание недоступны |
| Выдача готова | Полные карточки, признаки приложений | Добавить, листать, изменить фильтр |
| Пустая выдача | «Ничего не найдено» | Изменить фильтр, повторить поиск |
| Ошибка поиска/категорий | Причина и «Повторить» | Повторить, изменить фильтр; подборка сохранена |
| Пустая подборка | «Добавьте хотя бы одну задачу» | Искать и добавлять; создание недоступно |
| Создание | «Создаём работу» | Поиск и просмотр; создание и изменение подборки недоступны |
| Ошибка создания | Причина, успех не показан | Исправить подборку или повторить создание |
| Результат не подтверждён | Сообщение о потере связи | Подборка сохранена; дальнейшие действия — OQ-02 |
| Успешный экспорт | «Работа создана», число пунктов, раздельные файлы | Скачивать; редактировать подборку |
| Ошибка скачивания | Сообщение рядом с конкретным файлом | Повторить скачивание без нового экспорта |

### Key Entities *(include if feature involves data)*

- **Номер ЕГЭ и категория**: фильтр поиска; категории принадлежат выбранному номеру,
  а группа 19–21 соответствует общему блоку.
- **Задача**: постоянный ID источника, номер/группа ЕГЭ, оригинальное условие,
  изображения, приложения и ссылка на источник; ответы отделены от условия.
- **Выдача**: результаты текущего фильтра, текущая порция и возможность переходов.
- **Подборка**: упорядоченный список уникальных задач, позиции и число пунктов до 100.
- **Созданная работа**: зафиксированные состав/порядок, состояние создания и комплект
  файлов для этой версии подборки.
- **Материал работы**: назначение (ученик/преподаватель), тип, имя и доступность скачивания;
  ученический PDF либо ZIP, отдельные ответы и источники, при ZIP — PDF для просмотра.

## Success Criteria *(mandatory)*

### Measurable Outcomes

Это целевые критерии будущей приёмки; фактические измерения ещё не проводились.

- **SC-001**: В двух сквозных приёмочных сценариях (без приложений и с приложением)
  преподаватель проходит от выбора номера до скачивания ученического материала,
  ответов и источников только через интерфейс, без командной строки и поиска файлов вручную.
- **SC-002**: В проверочной подборке из трёх пунктов, включая блок 19–21 и задачу
  с рисунком, 100% условий, рисунков и порядок соответствуют выбранным оригиналам;
  блок занимает ровно один пункт в подборке и готовой работе.
- **SC-003**: После трёх переходов по выдаче, смены фильтра, пустой выдачи и одной
  ошибки поиска состав и порядок ранее выбранных задач остаются неизменными.
  Пять повторных попыток добавить один ID дают ровно один экземпляр.
- **SC-004**: Переместить пункт на соседнюю позицию и удалить пункт можно одним нажатием
  соответствующей кнопки; ни один сценарий управления подборкой не требует перетаскивания.
- **SC-005**: Пять быстрых нажатий «Создать работу» до завершения дают один запуск
  создания. Загрузка, пустая выдача, ошибка и успех различимы текстом; статус занятости
  и блокировка повторов видны не позднее одной секунды после действия.
- **SC-006**: В обоих экспортных сценариях ученический комплект содержит ноль отдельных
  файлов ответов/источников; оба преподавательских материала доступны отдельно.
  После ошибки экспорта 100% выбранных пунктов и их порядок сохраняются.

## Assumptions

- Один преподаватель использует локальное приложение на настольном компьютере;
  совместное редактирование, учётные записи и публикация в интернете не входят в фичу.
- «Локальное» не означает автономность без сети: существующий подборщик получает
  условия и ресурсы с сайта К. Полякова; недоступность источника показывается как ошибка.
- Подборка хранится в пределах открытой страницы и не сбрасывается поиском.
  Восстановление после перезагрузки/закрытия, история работ и постоянное хранение
  не входят в исходную версию требований.
- По умолчанию доступны все категории выбранного номера; в первой версии выбирается
  не более одной категории. Поиск по тексту, сложности и автоматический подбор вне фичи.
- Работы могут включать задачи разных номеров. Категории не фиксируются заранее;
  отображаются актуальные названия из существующего подборщика.
- Для создания не требуется вводить абсолютный путь на диске: предлагается автоматическое
  уникальное имя. Окончательное поведение имён согласуется с API (OQ-03).
- Ошибки не скрываются под пустым результатом, а неполное условие не заменяется пересказом.
- Основа изучения: `practices/practice_03/homework/README.md`, `server.py`, `polyakov.py`
  и `render.py` в том же каталоге. Подтверждено чтением: категории, поиск порциями до 30,
  ID, разметка условий, изображения/приложения, общий блок 19–21, экспорт 1–100 уникальных
  ID в заданном порядке, отдельные ответы/источники, PDF либо ZIP и запрет перезаписи.
  Живые вызовы и проверки приложения на этом этапе не выполнялись.
- Спецификация API и общий контракт при подготовке этой версии не читались.
  Предложения ниже не являются согласованным контрактом. До реализации UI и API
  обязаны согласовать единственный `../contracts/api-v1.yaml`; API отвечает за его ведение
  и интеграцию. UI не дублирует поиск/экспорт и сохраняет совместимость существующего MCP.

## Открытые вопросы согласования

Это вопросы к общей границе UI/API, а не скрытые требования к существующему API.
Рабочие допущения выше позволяют завершить исходную UI-спецификацию, но ответы
должны быть согласованы до планирования интеграции и реализации.

1. **OQ-01 — Полные условия и скачивание.** Как API предоставит пригодные для показа
   условия/ресурсы и доступные для скачивания материалы вместо одних локальных путей?
   Кто обеспечивает доступность изображений и как сообщается недоступность файла?
2. **OQ-02 — Создание и потеря связи.** Как подтверждается завершение долгого создания
   и выясняется результат после разрыва связи? Предложение UI: блокировать повтор
   до известного исхода, не повторять автоматически; при неизвестном исходе дать
   согласованный способ проверки/восстановления, затем разрешить явный повтор.
3. **OQ-03 — Имя и доступность результата.** Подтверждает ли API автоматическое уникальное
   имя без ввода пути? Как долго доступны готовые файлы и что показывать после их удаления?
   Предложение UI: до конца текущего локального сеанса, с понятной ошибкой при утрате файла.

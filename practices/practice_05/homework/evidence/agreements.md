## A-01. Один длительный запрос создания

Создание выполняется одним HTTP-запросом. Успех возвращается только после готовности
всех материалов и необходимых метаданных. Фоновые задания, опрос прогресса,
промежуточный успех и отмена в первую версию не входят.

**В API**: FR-009, FR-022; история 2, сценарий 9.
**Для UI**: состояние «Создаём работу» относится к ожиданию этого запроса;
быстрые повторные нажатия не должны отправлять новые создания, как уже предусмотрено UI.

## A-02. Неизвестный результат при потере связи

Потеря связи до подтверждённого ответа не доказывает ни отказ, ни успех: работа могла
быть создана на сервере. UI сохраняет состав и порядок подборки, показывает
«Результат не подтверждён» и не повторяет экспорт автоматически.

Пользователь может явно выбрать «Создать новую работу» после сообщения
«Предыдущая работа могла быть создана». Это отдельное создание с возможным дублированием
содержимого: отсутствие дублей не гарантируется. В первой версии нет механизма
поиска, проверки или восстановления потерянного результата, если клиент не получил его ID.
Чтение уже известного `work_id` и повтор скачивания известной работы остаются доступны.

**В API**: FR-023; история 4, сценарии 3–4; SC-008.
**Изменение исходного UI**: OQ-02, FR-020, Edge Cases и строка состояния
«Результат не подтверждён» должны отражать явное новое создание вместо восстановления
или ожидания известного исхода без предусмотренного способа его узнать.

## A-03. Необязательное имя и отдельная идентичность каждого создания

Обязательного ввода имени в UI нет. Поле `name` в API необязательно; при отсутствии
сервер автоматически создаёт имя и возвращает его в метаданных результата.
При явно переданном имени действуют проверки FR-008: строка, удаление крайних пробелов,
1–80 символов, без управляющих символов, разделителей путей, значений `.`/`..`
и обозначения диска. Явные null, пустая строка и строка из пробелов — ошибка проверки,
а не запрос автоматического имени. Автоматическое имя также удовлетворяет этим правилам.

Имя — не путь и не идентификатор. Каждое создание получает отдельные `work_id`
и каталог, в том числе при одинаковом имени; прежние материалы не перезаписываются.
Алгоритм генерации имени и расположение каталогов не назначались исходным A-03;
позднее они определены планом API и согласованным контрактом 1.0.0.

**В API**: FR-007–008; история 2, сценарии 7–8; SC-009.
**Изменение исходного UI**: часть OQ-03 об имени закрыта; одинаковое имя само по себе
не является конфликтом работ. Ошибки файлового конфликта и отказа записи остаются возможны.

## A-04. Хранение до ручной очистки и границы состояния UI

Готовые работы и необходимые для доступа к ним метаданные сохраняются между
перезапусками сервера до ручной очистки. Автоматического удаления нет. Известные
идентификатор и ссылки продолжают давать те же метаданные и материалы без нового экспорта.

После удаления запрошенного материала API возвращает понятную ошибку отсутствия
результата (404 `not_found`). Недоступность одного файла не отменяет
доступ к остальным сохранённым материалам. Автоматического повторного экспорта нет.

Экран истории работ и восстановление подборки после перезагрузки страницы
не входят в первую версию. Сохранность серверных материалов не означает восстановление
клиентской подборки, потерянного `work_id` или результата запроса по имени.

**В API**: FR-024; история 3, сценарии 4–5; SC-009.
**Изменение исходного UI**: OQ-03 больше не ограничивает доступность концом локального
сеанса; исключение истории и восстановления подборки не исключает хранения на сервере.

## A-05. Условия без ответов, отдельные преподавательские материалы

Поиск возвращает оригинальные условия без `answer` и `answer_html`.
Ответы и источники доступны отдельно для созданной работы: ответы — текст,
источники — JSON существующего формата с оригинальными данными и картой приложений.
Отдельный просмотр ответа задачи до создания в первую версию не входит.
Ответы и источники не включаются в ученические PDF/ZIP.

**В API**: FR-006, FR-014; история 3.
**Для UI**: карточки показывают условия без ответов; материалы созданной работы
разделены на ученические и преподавательские, как предусмотрено UI FR-004 и FR-017.

## A-06. Браузерное представление и скачивание через API

Условия предоставляются как HTML без исполняемого кода источника, с сохранением
содержания, рисунков, таблиц и ссылок. Изображения и приложения имеют рабочие
HTTP(S)-адреса для браузера; их временная недоступность не скрывается под пересказом.
Готовые материалы скачиваются через URL API. Локальные абсолютные пути клиенту
не передаются ни вместо ссылок, ни в метаданных/сообщениях об ошибке.

Способ предоставления ресурсов условий исходным A-06 оставлялся этапу plan.
Теперь план и контракт 1.0.0 определяют браузерную HTML-проекцию и task-bound resource API;
гарантия доступности внешнего источника не вводится.

**В API**: FR-006, FR-009, FR-015, FR-018; история 1, сценарий 6; SC-010.
**Изменение исходного UI**: OQ-01 закрыт по требуемому внешнему поведению;
технический способ доставки определён планом и контрактом 1.0.0 и принят UI.

## Сохранённые ограничения и совместимость

Уточнения не меняют исходные правила поиска и экспорта: категории для 1–27,
общий блок 19–21 как один пункт, до 30 результатов на страницу, от 1 до 100 уникальных
ID в порядке пользователя, оригинальные условия, байты и нумерация приложений,
переносимые относительные ссылки внутри комплекта, запрет перезаписи.
При наличии приложений основной результат — ZIP с PDF и `.files`, иначе — PDF.
Ответы и источники всегда отдельно.

Все четыре MCP-инструмента и их прежние входы/результаты сохраняются; необязательное
имя и запрет локальных путей относятся к HTTP, а не изменяют MCP `output_path`.
Согласованный контракт обязателен до реализации зависимых компонентов.

## A-07. Точный POST без перенаправления и повторной отправки

Пользователь подтвердил: UI отправляет один POST на точный `/api/v1/works`
и запрещает автоматическое следование redirect (`redirect: "error"`).
API обслуживает этот адрес напрямую, без 307/308. Вариант `/api/v1/works/`
отклоняется как JSON 404 `not_found`, без Location, redirect и запуска экспорта.
Автоматическая нормализация слеша отключается; ни клиент, ни сервер не используют
перенаправление как способ повторить тело запроса или начать работу.

**В API**: FR-022, SC-011; история 2, сценарий 10; план маршрутизации и quickstart.
**Будущая проверка**: точный путь вызывает экспорт один раз, вариант со слешем — ноль;
включённое следование redirect у диагностического клиента не меняет этот результат.
UI при навязанном 307/308 не переотправляет POST и не делает автоматический retry.

## A-08. ErrorResponse и узкие исключения файлового Range

Прикладные ошибки API имеют JSON ErrorResponse. Пользователь потребовал сверить
реальную выбранную версию Starlette, включая возможный текстовый 400.
Для файлового транспорта выбран baseline FastAPI 0.162.0 / Starlette 1.10.0.

- Обычное скачивание UI: GET без Range, полный 200.
- Прямой просмотр PDF сохранён: один применимый диапазон — 206 с Content-Range;
  несколько — multipart/byteranges 206 с заголовками частей, без общего Content-Range.
- Некорректный Range: транспортный 400 text/plain; charset=utf-8, без ErrorResponse.
- Недостижимый Range: 416 text/plain; charset=utf-8 с пустым телом и Content-Range bytes */N.
- Эти исключения относятся только к Range внутри файлового ответа. Отсутствующий
  материал с плохим Range даёт обычный JSON 404 до FileResponse; неверный JSON POST —
  JSON 400, остальные прикладные ошибки также сохраняют общий формат.
- После начала передачи разрыв не превращается в JSON-ошибку. UI не предлагает
  недочитанный файл как полный; явный повтор GET не создаёт новую работу.

**В API**: FR-015/018/019, SC-012; история 3, сценарии 6–7; общий контракт и quickstart.
**Фактическое основание**: код выбранного FileResponse прочитан; во временном окружении
шесть вызовов библиотеки подтвердили 200, одиночный/multipart 206, два текстовых 400
и пустой 416. Разрешение выбранных зависимостей вместе с MCP 1.30.0/HTTPX 0.28.1 прошло.
Это диагностика зависимости, не тесты приложения или проверка MCP; подробности в
[research.md, R-09](../api/specs/001-task-bank-http/research.md#r-09-прямой-post-и-транспортные-range-исключения).

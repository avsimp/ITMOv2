[контракт api-v1.yaml](../contracts/api-v1.yaml), версия **1.0.0**, статус **agreed**.

## Что не было новым решением человека

- Первоначальная спецификация уже требовала подборку без дублей, сохранение порядка
  при поиске, кнопки «Вверх/Вниз», правило «19–21 — один пункт», PDF/ZIP и отдельные
  ответы/источники. Эти правила сохранены, а не добавлены задним числом.
- Отсутствие обязательного имени не является удалением обязательного поля из исходного UI:
  оно уже предлагало автоматическое имя. Человек утвердил необязательность и уточнил,
  что уникальна идентичность создания, а не отображаемое имя.
- Человек принял внешнее поведение A-06; конкретные task-bound resource URL, allowlist
  и поля дескрипторов предложены в техническом дизайне API и затем согласованы.
- Для A-08 человек потребовал проверить реальный файловый транспорт; baseline
  FastAPI 0.162.0 / Starlette 1.10.0 и диагностика зависимости зафиксированы командой API.
  UI опирается на них как на принятое основание, не заявляет собственный прогон библиотеки.
- HTML/CSS/JavaScript без frontend-фреймворка и обслуживание с адреса API прямо заданы
  пользователем в запросе плана. ES-модули, Map/массив ID, история offset и Fetch/Blob —
  технические решения плана UI, а не отдельные функциональные решения A-01–08.

## Минимальное согласование с API без расширения контракта

- Дедупликация и порядок черновика остаются в UI: ordered ID и Map выбранных задач.
  API получает готовый массив topic_ids, новые операции черновика/перестановки не нужны.
- UI выбирает одну категорию либо все; отсутствие category_ids означает все.
  Множественные категории, contains/exclude_ids и иной limit — возможности API,
  не обязательные дополнительные элементы первой версии UI.
- Для «Предыдущие» UI хранит историю успешных offset; «Следующие» использует next_offset,
  конец — null. Ошибка и пустая выдача различаются; подборка не очищается.
- Признак приложений берётся из Task.attachments.length; дополнительное поле не нужно.
  Work.attachments содержит имена уже экспортированных файлов, не URL рисунков/приложений.
- Ученику выдаётся Work.result: PDF без приложений либо ZIP с приложениями.
  Work.pdf при ZIP — только просмотр; answers/sources доступны отдельными teacher-действиями.
- JSON-ошибки разбираются по статусу и ErrorResponse, не по одному MIME:
  успешный sources тоже JSON. Обрыв файла не публикует частичный Blob; повтор только GET.
- Скачивание не меняет сохранённый комплект и не обращается заново к источнику.
  Изменение внешнего банка между поиском и экспортом не выдаётся за единый снимок;
  сравнение условий на приёмке выполняется на неизменном контрольном источнике.

## Фактический итог и передача API

Контракт 1.0.0/agreed прочитан, статусы и ссылки документов UI синхронизированы.
ui-after.md сохраняет окончательную спецификацию; ui-before.md не изменён.
Реальных противоречий и открытых вопросов между UI и согласованным API нет.

Следующий этап — задачи и анализ согласованности. Код, браузерные проверки, живой поиск,
экспорт и интеграционные тесты в этом этапе не создавались и не выполнялись.
Команда UI завершила редактирование и передаёт документы API для общего коммита;
коммит выполняется только API, когда второй чат не редактирует файлы.

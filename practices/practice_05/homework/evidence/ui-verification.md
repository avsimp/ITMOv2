# UI: реализация, браузерные проверки и открытая общая граница

**Контракт**: 1.0.0/agreed. **Запуски**: 2026-10-28 UTC по журналам тестов.
**Статус**: UI реализован, обычный сквозной сценарий подтверждён настоящим API/сайтом.
Полная приёмка **не закрыта**: B-01 (pre-header TCP replay Chromium) и E-01 (Firefox).

## Реализованные файлы и поведение

`ui/index.html` и `ui/assets/{styles.css,app.js,api.js,state.js,render.js,downloads.js}`:
номер ЕГЭ/категория → явный поиск → полные оригинальные условия → подборка → порядок →
создание → раздельное получение материалов. Runtime — HTML/CSS/native ES modules,
без frontend-фреймворка, npm, сборки или отдельного UI-сервера.

UI использует CategoryResult/Task/SearchResult/Work/Artifact и ErrorResponse из общего
контракта. Порядок сохраняется массивом ID, в Selection запрещены дубли и 101-й пункт.
Карточки сохраняют HTML таблиц, индексов и рисунков, признак приложений вычисляется
из массива. Ответов в выдаче/карточках нет. Все источники HTML — браузерная проекция API;
обычные сообщения вставляются как текст. Поиск и экспорт имеют независимые состояния,
GET-контроллеры не отменяют POST. Точный POST имеет redirect:error, тело — только topic_ids.

Ученик получает result PDF/ZIP, preview PDF отдельно при ZIP, answers/sources — teacher.
GET полного файла без Range, получение через Blob и отдельное сохранение; MIME sources
JSON не считается признаком ошибки. Частичное тело не предлагается как полный файл.
Известный Work и подборка сохраняются при отдельных отказах и новом ожидающем создании.

## CONTROLLED — ответы API и ресурсы подменены

Настоящий браузер и настоящие файлы UI, но `/api/v1/**` перехватывается Playwright.
JSON фикстур проверяется по единственному YAML через tests/contract_support.py;
тела PDF/ZIP контролируемых тестов синтетические и не считаются экспортом.

Проверены категории/необязательный фильтр, оригинальная структура HTML таблицы/sup/img,
пагинация и возврат, пустота, категории/поиск с ошибкой и явный повтор, запоздалый GET,
отдельная ошибка/повтор рисунка. Подборка сохраняется при фильтрах/листах/ошибках;
дубли, 0/1/100/101 пунктов, соседние перестановки, удаление и клавиатурный фокус проверены.

Для экспорта проверены pending и единственный JS-запрос при быстрых повторных событиях,
поиск во время ожидания при заблокированном редактировании, JSON 400/404/409/415/422/
500/502/504, повреждённый 201, неизвестный исход, redirect:error, явное новое создание
и сохранение предупреждения после правок. Для файлов — отдельные teacher-материалы,
JSON sources, JSON 404 и текстовые Range-отказы, отсутствие Range/If-Range в обычном GET.
Ключевые снятия блокировок дополнительно проверяются expect с timeout=1000 мс.

## REAL-LOCAL — реальные UI и все локальные компоненты, внешний HTTP фиксирован

В тестах используется `api/tests/source_fixture.py`: подменяется только httpx-доставка
сырых HTML/JSON/PNG/приложения внешнего источника. Реальные API, Bank, парсер, export_pdf,
Chromium/PyMuPDF и дисковые файлы работают вместе, без FakeBank/FakeExporter.

Четыре проверки: фиксированные PDF/ZIP и перезапуск/Range; подтверждённый реальный API
отказ 502 при сбое upstream; обрыв реального файлового TCP без выдачи частичного Blob;
форматы всех шести операций и файловые заголовки. Выбранные statement сравниваются
с сохранёнными tasks в sources, порядок меток TASK-001/002/004 и отсутствие SECRET_
в PDF подтверждены; игра содержит три вопроса одним пунктом. Это закрывает пробел C1
предыдущего анализа на воспроизводимом источнике, но не выдаётся за живой сайт.

## B-01 — на согласование API/человеку: обрыв до заголовков

Воспроизводитель boundary_probe не подменяет ответы API: TCP relay передаёт байты,
после появления серверного каталога до work.json закрываются реальные сокеты.
В повторных наблюдениях Chromium 153 дал **один браузерный request-event/один вызов Fetch**,
но сервер создал две работы; интерфейс получил повторный 201 и показал succeeded.

Последнее воспроизведение с прямым счётчиком POST на TCP relay:
`ui/.test-artifacts/runs/live-ui-20261028-131705-392447/journal.json`:
fetch_requests=1, **relay_post_requests=2**, ui_state=succeeded, server_work_ids:
24377f81-56b7-4562-aceb-1277a424909e и 3d8b95a6-8279-43d4-a58b-7185bda5df7f.
Предыдущее независимое наблюдение: live-ui-20261028-124736-606580/journal.json,
UUID 08364e49-bcb6-4ce3-9295-843b0c99c222 и 14d9d918-7fa7-4c85-96d1-b6397068a728.

Это наблюдение транспортного повтора ниже JS Fetch, не дополнительный retry в app.js.
Полная гарантия A-02/A-07 «нет автоматического повтора» в этом случае **не подтверждена**.
Нельзя выдать прошедший partial-body сценарий за успешный pre-header сценарий.

Нужно совместно решить, как трактовать и предотвращать такой транспортный повтор
на общей границе. Контракт 1.0.0 сейчас явно не предоставляет идемпотентность;
новое поле/механизм либо изменение гарантии нельзя ввести UI единолично.
API-код, конфигурация его соединений и общий YAML в рамках UI не исправлялись.
До решения B-01 полная интеграционная приёмка открыта.

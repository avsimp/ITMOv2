### Сквозное поведение и граница ошибки

- Настоящие UI и API обслуживаются на одном origin; поиск показывает оригинальные
  условия с таблицами/рисунками, без ответов. Подборка сохраняется при смене выдачи,
  дубли запрещены, порядок управляется пользователем, 19–21 — один пункт.
- LIVE-UI подтвердил PDF для ID `9296, 9316, 9300` и ZIP для `9316, 9304`.
  Проверены порядок/состав, условия против sources, SHA-256, отдельные answers/sources,
  состав архива и цели относительных ссылок после распаковки. UI-скриншот и выбранные
  PDF были просмотрены; это свидетельства выбранных примеров, не всего банка.
- В успешном сценарии обрыва **после заголовков 201, до полного JSON** UI показывает
  unknown, сохраняет выбор, снимает блокировки; наблюдались один Fetch/один каталог
  до явного нового действия. JS не повторял создание. Потерянный ID не восстанавливается.
- Реальный offline-поиск сохраняет подборку и допускает явный повтор после возврата сети.
  Отдельно подтверждены 422, удалённый answers с JSON 404 и доступный sources;
  обрыв файлового GET не предлагает частичное тело как полный Blob.
- Перезапуск с тем же origin/storage сохраняет известные метаданные и байты файлов
  без нового экспорта. Точный POST не перенаправляется, вариант со слешем даёт 404.

Трассировка исходных требований сохранена в [ui-acceptance.md](ui-acceptance.md);
актуальная трактовка FR-020/SC-005 UI и FR-023/SC-008 API учитывает A-09.
Исторический отчёт приёмки не переписан задним числом.

## Известные ограничения

1. **B-01 — не исправлен, boundary_probe: 1 failed.** При обрыве до заголовков
   Chromium 153 выполнил один Fetch/request-event, но relay увидел **два POST**,
   сервер создал две работы, UI получил повторный 201. Успех partial-body сценария
   не доказывает успех pre-header сценария. Отсутствие JS-retry не означает отсутствие
   транспортных дублей, идемпотентность или выполнение «ровно один раз».
2. **Firefox E-01 — не проверен успешно.** После установки браузера процесс не открыл
   UI из-за `Could not find profile folder`. Проверки относятся к Chromium.
3. Нет восстановления неизвестного work_id, серверной истории UI, идемпотентности,
   фоновых заданий, БД, авторизации, автоочистки или сохранения подборки после reload.
   Незавершённые каталоги непубличны; очистка ручная. Явное новое создание тоже может
   дать дубль содержимого.
4. Успех внешнего сайта зависит от времени и выбранных задач. Python 3.11 отдельно
   не прогонялся; зафиксирован macOS/Python 3.14.4. В отчётах — пять SWIG/PyMuPDF
   DeprecationWarning, не падения тестов.
5. Получение Blob не доказывает сохранение на диск пользователем. Клик ODS в отдельном
   PDF-просмотрщике не проверялся; существование целей относительных ссылок проверено.
   Бинарные свидетельства и журналы остаются в игнорируемых локальных каталогах.

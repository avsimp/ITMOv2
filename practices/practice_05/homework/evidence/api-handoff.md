# Передача API команде UI

**Статус**: независимая API-часть реализована и проверена по 1.0.0/agreed.
Настоящий UI не поставлен; сквозная приёмка не объявляется выполненной.
Пользователь подтвердил, что UI сейчас не редактирует файлы, и разрешил коммит API
с сохранением открытой LIVE-UI проверки.

## Запуск

Рабочий каталог — `practices/practice_05/homework/api/`.

```bash
uv venv .venv
uv pip sync --python .venv/bin/python requirements-dev.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

UI открывается на http://127.0.0.1:8000/ после передачи `ui/index.html` и `ui/assets/`.
Сервер не публикует specs/.specify/tests/var. Без файлов UI — 404, API продолжает работать.
HOMEWORK_API_ORIGIN задаёт адрес выдаваемых URL при другом порте; он должен совпасть
с командой запуска. Runtime storage по умолчанию — api/var/works, после перезапуска сохраняется.

## Готовые возможности

Все шесть операций единственного `contracts/api-v1.yaml` доступны. Поиск выдаёт
безопасный statement_html и готовые delivery URL, не ответы. Создание принимает
ordered topic_ids и необязательное name, возвращает 201 Work после полной готовности.
Основной файл — result, pdf — просмотр, answers/sources — teacher, archive nullable.
Использовать выданные URL и filename, не строить пути из work.name.
POST со слешем — JSON 404 без redirect/экспорта. Обычный GET файла без Range — 200;
прямой просмотр допускает согласованные 206 и текстовые Range 400/416.

Потеря связи при POST не отменяет уже начатый экспорт. UI сохраняет подборку,
показывает «Результат не подтверждён»/«Предыдущая работа могла быть создана»,
не повторяет автоматически. Никакого recovery/job API нет.
Отдельная ошибка GET не создаёт работу заново и не отменяет остальные материалы.

## Подтверждения и следующий совместный этап

Фактические результаты, режимы и UUID примеров — в `evidence/api-verification.md`.
Тестовые UUID относятся к отдельному var/checks, не default var/works;
новую работу UI создаёт своим явным POST по выбранным актуальным ID.

Ожидаются UI-D1/D2/D3: реальные index/assets, согласованные клиентские состояния,
совместное окно PDF/ZIP и отказов. Проверки следует выполнить настоящим браузером
с реальным сервером/Bank/export_pdf, без route.fulfill или подмен источника.
До этого API T047–T049 и финальные совместные gates остаются открытыми.
При дефекте UI исправляет свои файлы, API — свои; изменения контракта сначала согласуются.

Общие журналы ui-api-live.md/ui-api-faults.md не создаются с фиктивным успехом.
Файлы UI не редактировались командой API. Завершение этого этапа не заменяет
полную пользовательскую приёмку двух компонентов.

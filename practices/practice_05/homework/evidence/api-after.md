## Clarifications

### Session 2026-10-27

Решения предоставлены пользователем без дополнительных вопросов. Исходное описание
выше сохранено как контекст; обязательность имени заменена уточнением ниже.

- Q: Как подтверждается создание работы? → A: Одним длительным HTTP-запросом;
  успех только после готовности всех материалов, без фоновых заданий, прогресса и отмены.
- Q: Что делать при потере связи во время создания? → A: Результат неизвестен;
  UI сохраняет подборку, показывает «Результат не подтверждён», не повторяет экспорт
  автоматически. «Создать новую работу» доступно явным действием после предупреждения,
  что предыдущая работа могла быть создана; отсутствие дублей и восстановление не обещаются.
- Q: Обязательно ли имя работы и определяет ли оно идентичность результата? → A: `name`
  необязателен; при отсутствии сервер создаёт имя. Явное имя проверяется по FR-008.
  Каждое создание получает отдельные `work_id` и каталог, в том числе при одинаковом имени.
- Q: Как долго доступны работы и восстанавливается ли состояние UI? → A: Материалы
  и необходимые метаданные сохраняются между перезапусками до ручной очистки,
  автоудаления нет; история и восстановление подборки после перезагрузки страницы
  вне первой версии. После удаления материала возвращается понятная ошибка отсутствия.
- Q: Какие данные поиска и адреса ресурсов получает браузер? → A: Оригинальные условия
  без ответов, HTML без исполняемого кода и рабочие HTTP(S)-адреса изображений и приложений;
  ответы и источники отдельно для созданной работы, готовые материалы по URL API,
  без локальных абсолютных путей. Способ предоставления ресурсов определяется в plan
  и фиксируется в общем контракте.

Дополнительно пользователь подтвердил A-07–08: создание только на точном
`POST /api/v1/works` без redirect; прикладные ошибки — JSON ErrorResponse,
а файловые транспортные 400/416 при обработке Range — явно описанные исключения.
Обычное скачивание UI не использует Range; прямой просмотр PDF сохранён.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Найти задачи по номеру ЕГЭ (Priority: P1)

Преподаватель получает категории выбранного номера, задаёт фильтры и просматривает
страницы оригинальных условий, чтобы выбрать подходящие задачи.

**Why this priority**: Выбор задач — вход в основной сценарий; он полезен и без экспорта.

**Independent Test**: На контролируемом наборе задач запросить категории и две страницы
поиска, сверить состав, порядок и границы страниц без создания работы.

**Acceptance Scenarios**:

1. **Given** доступен номер 5, **When** запрошены его категории, **Then** возвращены их ID
   и названия из существующего банка, без самостоятельно придуманной классификации.
2. **Given** одни и те же категории и неизменный источник, **When** поиск выполнен
   с `contains`, `exclude_ids`, `offset=0`, `limit=1`, а затем с полученным `next_offset`,
   **Then** исключения и поиск подстроки применены до пагинации, страницы не повторяются.
3. **Given** нет совпадений либо `offset >= total`, **When** выполнен поиск,
   **Then** получен успешный пустой список, актуальный `total` и `next_offset=null`.
4. **Given** выбраны 19, 20 или 21, **When** запрошены категории и задачи,
   **Then** используется общий банк 19–21, каждый полный блок — одна запись.
5. **Given** категория не принадлежит номеру либо `limit=31`, **When** выполнен запрос,
   **Then** получена ошибка входных данных, а не пустая успешная выборка.
6. **Given** доступны задачи с рисунком и приложением, **When** получен результат поиска,
   **Then** исходные условия пригодны для показа в браузере: HTML без исполняемого кода,
   HTTP(S)-адреса ресурсов доступны при исправном источнике и соединении;
   ответов и локальных абсолютных путей в выдаче нет.

### User Story 2 - Создать и скачать ученическую работу (Priority: P1)

Преподаватель отправляет упорядоченные ID без обязательного ввода имени, получает
готовую работу и скачивает единственный рекомендуемый файл для ученика:
PDF либо ZIP с приложениями. При желании он может передать допустимое имя.

**Why this priority**: Это основной результат подбора, пригодный для передачи ученику.

**Independent Test**: Передать известные ID напрямую без поиска; отдельно проверить
набор без приложений и набор с приложениями, включая блок 19–21.

**Acceptance Scenarios**:

1. **Given** известны три ID без приложений, **When** они отправлены в заданном порядке,
   **Then** работа содержит три пункта в том же порядке, итоговый файл — PDF,
   архив отсутствует, локальный путь сервера клиенту не передаётся.
2. **Given** есть блок 19–21 и задача с таблицей-приложением, **When** работа создана,
   **Then** блок занимает один пункт, результат — ZIP с PDF и соседней папкой `.files`,
   PDF также доступен отдельно для просмотра, ответы и источники в архив не включены.
3. **Given** скачан ZIP, **When** он целиком распакован в другой каталог,
   **Then** относительные ссылки PDF указывают на существующие приложения с исходными
   байтами; для разрешения этих ссылок не нужен сервер или исходный каталог.
4. **Given** переданы повторяющиеся ID, 0 ID, 101 ID либо поле `output_path`,
   **When** отправлен запрос создания, **Then** получена ошибка и работа не опубликована.
5. **Given** файл назначения уже существует либо возник сбой экспорта,
   **When** выполняется создание, **Then** прежние файлы не перезаписываются,
   частичный результат не выдаётся за готовую работу.
6. **Given** существует готовая работа, **When** её итог скачан дважды,
   **Then** получены одинаковые байты без повторного подбора или экспорта.
7. **Given** передан допустимый список ID без `name`, **When** создание завершается,
   **Then** сервер назначает имя и возвращает его с новым `work_id`; отсутствие имени
   не является ошибкой. Явное пустое, null или недопустимое имя даёт ошибку проверки.
8. **Given** два запроса с одинаковым допустимым именем, **When** оба успешны,
   **Then** у них разные `work_id` и каталоги, материалы не смешаны и не перезаписаны.
9. **Given** экспорт ещё не завершён, **When** запрос создания ожидает результата,
   **Then** нет промежуточного успешного ответа или доступного частичного комплекта;
   итоговый успех возвращается одним ответом после готовности всех материалов.
10. **Given** допустимая подборка, **When** UI отправляет POST на точный `/api/v1/works`
    с запретом redirect, **Then** запрос обрабатывается напрямую, без 307/308.
    POST на `/api/v1/works/` возвращает 404 ErrorResponse без перенаправления
    и без запуска экспорта.

### User Story 3 - Получить преподавательские материалы отдельно (Priority: P2)

Преподаватель отдельно получает ответы и источники созданной работы для проверки
и отслеживания происхождения задач, не смешивая их с ученической выдачей.

**Why this priority**: Отдельные материалы необходимы для проверки и доверия к результату.

**Independent Test**: Для готовой контрольной работы запросить только ответы и только
источники; сопоставить их нумерацию с ученическим результатом.

**Acceptance Scenarios**:

1. **Given** работа содержит игру на позиции 2, **When** получены ответы,
   **Then** соответствующая строка имеет вид `2. 19) …; 20) …; 21) …`.
2. **Given** работа имеет приложения, **When** получены источники,
   **Then** доступны оригинальные данные задач, адреса источника, соответствие
   исходных и новых имён файлов и контрольная сумма PDF.
3. **Given** запрашивается неизвестная работа или отсутствующий у неё архив,
   **When** запрошен материал, **Then** получена ошибка отсутствия ресурса,
   а не подмена другим файлом или создание новой работы.
4. **Given** сохранены `work_id` и ссылки готовой работы, **When** сервер перезапущен,
   **Then** метаданные и все материалы доступны без повторного экспорта с теми же байтами.
5. **Given** материал удалён при ручной очистке, **When** запрошена прежняя ссылка,
   **Then** API возвращает 404 с понятным сообщением об отсутствии результата,
   не восстанавливая его экспортом. Ошибка одного файла не скрывает остальные доступные.
6. **Given** готовый файл, **When** UI скачивает его обычным GET без Range,
   **Then** получает полный 200; прямой просмотр PDF может использовать Range.
   Некорректный Range может дать текстовый 400, недостижимый — 416 с пустым телом
   и Content-Range; UI не считает эти транспортные ответы JSON ErrorResponse.
7. **Given** передача уже началась, **When** связь оборвалась при чтении файла,
   **Then** JSON-ошибка не подставляется в файл, частичный результат не считается полным;
   явный повтор GET получает сохранённый материал без нового экспорта.

### User Story 4 - Пройти весь цикл с понятным отказом (Priority: P2)

Преподаватель проходит путь от категорий и поиска до скачивания, отличает подтверждённый
отказ от неизвестного результата и сохраняет подборку для осознанного следующего действия.

**Why this priority**: Отдельные успешные операции не доказывают пригодность всего процесса.

**Independent Test**: Через HTTP-вход пройти категории → поиск → упорядоченные ID →
создание → скачивание → отдельные ответы и источники; повторить с отказом источника.

**Acceptance Scenarios**:

1. **Given** доступен контролируемый набор с рисунком, таблицей, приложением и игрой,
   **When** пройден полный цикл, **Then** выбранные ID, порядок, число пунктов,
   ученический файл и преподавательские материалы согласованы между собой.
2. **Given** источник недоступен или вернул неполную игру, **When** выполнен поиск
   либо создание, **Then** получена явная ошибка, неполный успех не объявлен,
   ранее созданная работа остаётся доступной без изменений.
3. **Given** связь потеряна до получения подтверждённого результата создания,
   **When** UI завершает ожидание, **Then** показано «Результат не подтверждён»,
   состав и порядок подборки сохранены; нет автоматического повтора, заявления
   об отказе или успехе, опроса прогресса либо восстановления потерянного результата.
4. **Given** результат не подтверждён, **When** пользователь видит предупреждение
   «Предыдущая работа могла быть создана» и явно выбирает «Создать новую работу»,
   **Then** отправляется новый запрос создания. Предыдущая работа могла сохраниться;
   новый запрос не является её восстановлением и может создать дубль по содержимому.

### Edge Cases

- Номера 0 и 28; дроби, строки и логические значения вместо целых чисел; ID <= 0.
- `category_ids` не задан (все категории) и задан пустым списком (ошибка).
- `offset=-1`, `limit=0/1/30/31`; пустая подстрока; разный регистр кириллицы;
  исключения убирают все записи; `offset` равен или превышает `total`.
- Список ID длиной 0/1/100/101; повтор ID; смешанные номера ЕГЭ; игра среди обычных задач.
- Отсутствующее `name` (автоматическое имя) в отличие от явного null, пустой строки,
  имени из пробелов, чрезмерно длинного имени, разделителей путей и управляющих символов;
  одинаковые допустимые имена у двух разных работ; неизвестные входные поля.
- Один URL повторён внутри пункта или в разных пунктах; разные URL имеют одинаковое
  исходное имя; многосоставное расширение; кириллица и пробелы в файловых именах.
- Ответ, условие или вопрос игры отсутствует; повреждённая разметка; внешний домен;
  неполученное изображение; потерянная файловая ссылка в PDF; ошибка записи на диск.
- Одновременные создания с одинаковым именем; конфликт каждого сопутствующего файла
  или символической ссылки; файл появляется после предварительной проверки.
- Неизвестный идентификатор работы, отсутствующий файл готовой работы, попытка
  скачать произвольный локальный путь; повторная загрузка готового результата.
- Источник изменился между страницами поиска или между выбором и экспортом:
  консистентный снимок всего внешнего банка не обещается, экспорт заново получает задачи по ID.
- Разрыв связи до ответа, включая уже завершённое на сервере создание: клиент не знает
  исхода, не повторяет запрос автоматически; явное новое создание может дать дубль.
- Перезапуск сервера не равен ручной очистке: готовые работы и метаданные сохраняются;
  перезагрузка страницы не восстанавливает подборку или потерянный `work_id`.
- Ресурс условия имеет HTTP(S)-адрес, но временно не загружается в браузере: условие
  не заменяется пересказом и неполное отображение не считается подтверждением готовности
  экспорта; новый механизм доставки ресурсов в этой спецификации не назначается.
- POST на вариант `/api/v1/works/` с завершающим слешем: отказ без 307/308,
  Location и вызова экспорта, а не автоматическое исправление адреса.
- Файловый Range некорректен или недостижим: транспортные 400/416 не обязаны содержать
  ErrorResponse. Несколько диапазонов дают multipart 206; применимый одиночный — 206
  с Content-Range. Прикладной 404 отсутствующего файла остаётся JSON даже с Range.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: HTTP-слой ОБЯЗАН предоставлять операции категорий, поиска, создания работы,
  чтения её метаданных, скачивания результата и PDF, отдельных ответов и источников.
  Состав операций описывает внешнее поведение; точные маршруты и схемы согласуются
  перед изменением реализации, текущая согласованная редакция — единый
  `../contracts/api-v1.yaml` версии `1.0.0`.
- **FR-002**: Категории и поиск ОБЯЗАНЫ переиспользовать `Bank.categories` и `Bank.search`,
  получение задач при создании — `Bank.get`, экспорт — `export_pdf`.
  Новая предметная логика поиска, интерпретация ответов и отдельный генератор PDF не вводятся.
- **FR-003**: Категории принимают обязательный целый `ege_number` от 1 до 27 включительно
  и возвращают список `{id, title}`. Значения 20 и 21 эквивалентны 19.
- **FR-004**: Поиск принимает `ege_number`, необязательные списки положительных целых
  `category_ids` и `exclude_ids`, `contains` (строка, по умолчанию `""`), `offset`
  (целое >= 0, по умолчанию 0), `limit` (целое 1–30, по умолчанию 10).
  Отсутствие `category_ids` означает все категории; пустой список и чужие категории — ошибка.
- **FR-005**: Поиск ОБЯЗАН сохранять порядок банка, регистронезависимое вхождение подстроки
  в текст условия и исключение ID до разбиения на страницы. Результат содержит `total`
  после фильтров, `offset`, `tasks`, `next_offset` (либо null) и адрес исходной выборки.
  Текстовый фильтр не является оценкой сложности или семантическим поиском.
- **FR-006**: Каждая запись поиска содержит ID генератора, `ege_numbers`, исходное условие
  в текстовом и нормализованном HTML-представлении, ссылки на рисунки и приложения,
  адреса происхождения. HTML ОБЯЗАН быть пригоден для браузера без исполняемого кода
  источника, а изображения и приложения — адресоваться рабочими HTTP(S)-URL,
  без локальных абсолютных путей. Запись не содержит `answer` и `answer_html`:
  ответы и источники работы доступны отдельными преподавательскими операциями.
  Способ предоставления ресурсов определён планом и общим контрактом `1.0.0`.
- **FR-007**: Создание принимает обязательный упорядоченный `topic_ids` из 1–100
  уникальных положительных целых ID и необязательный `name`. Отсутствие `name`
  запускает автоматическое назначение имени сервером, а не ошибку проверки.
  Числа не включают логические значения и дроби.
  Произвольные условия, ответы и файловые пути, включая `output_path`, запрещены;
  неизвестные поля отклоняются. Допускается смешивать номера ЕГЭ в одной работе.
- **FR-008**: Явно переданный `name` ОБЯЗАН быть строкой; null не равен отсутствию поля.
  После удаления крайних пробелов имя содержит 1–80 символов,
  без управляющих символов, `/`, `\`, значений `.` и `..` и обозначения диска вида `C:`.
  Это не путь и не инструкция печатать заголовок в PDF. Размещение и безопасные файловые
  имена выбирает сервер; имя не определяет идентичность работы. Повтор имени допустим:
  каждое создание получает новый непрозрачный `work_id` и отдельный каталог с файлами,
  в том числе при одинаковом имени. Автоматически назначенное сервером имя также
  удовлетворяет этим ограничениям и возвращается в метаданных готовой работы.
- **FR-009**: Успешное создание возвращает `work_id`, имя, время создания, исходную
  последовательность ID, `count`, сведения о приложениях и ссылки на рекомендуемый
  результат, PDF, архив (либо null), ответы и источники. Ответ не включает содержимое
  ответов, источников или абсолютные локальные пути. Метаданные готовы только после
  завершения экспорта и доступны повторно по `work_id`.
- **FR-010**: При отсутствии приложений рекомендуемый результат — PDF, архив отсутствует,
  `.files` и ZIP не создаются. При наличии приложений рекомендуемый результат — ZIP,
  содержащий только PDF в корне и соседнюю папку `<основа>.files/` с приложениями.
  Отдельный PDF остаётся доступным для просмотра; передача одного PDF с приложениями
  не считается полной ученической выдачей.
- **FR-011**: PDF ОБЯЗАН сохранять существующее оформление: A4, поля 18 мм, основной
  шрифт 12 pt, только нумерация `1)`, `2)` и оригинальные условия с рисунками и таблицами,
  без добавленных заголовков, ответов и номеров страниц. Порядок соответствует `topic_ids`.
  Полный блок 19–21 учитывается и нумеруется как один пункт.
- **FR-012**: Приложения сохраняют исходные байты и расширения. Единственный файл пункта N
  именуется `N.<расширение>`, несколько — `N_1.<расширение>`, `N_2.<расширение>` в порядке
  первого появления разных URL; без расширения остаётся только числовая основа.
  Повтор URL внутри пункта даёт один файл, в разных пунктах — отдельные номера;
  разные URL не объединяются по исходному имени. Многосоставные расширения сохраняются.
- **FR-013**: Ссылки PDF на приложения ОБЯЗАНЫ быть относительными к соседней `.files`.
  Подпись, точно совпадающая с исходным именем файла, заменяется новым именем с сохранением
  оформления; прочие подписи сохраняются. При потере ссылок экспорт не объявляется успешным.
  Полностью распакованный ZIP переносим; поддержка открытия файла по клику зависит
  от PDF-просмотрщика и не гарантируется HTTP-слоем.
- **FR-014**: Ответы ОБЯЗАНЫ выдаваться отдельно как UTF-8 текст с нумерацией по позиции
  работы; тройка форматируется `N. 19) …; 20) …; 21) …`. Источники выдаются отдельно
  как JSON существующего формата: `format_version`, `created_at`, оригинальные `tasks`,
  `pdf_sha256`, `attachments`, `attachment_map`. Исходные ответы остаются в преподавательском
  манифесте, не в ученической выдаче. Эти данные относятся к моменту создания работы,
  а не повторно запрашиваются при скачивании.
- **FR-015**: Скачивание принимает только `work_id` и предусмотренный вид артефакта.
  Выдаётся ровно зарегистрированный файл этой работы, без повторного экспорта,
  листинга каталога или возможности адресовать произвольный файл. Для PDF, ZIP,
  ответов и источников указываются соответственно `application/pdf`, `application/zip`,
  `text/plain; charset=utf-8`, `application/json` и безопасное имя скачивания,
  корректное для кириллицы. Все готовые материалы скачиваются через HTTP(S)-URL API,
  а не адреса локальной файловой системы. Ответы и источники не объединяются с ученическим ZIP.
  Обычный GET скачивания UI не посылает Range; прямой просмотр PDF допускает его.
  Обрыв начатой передачи не превращается в JSON; повтор GET не создаёт работу заново.
- **FR-016**: HTTP-слой ОБЯЗАН сохранять запрет перезаписи PDF, ZIP, `.answers.txt`,
  `.sources.json`, `.files`, включая существующие символические ссылки и конфликт
  только по ZIP у работы без приложений. Конкурирующие создания не смешивают материалы.
  Подтверждённый отказ не публикует частичную работу; уже готовые работы не меняются.
  Потеря связи сама по себе не является подтверждённым отказом (FR-023).
- **FR-017**: Ограничения источника ОБЯЗАНЫ сохраняться: разрешены только поддерживаемые
  HTTP(S)-ресурсы домена Полякова; перенаправления не обходятся автоматически.
  Отсутствующее условие/ответ, неполная игра, неизвестная разметка, недоступный ресурс,
  неподдерживаемое изображение или потерянная ссылка приводят к явной ошибке,
  а не к незаметно урезанному результату. Ответы копируются из источника, не вычисляются.
- **FR-018**: Прикладные ошибки API ОБЯЗАНЫ иметь JSON ErrorResponse с единым
  машиночитаемым кодом, понятным сообщением и указанием поля при ошибке поля.
  Исключения ограничены обработкой Range файлового ответа: текстовый 400 при
  некорректном Range и 416 с пустым телом/Content-Range при недостижимом диапазоне.
  Они не меняют JSON-формат остальных ошибок, включая неверный JSON POST и 404 файла.
  Обрыв после начала передачи также не заменяется ErrorResponse.
  Не возвращаются трассировки и локальные пути.
  Неизвестная положительная задача не объявляется достоверно несуществующей,
  если банк наблюдает лишь сетевой сбой, перенаправление или неожиданную страницу.
- **FR-019**: HTTP-результаты ОБЯЗАНЫ различать: успешное чтение/скачивание (200),
  готовое создание (201), повреждённый запрос (400), ошибку значений/типов (422),
  неизвестную работу или отсутствующий артефакт (404), конфликт файлов (409),
  сбой источника (502), достоверно распознанный тайм-аут источника (504),
  внутреннюю ошибку экспорта/хранилища (500). Нормальная пустая выборка — 200.
  Для файлового Range отдельно предусмотрены частичный успех 206 и транспортные
  400/416 по FR-018; точные MIME и заголовки заданы общим контрактом.
  Обязательные различимые коды: `invalid_request`, `validation_error`, `not_found`,
  `output_conflict`, `source_error`, `source_timeout`, `export_failed`.
  Точный объект ошибки зафиксирован в контракте `1.0.0`; он не выводится разбором
  нестабильного текста исключения. Неразличимая ошибка источника остаётся `source_error`.
- **FR-020**: MCP ОБЯЗАН сохранить четыре инструмента `list_categories`, `search_tasks`,
  `get_task`, `create_pdf`, их входы и существующие результаты. В частности, MCP
  `create_pdf(topic_ids, output_path)` по-прежнему принимает абсолютный путь `.pdf`
  и возвращает `pdf`, `sources`, `answers_file`, `answers`, `count`, `attachments`,
  `result_file`, `archive`. Новые ограничения HTTP на пути и выдачу ответов не меняют MCP.
- **FR-021**: Приёмка ОБЯЗАНА включать успешные, ошибочные и сквозные сценарии выше,
  проверку сохранения MCP и существующих регрессий банка и экспорта. Для каждой
  выполненной проверки фиксируются шаги/команда и фактический результат;
  изучение теста не считается его успешным запуском.
- **FR-022**: Создание ОБЯЗАНО выполняться одним длительным HTTP-запросом; успешный ответ
  201 возвращается только после готовности всех материалов и необходимых метаданных.
  UI отправляет один POST на точный `/api/v1/works` и запрещает автоматическое
  следование перенаправлениям. API обслуживает этот путь напрямую, без 307/308;
  вариант `/api/v1/works/` даёт 404 ErrorResponse без Location и запуска экспорта.
  Фоновые задания, опрос прогресса, промежуточный успех и отмена в первую версию не входят.
- **FR-023**: При потере связи до подтверждённого результата исход создания неизвестен:
  сервер мог завершить работу. На границе UI/API ОБЯЗАТЕЛЬНО следующее поведение UI:
  сохранить состав и порядок подборки, показать «Результат не подтверждён» и не повторять
  экспорт автоматически. После предупреждения, что предыдущая работа могла быть создана,
  пользователь может явно выбрать «Создать новую работу». Это отдельное создание,
  не восстановление; отсутствие дублей по содержимому не гарантируется. Механизм
  поиска/восстановления потерянного результата в первую версию не входит.
- **FR-024**: Готовые материалы и необходимые для доступа к ним метаданные ОБЯЗАНЫ
  сохраняться между перезапусками сервера до ручной очистки, без автоматического удаления.
  При известном `work_id` доступны те же метаданные и файлы без нового экспорта.
  После удаления запрошенного материала API возвращает 404 `not_found` с понятным
  сообщением об отсутствии результата; это не отменяет доступ к другим сохранённым файлам.
  Экран истории и восстановление подборки после перезагрузки страницы вне первой версии.

### Key Entities *(include if feature involves data)*

- **Категория**: ID и название подтипа, принадлежность номеру ЕГЭ; 19–21 используют общий набор.
- **Задача**: постоянный ID генератора (не номер пункта и не номер КИМ), номера ЕГЭ,
  оригинальное условие, рисунки, приложения, происхождение и отдельные ответы источника.
- **Страница поиска**: фильтры, общее число совпадений, смещение, задачи и следующее смещение.
- **Работа**: независимый `work_id`, имя, время создания, упорядоченные ID, число пунктов
  и набор завершённых материалов в отдельном каталоге; имя задано явно либо автоматически.
  Материалы и необходимые метаданные неизменны после успеха и доступны после перезапуска
  до ручной очистки. Одинаковое имя не означает одну и ту же работу.
- **Артефакт работы**: PDF, необязательный ZIP, ответы или источники с типом содержимого
  и ссылкой скачивания; локальное размещение не является частью публичной идентичности.
- **Карта приложений**: позиция пункта, ID задачи, исходный URL и имя, новое имя
  и относительный путь; связывает исходные данные с ученическим набором.
- **Ошибка операции**: код причины, сообщение и необязательная ссылка на ошибочное поле;
  ошибка не является готовой работой.
- **Неподтверждённый результат**: клиентское состояние после потери связи, а не статус
  отказа API или доказательство отсутствия работы; `work_id` может быть неизвестен клиенту.

- **SC-005**: Каждый перечисленный класс ошибочных входов и подтверждённых отказов

- **SC-007**: Существующие сценарии MCP поиска и экспорта продолжают давать совместимые

- **SC-008**: В сценарии разрыва связи до ответа сохраняются 100% выбранных ID и их порядок,
  число автоматических повторов создания равно нулю; пользователь видит неизвестный
  результат и предупреждение перед явным новым созданием, без обещания отсутствия дублей.

  материалов доступны по известным ссылкам с прежними байтами; после ручного удаления
  запрошенного материала сообщается его отсутствие без повторного создания.
- **SC-010**: Во всех контрольных карточках с рисунками, таблицами и приложениями

  исполняемый код источника и ответы отсутствуют; все адреса ресурсов используют HTTP(S),

- **SC-011**: Один допустимый POST на точный путь вызывает один экспорт и не имеет

  число повторных экспортов при всех файловых сценариях равно нулю.

## Assumptions

### Границы и рабочие допущения

- Пользователь — преподаватель на локальном компьютере. Многопользовательская работа,
  учётные записи, публичный доступ, редактирование исходных задач, автоматический подбор
  сложности и управление макетом не входят в эту фичу.
- Разделение ученических и преподавательских материалов — разделение выдачи и файлов,
  а не система ролей или защита секретов от другого пользователя того же компьютера.
- Первая версия создаёт работу в рамках одного запроса и отвечает успехом только
  после готовности всех материалов. Отсутствие фоновых заданий, опроса прогресса
  и отмены принято решением пользователя, а не оставлено открытым допущением.
- Хранение работ и необходимых метаданных между перезапусками до ручной очистки,
  без автоудаления, принято решением пользователя (FR-024). История работ и восстановление
  подборки после перезагрузки страницы не входят в первую версию; при этом доступ
  к готовой работе по уже известному идентификатору сохраняется.
- Имя необязательно, повтор имени допустим; отдельное создание получает новые `work_id`
  и каталог. При потере подтверждения нет автоматического повтора и восстановления;
  явное новое создание может дать дубль по содержимому (FR-007–008, FR-023).
- Поиск без ответов, отдельные ответы/источники созданной работы и браузерное
  представление ресурсов приняты решением пользователя (FR-006, FR-014–015).
- Источник нужен для получения и экспорта задач, но не для повторного скачивания готовой
  работы. Существующий кеш банка допускает данные давностью до 900 секунд; между
  страницами нет гарантии единого снимка. Экспорт сохраняет фактически загруженные данные.
- Визуальный просмотр нового PDF остаётся частью проверки пригодности работы;
  ни один тест не доказывает корректность всего внешнего банка или всех PDF-просмотрщиков.
- Поля, форматы и распределение ответственности подтверждены пользователем вместе
  с уточнениями A-07–08. Команда UI подтвердила все 6/6 условий в contract-review;
  решения пользователя зафиксированы в `../evidence/agreements.md` относительно корня API.
  Единственный нормативный файл форматов — общий `../contracts/api-v1.yaml` версии
  `1.0.0`, статус `agreed`. Дальнейшие изменения согласуются до реализации.

Все три исходных вопроса API закрыты: один запрос создания; хранение до ручной очистки
с сохранением после перезапуска; ответы только отдельно для созданной работы.
Также определены неизвестный исход при разрыве связи, необязательное имя и требования
к браузерному представлению. Критических неоднозначностей поведения первой версии нет.

Актуальные спецификация, план и contract-review UI прочитаны. Команда UI подтвердила
6/6 условий, включая A-07–08, и готовность принять контракт как `1.0.0`.
Пользователь принял согласованное поведение. Общий контракт зафиксирован как `1.0.0`
со статусом `agreed`; открытых вопросов и содержательных расхождений нет.

# Unit-проверки

Статус: **тест-план, не выполненные тесты приложения**. В репозитории дан diff, а не запускаемый сервис Practice 1. После реализации проверки запускаются без сети и реальной LLM. Общий контракт — [R1–R7](context.md#context-pack).

| ID / правило | Изолированный объект и вход | Ожидаемый результат |
|---|---|---|
| U1 / R1 | Валидатор: `{}`, `{"diff":123}`, `{"diff":null}`, `{"diff":true}`, `{"diff":[]}`, `{"diff":""}`, `{"diff":" \n"}`, `[]` | Для каждого входа ошибка валидации invalid_diff; никаких преобразований числа в строку |
| U2 / R2 | Валидатор: строки `"x" * 1`, `"x" * 10000`, `"x" * 10001`; отдельно `"я" * 10000`, `"😀" * 10000`; дополнительные поля в JSON | 1 и 10000 принимаются без изменения строки; 10001 → diff_too_large; Unicode считается в code points, а не UTF-8 байтах; дополнительные поля игнорируются |
| U3 / R3, R7 | Сервис с spy LLM; diff `"diff --git a/a.py b/a.py"`, ответ `"Проверено"` | Один вызов; diff передан без изменений внутри явно обозначенного блока данных; промпт содержит R7 и запрет исполнять инструкции из diff; результат ровно `{"comment":"Проверено"}` |
| U4 / R4 | Адаптер со stub транспорта: сетевой сбой, истечение общего дедлайна; время управляется тестовыми часами | Соответственно типизированные ошибки failure/timeout; deadline=5 секунд передан транспорту, повторов нет, отмена запрошена. Фактическая отмена проверяется интеграционно в I6 |
| U5 / R4 | Ответ адаптера: `null`, `123`, `""`, `"   "`, затем `"ok"` | Первые четыре → invalid_llm_response, последний → успех; ошибки не маскируются строковым приведением |

Unit-тест валидатора не вызывает напрямую старый `create_review` в обход HTTP и не ожидает от Python-аннотации runtime-проверку. Отображение внутренних ошибок в статусы и JSON проверяется интеграционно.

Подтверждение после реализации: отчёт с ID и входом каждого параметризованного случая, ожидаемым/фактическим результатом, версией кода. До этого все строки имеют статус «запланировано».

## Как использовали AI

- Сессия: [P1-03](prompts.md#журнал), OpenCode / anthropic/claude-sonnet-5.
- Тип: master prompt.
- Задача: подготовка unit-сценариев.
- Оценка результата: В ответе выделены формирование промпта, возврат comment и сбой LLM. Это описание проверок, а не выполненные тесты.
